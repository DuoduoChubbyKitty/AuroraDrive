#### 2.1.3 三档降级状态机（DegradeCascade）—— 玩家信任的核心

**eyebrow**：`DEGRADE STATE MACHINE`

**标题**：模型不靠谱的时候，它自己往后退一档

**导语**：这是整套系统里最重要的一个设计。能力只有三档，退档是单向的，阈值带滞回，所以不会在临界点上反复横跳。

**三档卡片**

| 档 | 名称 | 正文 | 出处 |
| --- | --- | --- | --- |
| 01 | 端到端主驾 | M9 单目端到端模型直接输出转向、油门与刹车。这是最聪明的一档，也是唯一不需要几何规则的一档。 | `DegradeStateMachine.swift:5-9` |
| 02 | YOLO 接管 | YOLOPX 感知模型接手：一个模型同时输出目标检测、可行驶区域与车道线三个头，再由规则把车道线转成控制量。能力下降，但系统健康。 | `YolopxEngine.swift` |
| 03 | 纯规则兜底 | 不再依赖任何神经推理，只用几何与阈值。最笨，但最保守。 | `DegradeStateMachine.swift:5-9` |

**档位下方的机制注解**（每档一张小卡）：

- **降级是单调的**：能力只会往下走，不因为一次抖动就跳回上一档。
- **阈值带滞回**：降级健康度阈值 `0.65`，恢复滞回 `0.15`。两个参数共同抑制阈值附近的反复横跳。
- **阈值可以实时调**：降级阈值在界面上直接暴露给你，随时改、立刻生效。

**口播注解块**（`--bg-inset` 底 + `--accent` 左边条）：

> 说人话：模型不靠谱时，系统会自己退到更笨但更稳的规则档，而不是直接失控。

> **本页最想让人点的一句**：口播块这句 —— 玩家看完这一句才敢往下点。

#### 2.1.5 架构红线（ArchitectureRedline）

**eyebrow**：`ARCHITECTURE RED LINE`

**标题**：让画面更顺，不等于让决策变慢

**导语**：MetalFX 空间超分与时域插帧只做人眼观看的叠加层，绝不进入「捕获 → 推理 → 按键注入」的决策链路。为了画面更顺滑而给决策加延迟，等于让车反应变慢——所以我们没这么干。

**三条架构事实**（横向条目，左 40% 数字 / 右 60% 文字）：

| 数字 | 事实 | 机制 |
| --- | --- | --- |
| `2` 个进程 | UI 与引擎是两个长驻进程，经 `/aurora_frame_v1` 共享内存传帧与检测数据 | UI 卡了不影响引擎干活，反之亦然 |
| `v3` | 共享内存协议版本会做校验，不匹配直接明确报错，而不是静默错位 | `EngineClient.swift:65`、`:281-298` |
| `15Hz / 15fps` | 决策频率固定，应急冲刺时两者一起提到 20 | `EngineMain.swift:771` |

#### 2.2.2 四段管线（Pipeline）

**标题**：一条主干链路，四个可插拔环节

**导语**：任何一环出问题，系统会沿着降级状态机退档，而不是带着错误继续开。

| 段 | 名称 | 说明 | 关键数字 |
| --- | --- | --- | --- |
| 01 | 捕获 Capture | ScreenCaptureKit 取 CVPixelBuffer 流，不录屏再转码 | `15fps` |
| 02 | 推理 Inference | CoreML 跑在 Apple Neural Engine 上；YOLO 走 GPU 直通 | `15Hz`；YOLOPX 单次约 `60ms`（148 GFLOPs，ANE 峰值 9.26 TFLOPS，效率约 26%） |
| 03 | 决策 Decision | 三档状态机仲裁，输出转向 / 油门 / 刹车 | 降级健康度 `0.65`，恢复滞回 `0.15` |
| 04 | 注入 Inject | CGEvent 合成真实键鼠事件；AXIsProcessTrusted 做辅助功能鉴权 | 键位 / 文本 / 鼠标 |

**视觉**：直角折线箭头串联四个节点，不用插画。

#### 2.2.3 三档降级详解（DegradeDetail）

**标题**：退档是单向的，阈值带滞回

**导语**：降级逻辑集中在一个状态机里，两个常量决定它稳不稳。

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `degradeHealth` | `0.65` | 健康度低于此值触发降档 |
| `recoverHysteresis` | `0.15` | 恢复需要额外跨过的滞回量，防止在阈值附近反复横跳 |

**三档行为说明**（每档写清"什么时候进 / 进去之后做什么"）：

- **端到端主驾**：默认档。M9 单目端到端模型直接给控制量。
- **YOLO 接管**：主驾健康度掉到阈值以下时进入。YOLOPX 在 `ayolom` 档每 tick 都跑，在 `legacy` 档偶数帧跑 —— 感知频率跟着档位走，不浪费算力。
- **纯规则兜底**：感知也不可靠时进入。纯几何与阈值，最笨也最稳。

**注解**：

> 降级阈值在界面上直接暴露给你，改完立刻生效。你可以拿它做实验：故意把阈值调高，看它多快退档。

#### 2.2.4 YOLOPX：一个模型三个头

**标题**：一个模型，三个任务

**导语**：不要被"三个输出"骗成"三个模型"。YOLOPX 是单模型多任务，一次前向同时给出三路结果。

| 输出头 | 含义 | 谁在用 |
| --- | --- | --- |
| `det` | 目标检测 | 识别前方车辆与障碍物 |
| `da` | 可行驶区域 | 哪些像素是可以压上去的路面 |
| `ll` | 车道线 | 车道几何，作为规则档的输入 |

**频率随档位**：

| 档位 | YOLOPX 运行频率 |
| --- | --- |
| `ayolom` | 每 tick 都跑 |
| `legacy` | 偶数帧跑 |

**来源**：`Sources/AuroraDrive/Inference/YolopxEngine.swift`

#### 2.2.5 光流选型实测对照（OpticalFlowBench）

**eyebrow**：`BENCHMARK · 640 × 640`

**标题**：官方硬件光流，在我们的机器上反而更慢

**导语**：这是"实测选型"的完整对照，不是跑分炫耀。同一台机器、640×640、ABBA 交错同批测得。

| 实现 | 单帧耗时 | 说明 |
| --- | --- | --- |
| OpenCV DIS ULTRAFAST（全核） | `1.91ms` | 主力路径 |
| OpenCV DIS ULTRAFAST（单核退化） | `3.78ms` | 极端工况，仍在 5ms 用户红线内 |
| Apple VTOpticalFlow（VideoToolbox 硬件） | `10.28ms` | 硬件加速，却慢 5 倍以上 |
| Vision `VNGenerateOpticalFlow` | `27.43ms` | 慢 14 倍 |

**结论注解**：

> 所以项目自己接了 OpenCV DIS（ULTRAFAST 预设），通过 `Vendor/OpenCVFlow` 的 C++ 桥接入 Swift。选择依据是这张表，不是"哪个名字更响"。

**用法注解**：

> 光流负责把 10Hz 的检测结果补成 20Hz 级的动作连续性 —— 让两次检测之间的按键不跳变。

#### 2.2.6 坐标定位与四级新鲜度（CoordinateDetail）

**标题**：位置不是猜出来的，是从网络包里解出来的

**导语**：libpcap 抓取 UE5 移动同步包，过滤器 `tcp port 30031 or udp`，解码位流得到世界坐标与朝向，映射到 `13,056 × 13,056` 的大地图像素空间。

**四级新鲜度表**：

| 档 | 条件 | 行为 |
| --- | --- | --- |
| live | ≤ 18s | 参与决策 |
| recent | ≤ 40s | **起不再参与决策**（更保守） |
| stale | ≤ 90s | 只如实标注，不闪断 |
| lost | > 90s | 明确标记位置失效 |

**注解**：

> 位置数据会过期。系统在数据变陈旧时**如实标注**，而不是继续拿旧坐标假装一切正常 —— 这是"不闪断"的含义。

#### 2.2.7 速度 OCR 三层校验（SpeedOcrDetail）

**标题**：读错一个数字，比读不出数字更危险

**导语**：所以识别结果必须过三道关，任何一道不过就不采信。

| 层 | 校验 | 拦下什么 |
| --- | --- | --- |
| Layer 1 | 量程 | 超出物理可能的速度读数 |
| Layer 2 | 跳变 | 帧间速度突变 |
| Layer 3 | 多帧确认 | 单帧偶发误读 |

**双路径**：

| 路径 | 模型 | 特点 |
| --- | --- | --- |
| 主路径 | PP-OCRv6 微调整行模型（`models/ppocrv6_tiny_ft_int8.mlpackage`） | int8 量化，GPU 推理 |
| 备用路径 | 逐位 CNN（`speed_digit_cnn_v4*`） | 主路径失效时接管 |

#### 2.2.8 显示层与决策层隔离（DisplayBoundary）

**eyebrow**：`THE RED LINE`

**标题**：MetalFX 只进人眼，不进决策

### 2.5 常见问题 `/faq`

**eyebrow**：`FAQ`

**H1**：你问的，我们逐条回答

**lead**：14 条。封号、硬件、模型来源、检测、性能、安全边界 —— 能给的都给清楚，不能保证的也直说。

---

**分组 A · 上手与风险**

**Q1. 我会被封号吗？**
**A**：有风险，而且我们不能替你判断。使用自动化控制游戏可能违反游戏服务条款，作者不对封号或其他任何后果负责，请自行评估风险。这个项目仅供研究与个人学习使用。

**Q2. 需要什么硬件？**
**A**：macOS 26+、Apple Silicon、Xcode Command Line Tools。libpcap 系统自带，不需要额外的采集卡、显卡或外设。

**Q3. 还需要手动做点什么？**
**A**：两项权限：屏幕录制与辅助功能，都在「系统设置 → 隐私与安全」。抓包权限会在首次启动时输入一次管理员密码自动装好开机服务，之后自动恢复。

**Q4. 它会不会乱按我的键盘，把我正在打的东西打出去？**
**A**：按键注入走的是 CGEvent 系统级事件，和你真实敲键盘同一条路径，因此全局生效 —— 所以请不要在它接管时同时操作其他应用。这一点我们不粉饰。

**Q5. 我在游戏外打开它会怎样？**
**A**：AI 助手有四道护栏，其中一道就是"游戏不可见拒绝"。观测模式（`AURORA_OBSERVE_ONLY`）下拒绝一切注入；dryRun 不注入任何按键，但返回结构完整的结果。所有护栏遇错都是明确报错，不静默。

---

**分组 B · 技术与模型**

**Q6. 和普通按键脚本、按键宏有什么区别？**
**A**：脚本走预先写死的路径，场景一变就失效。这里是实时截屏 → 端到端神经网络推理 → 按键注入，并且系统知道自己处于哪一档、什么时候该退。差别不在"能按多少键"，在"能不能应对没见过的画面"。

**Q7. 模型从哪来？要自己训练吗？**
**A**：感知与 OCR 所需的权重集中在 `models/` 目录，包括 PP-OCRv6 微调整行模型（`models/ppocrv6_tiny_ft_int8.mlpackage`，int8 量化）、逐位 CNN（`speed_digit_cnn_v4*`）、路网先验（`models/route_graph.json`）与任务索引（`models/quest_index.json`）。端到端主驾与 YOLOPX 权重属于项目资产，仓库与发行版中以实际提供为准。**权重缺失时系统走降级档而不是崩溃** —— 这正是三档状态机的意义。

**Q8. 性能占用多大？会不会把电脑拖垮？**
**A**：决策频率是固定的：推理 15Hz、抓屏 15fps，不随负载浮动；应急冲刺时两者一起提到 20。实测光流 1.91ms/帧（单核退化 3.78ms）是这个节奏能跑起来的关键。UI 与引擎是两个独立进程，界面卡顿不影响引擎干活。

**Q9. AI 助手到底能做多少事？**
**A**：工具注册表挂载 30 个工具（18 技能 + 4 键位 + 1 文本 + 3 鼠标 + 2 观察 + 2 搜索）。其中 18 个技能里 **15 个已实装**，`pinkpaw` / `rhythm` / `preset_realtime` 三个尚未移植，调用会返回失败而不是假装成功。会话滑动窗口上限 200 条（约 100 轮）。

**Q10. AI 助手怎么操作游戏界面？**
**A**：唯一可靠路径是 ESC → 截图 → 鼠标点击。先退出到可交互界面，再截图理解，最后用鼠标点击。这是可靠性设计 —— 比"直接往坐标上盲点"可靠得多。

**Q11. 能用 Windows 或 Linux 吗？**
**A**：不能。这是 macOS 专属系统：ScreenCaptureKit、CGEvent、AXIsProcessTrusted、MetalFX 全部是 Apple 平台技术。

**Q12. 支持别的游戏吗？**
**A**：当前是针对《异环》(NTE) 视角驾驶场景做的。抓屏、注入、网络定位这些环节是通用的，但模型、地图与任务索引都是针对 NTE 训练的。

## 3. 交互流程

> 视觉与动效参数（时长、曲线、位移）全部继承 `DESIGN_SYSTEM.md`，本文只定义**行为与状态**。

### 3.1 导航栏行为

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| 顶部透明 | 页面 `scrollY < 8` | 背景透明、无底部边框 |
| 滚动吸顶 | `scrollY ≥ 8` | 背景 `color-mix(in srgb, var(--bg-base) 78%, transparent)` + `backdrop-filter: blur(20px) saturate(160%)` + 底部 1px `--stroke-subtle` |
| 当前页高亮 | 路由匹配 | 文字 `--text-primary` + 下方 2px `--accent` 指示条（`scaleX` 0→1，200ms） |
| 键盘聚焦 | Tab | 焦点环 2px `--stroke-focus`，`outline-offset: 2px`（不得移除原生 outline） |
| 移动抽屉 | 点击汉堡 | 从右滑入 280ms `cubic-bezier(0.16,1,0.3,1)`，宽度 `min(88vw, 360px)`，遮罩 `rgba(7,10,15,0.6)` 240ms 淡入 |
| 抽屉打开时 | — | `body` 锁滚动；焦点移入抽屉；`Esc` 关闭；关闭后焦点**返回汉堡按钮** |
| 抽屉内导航项 | — | 触控高度 44px，`min(88vw,360px)` 内 20px 内边距 |

**滚动切换必须用 IntersectionObserver 打在页面顶部 1px 哨兵元素上**（`threshold: 0`），不要绑 `scroll` 事件。

### 3.2 Hero 双 CTA 路径

| CTA | 文案 | 目标 | 用户预期 |
| --- | --- | --- | --- |
| 主 | 克隆并运行 | GitHub 仓库根 | "点了就能跑起来" |
| 次 | 先看它怎么跑 | `/architecture` | "先搞懂再决定要不要用" |

- 桌面并排（gap 12px），移动端垂直堆叠、宽度 100%、gap 12px。
- 主按钮 hover：`bg → --accent-hover` + `translateY(-1px)` + `--glow-accent`。
- 次按钮 hover：`bg → --bg-elevated` + `border-color → --accent-line`。
- 键盘 Tab 顺序：主 → 次 → 主题切换 → 导航项（DOM 顺序即视觉顺序）。
- 点击主 CTA **不做站内跳转动画**（外链直出）。

### 3.3 FAQ 手风琴

**展开逻辑**

| 项 | 规定 |
| --- | --- |
| 展开模式 | **一次只展开一项**（`single`），切换时前项收起与后项展开重叠 60ms |
| 动画 | `grid-template-rows: 0fr → 1fr` + `overflow: hidden`，260ms `cubic-bezier(0.4,0,0.2,1)`，**不用固定 max-height** |
| 箭头 | 旋转 180°，260ms `cubic-bezier(0.4,0,1,1)` |
| Reduced motion | 即时展开（0ms），无高度动画 |
| 首屏 | 默认全部收起，**不预展开任何一项**（避免一进页面就是大片文本） |

**键盘与读屏**

- 触发器是 `<button>`，带 `aria-expanded={布尔}` 与 `aria-controls={答案区 id}`。
- 答案容器 `<div role="region" aria-labelledby={触发器 id}>`，通过 `hidden` 或 `inert` 移出无障碍树（收起时）。
- 焦点顺序：Tab 依次遍历所有 15 个触发器；`Enter` / `Space` 切换当前项。
- **单展开模式下，`↓` / `↑` 在触发器之间移动焦点**，`Home` / `End` 跳到首尾（`role="tablist"` 风格的可选增强；若不实现箭头键，至少保证 `Tab` 可达 + `Enter` 可切）。
- 分组标题（"上手与风险"等）用 `<h3>`，每组用 `<section aria-labelledby>`。

### 3.4 代码块复制交互

| 状态 | 视觉 | 时序 |
| --- | --- | --- |
| 默认 | 图标 + "复制"，`--text-tertiary` | — |
| hover | `--text-primary` + `bg --bg-elevated` | 120ms |
| 成功 | "✓ 已复制"，`--success` | 保持 **1600ms**，再 200ms 淡回默认 |
| 失败 | "复制失败"，`--danger` | 保持 **2000ms**，再恢复默认 |

**降级链（必须实现，三级）**

1. `navigator.clipboard.writeText(code)` —— 首选。
2. 失败 → `document.execCommand('copy')` + 选中文本 —— 非安全上下文 / 旧浏览器。
3. 两者都失败 → 显示"复制失败"，并**自动全选代码文本**提示用户手动 `Cmd+C`。

**无障碍**

- 按钮 `aria-label` 随状态变化：`复制代码到剪贴板` → `已复制到剪贴板`。
- 独立隐藏节点 `aria-live="polite" role="status"` 宣告：`代码已复制到剪贴板` / `复制失败，请手动选择后按 Command+C`。
- 代码区 `<pre><code>` 保持**不换行**（`white-space: pre`），横向滚动 —— 代码换行会破坏可复制性。
- 键盘可达：按钮在 Tab 序列内，触控目标 ≥ 44×44（视觉尺寸可小，但点击区用 padding 补足）。

> **⚠️ 校对提示**：`src/components/CodeBlock.tsx` 当前实现只有第 1 级与 `catch → setCopied(false)`（静默失败），缺第 2、3 级与失败态文案。见 §7。

### 3.5 页面过渡、滚动位置与返回顶部

**页面过渡**（继承 DESIGN_SYSTEM §6.6，行为层面补充）

| 项 | 规定 |
| --- | --- |
| 模式 | `AnimatePresence mode="wait"`，`initial={false}` |
| 出场 | 200ms，`--ease-in`，`opacity 1→0` + `y 0→-8` |
| 进场 | 360ms，`--ease-out`，`opacity 0→1` + `y 12→0` |
| 移动端 | 进场压到 280ms，位移 8px |
| Reduced motion | 单次 opacity 160ms，无位移 |
| 首屏 | **不做入场动画**（`initial={false}`） |
| 背景 | 页面根恒为 `var(--bg-base)`，不随路由变 |

**滚动位置**

| 场景 | 行为 |
| --- | --- |
| 路由跳转（PUSH） | `useLayoutEffect` 中 `window.scrollTo({top:0,left:0,behavior:'instant'})` —— **必须 instant，不能 smooth** |
| 浏览器原生恢复 | `history.scrollRestoration = 'manual'`，由 `PageTransition` 接管 |
| 前进 / 后退（POP） | 在 `location.key` 上挂 `Map<key, scrollY>` 缓存；进场动画结束后用 `behavior:'instant'` 恢复 |
| hash 锚点 | 等进场动画结束（delay 380ms）后 `scrollIntoView({behavior:'smooth', block:'start'})`，目标加 `scroll-margin-top: 96px` |
| Reduced motion | 锚点用 `behavior:'instant'` |

**返回顶部按钮**

| 项 | 规定 |
| --- | --- |
| 出现条件 | `scrollY > 800` 才出现 |
| 位置 | 右下角，距边 24px（移动端 16px），44×44 |
| 样式 | `--bg-elevated` 底 + 1px `--stroke-default` 描边 + `--radius-sm` |
| 行为 | 点击 `window.scrollTo({top:0, behavior: reduced ? 'instant' : 'smooth'})` |
| 焦点 | 出现时**不自动获得焦点**（避免打断阅读），但必须可通过 Tab 到达 |
| 过渡 | 淡入 200ms；hidden 时用 `visibility:hidden` + `pointer-events:none` 移出可点击区（不能只 `opacity:0`） |

### 3.6 表单六态（前端模拟）

> **前提**：官网无后端。所有"提交"均为前端模拟，页面上必须写明这一点（见 §2.7.5 声明）。

| 态 | 触发 | 表现 | 时长 |
| --- | --- | --- | --- |
| 1. Default | 初始 | `--bg-inset` 底 + 1px `--stroke-input` 边框，placeholder `--text-tertiary` | — |
| 2. Invalid | 失焦校验不通过 / 提交校验失败 | 边框 → `--danger`，下方错误文字 `--text-xs --danger` + 左侧 2px `--danger` 竖条；`aria-invalid="true"` + `aria-describedby` 指向错误节点 | 140ms |
| 3. Valid | 失焦校验通过 | 边框保持 `--stroke-input`，右侧 16px `--success` 对勾 SVG（`aria-hidden`） | 140ms |
| 4. Submitting | 点击发送 | 按钮内联 spinner（1.5px 描边圆环，1s/圈线性旋转）+ 文案改「发送中…」+ 按钮 disabled；字段全部 disabled | — |
| 5. Success | 模拟提交完成（1200ms 后） | 整块表单替换为成功面板：16px `--success` 图标 + 标题「已收到」+ 说明「这是一个前端演示，消息没有真的发送出去。请到 GitHub Issues 提交」；面板淡入 240ms，用 `min-height` 预留避免高度跳变 | 240ms |
| 6. Failed | 模拟失败（提供开发调试开关触发，如 `?fail=1`） | 面板变 `--danger` 态 + 文案「模拟提交失败，请直接到 GitHub Issues 反馈」+ 重试按钮 | 240ms |

**校验时机**

- **失焦时校验**（`onBlur`）；**输入时清除错误**（`onChange` 只清 error，不重新校验，避免边打字边报红）。
- 提交时校验全部字段，不通过则**聚焦第一个错误字段**并 `scrollIntoView({behavior:'smooth', block:'center'})`。
- 提交按钮宽度固定（避免文案变化导致按钮跳动）。
- 必填项 label 后加 `--accent` 的 `*`，同时 `aria-required="true"`，并在 label 文字里写"（必填）"而不仅靠视觉星号。

### 3.7 深色模式切换

| 项 | 规定 |
| --- | --- |
| 存储键 | `aurora-theme`，值 `'light' \| 'dark'` |
| 默认 | 首次访问读 `prefers-color-scheme`，随后写入 localStorage |
| 生效方式 | `document.documentElement.dataset.theme` + `classList.toggle('dark')` **双写** |
| 防闪白 | `index.html` `<head>` 最前内联脚本同步执行（已实现）+ `<style>` 兜底底色（已实现） |
| 切换动画 | View Transitions API 圆形扩散：从按钮中心算 `r = max(dx_left, dx_right, dy_top, dy_bottom)`，`clip-path: circle(0 → r)`，420ms `--ease-out` |
| 降级 | 不支持 View Transitions → 全局颜色交叉淡化 240ms（给 `body` 临时开 `transition: background-color 240ms, color 240ms`） |
| Reduced motion | **不做扩散，不加淡入淡出，直接瞬时切换** |
| 切换期间 | 锁定页面滚动（`body { overflow: hidden }`），防止误滚 |
| 键盘 | 按钮是真实 `<button>`，`aria-label="切换到亮色模式"` 随当前主题动态更新；`Enter` / `Space` 均可切换 |
| 图标 | 太阳/月亮 1.5px 线性 SVG，`aria-hidden="true"` |

> **⚠️ 校对提示**：`src/hooks/useTheme.ts` 的降级路径是**瞬时切换**，未实现 DESIGN_SYSTEM §7.2 要求的 240ms 交叉淡化；且未锁定切换期间的 body 滚动。见 §7。

### 3.8 定价切换

- 三档方案卡**不做轮播 / 滑块 / 手风琴折叠** —— 三档同时可见是这张表的核心信息价值。
- 「推荐」标签用 `--accent` 1px 描边 + 顶部 2px 极光渐变细线（**不用 2px 描边、不用发光大阴影**）。
- 对比表在移动端横向滚动，**首列 sticky**（`position: sticky; left: 0; background: var(--bg-card); z-index: 1`），保证行标签始终可见。
- 对比表每一行的勾/叉/破折号必须有**文字兜底**（`<span class="sr-only">支持 / 不支持 / 不适用</span>`），不能只有颜色或图形符号。
- 「成为支持者」CTA 是页内锚点滚动（`scroll-margin-top: 96px`），不是外链。

### 3.9 导航当前页高亮与滚动位置记忆

- 当前页高亮用 `useLocation().pathname` **精确匹配**（`/` 只在恰好是 `/` 时高亮，`/features` 与 `/features/xxx` 视为不同）。
- 移动抽屉打开某项后**自动关闭抽屉**并滚动到顶。
- 点击 Logo 回首页时**也要归零滚动**（`behavior:'instant'`，与其他路由一致）。
- 站内跳转一律走 `<Link>`（react-router），**不要用 `<a href>` 触发整页刷新** —— 整页刷新会丢主题闪烁控制、丢路由过渡、丢滚动缓存。

## 5. 无障碍规范

### 5.1 语义标签

| 元素 | 标签 |
| --- | --- |
| 页面唯一主标题 | `<h1>` —— **每页恰好一个** |
| 区块标题 | `<h2>` |
| 卡片标题 / FAQ 问题 / 分组标题 | `<h3>` |
| 页面外壳 | `<header>` / `<nav>` / `<main>` / `<footer>` |
| 导航 | `<nav aria-label="主导航">`；移动抽屉 `<nav aria-label="移动导航">` |
| Hero 视觉构件 | `<figure>` + `<figcaption>`（或 `aria-hidden` 若纯装饰） |
| 统计条 | `<dl>` / `<dt>`（标签） / `<dd>`（数值 + 释义） |
| 功能卡网格 | `<ul>` / `<li>` |
| 表格 | `<table>` + `<caption>` + `<th scope="col">` / `<th scope="row">` |
| 代码 | `<pre><code>` |
| 免责声明块 | `<aside>` |

### 5.2 标题层级不跳级

- 全站标题层级只走 `h1 → h2 → h3 → h4`，**不得跳级**。
- 页面结构统一为：`h1`（页面主标题）→ 各区块 `h2` → 区块内卡片 `h3`。
- `SectionHeading` 组件渲染的 `h2` **必须带 `id`**，并由父 `<section aria-labelledby="...">` 引用 —— 现有 `Section` 组件已预留 `aria-labelledby` 属性，实现时必须传值。
- 移动抽屉里的导航项**不使用 heading 标签**（导航不是内容结构）。

### 5.3 焦点可见性

- 全局 `:focus-visible { outline: 2px solid var(--stroke-focus); outline-offset: 2px }` —— 已实现，**不得移除原生 outline**。
- 焦点环颜色随主题切换：深色 `#35E0A1`、亮色 `#0A7A55`（`--stroke-focus`），两种模式下对相邻底色均 ≥ 3:1。
- 深色下焦点环与卡片描边不要混在一起：`outline-offset: 2px` 已形成间隙。
- **`:focus:not(:focus-visible) { outline: none }` 只对鼠标点击生效，键盘 Tab 必须始终可见。**
- 焦点环不得被 `overflow: hidden` 裁切 —— 代码块横向滚动区、对比表 sticky 首列里的可聚焦元素需额外检查。

### 5.4 键盘可操作

| 场景 | 要求 |
| --- | --- |
| 全站 | 仅用键盘 `Tab` / `Shift+Tab` 可完成所有操作；无键盘陷阱 |
| 导航 | Tab 到导航项 → `Enter` 跳转；抽屉内 `Esc` 关闭并**焦点返回触发按钮** |
| Hero CTA | Tab 顺序 = 主 → 次 |
| 主题切换 | 真实 `<button>`，`Enter` / `Space` 均可触发 |
| FAQ | 触发器是 `<button>`，`Enter` / `Space` 切换；至少保证 `Tab` 可达 + 可操作 |
| 代码复制 | 按钮可聚焦，`aria-label` 随状态变化 |
| 表单 | 每个字段有 `<label for>`；提交失败后焦点移到第一个错误字段 |
| 抽屉 | 打开时焦点移入抽屉第一个可聚焦元素；`Tab` 在抽屉内循环（`focus trap`） |
| 跳过导航 | 页首提供「跳到主内容」链接（`.sr-only` → 聚焦时可见），`href="#main"` |
| 滚动锚点 | 所有锚点目标加 `scroll-margin-top: 96px`，避免被吸顶导航遮住 |

### 5.5 屏幕阅读器

| 项 | 规定 |
| --- | --- |
| `lang` | `<html lang="zh-CN">` —— 已实现 |
| 页面标题 | 每页唯一 `<title>`，格式：`区块名 · AuroraDrive`（首页为 `AuroraDrive · macOS 视角自动驾驶系统`） |
| 图片 alt | 每张 AI 图必须有 `alt`，描述**传达的概念**而非"装饰图片"；纯装饰图用 `alt=""` + `aria-hidden="true"` |
| 状态灯 | `StatusDot` 已是 `aria-hidden="true"` —— 旁边的文字必须自带状态文字（不能只靠颜色） |
| 档位 | 降级三档必须**文字 + 颜色**双编码（色弱用户靠文字分辨） |
| `aria-expanded` | FAQ 触发器、手风琴、抽屉均需 |
| `aria-controls` | FAQ 触发器 → 答案区 id；抽屉按钮 → 抽屉 id |
| `aria-live` | 复制成功/失败、表单提交结果、返回顶部提示 —— 一律 `aria-live="polite"` + `role="status"` |
| `role="region"` | FAQ 答案区用 `role="region" aria-labelledby={触发器id}` |
| 装饰性图标 | 全部 `aria-hidden="true"` + `focusable="false"` |
| 渐变文字 | `background-clip: text` 的 H1 关键句必须保留可读文本（`-webkit-text-fill-color: transparent` 不影响读屏文本，但**不得**用 `::after` 伪元素承载文字） |
| 表格 | `<caption>` 必填；行标题 `<th scope="row">`；对比表符号要有 `sr-only` 文字兜底 |
| 数字滚动 | 屏幕阅读器读到的是**终值**（DOM 文本即为终值，动画只改视觉层）；`aria-live="off"` |

### 5.6 动效降级

- 统一以 `prefers-reduced-motion: reduce` 判定，同时用 framer-motion 的 `useReducedMotion()` 覆盖 JS 驱动的 transform/opacity。
- 降级映射表以 DESIGN_SYSTEM §6.7 为准。**必须实现**的六项：滚动渐入（仅 opacity 200ms）、hover 位移（取消位移，保留颜色/阴影）、数字滚动（直接终值）、页面过渡（单次 opacity 160ms，无位移）、状态灯脉冲（常亮）、手风琴（即时展开）。
- 无限循环动效**全站仅允许状态灯**，reduced motion 下必须变常亮（`index.css` 已实现 `.pulse-dot { opacity: 1 !important }`）。
- 主题切换在 reduced motion 下**瞬时切换**，不扩散、不淡化。

### 5.7 对比度

- 验收标准就是 DESIGN_SYSTEM §2.4 的实测表：正文级 ≥ 4.5:1，大字/图形/焦点环/输入边界 ≥ 3:1。
- **禁用态文字按 ≥ 3:1 校准**（`--text-disabled`）。
- `--accent-3`（极光洋红）**只允许出现在渐变停靠点与插画**，禁止单独用于文字（深色底 6.40:1 虽达标，但语义上不是文字色）。
- 渐变文字限字号 ≥ 32px，且必须有纯色对比版本供读屏与低视力用户。
- 状态色不能是唯一信息载体（见 §5.5「档位」条）。
- 颜色变更后必须重跑 `python3 website/contrast-check.py`。

### 5.8 触控目标

- 所有可交互元素点击区 ≥ **44×44px**（移动端硬性）。
- 视觉上可以更小（复制按钮 32×28、主题按钮 36×36），但用 `padding` 或 `::after` 扩展点击区到 44px。
- 相邻触控目标间距 ≥ 8px。
- FAQ 触发器整行可点，高度 56px。
- 抽屉导航项 44px 高。
- 返回顶部按钮 44×44。

### 5.9 其他

- `<html lang="zh-CN">` + `<meta name="color-scheme" content="dark light">` —— 已实现。
- 表单 `autocomplete`：邮箱字段用 `autocomplete="email"`。
- 输入框 `inputmode` 与 `type`：邮箱 `type="email" inputmode="email"`。
- 页面必须有"跳到主内容"skip link。
- 所有外链新窗口打开必须带 `rel="noreferrer noopener"`（`ButtonLink` 的 `external` 分支已实现）。
- 错误提示文字不能只用红框表达，必须有文字 + `aria-describedby`。

### 6.4 内容层建议

- 所有中文文案集中放在 `src/content/`（如 `src/content/site.ts`、`home.ts`、`architecture.ts`、`features.ts`、`docs.ts`、`faq.ts`、`pricing.ts`、`about.ts`、`footer.ts`），页面组件只做布局。
