## 一、NVIDIA 规划概述

### 1.1 NVIDIA 规划方案整体定位

NVIDIA 在自动驾驶领域定位为"芯片 + 软件栈 + 数据 + 仿真"全栈平台供应商，其规划（Planning）方案并非单一算法，而是一套**多层级、可演进**的体系，覆盖从车规级中间件到端到端 VLA 大模型的完整光谱。整体规划能力承载于三大载体：

1. **NVIDIA DRIVE AV 软件套件**：包含感知、预测、规划、控制四大模块，是面向 L4 的完整参考实现。其中规划与控制层以 **Safety Force Field（SFF，安全力场）** 为核心安全决策组件，强调"基于数学零碰撞验证的安全性"而非依赖有限统计场景建模。
2. **DriveWorks SDK**：车规级中间件，提供加速算法与通用工具（传感器抽象、图像/点云处理、动态标定、Egomotion 自车运动估计等），是上层规划算法的工程基座。
3. **NDAS（NVIDIA DRIVE AV Solution）/ Alpamayo**：由吴新宙主导的 L3 级自动驾驶系统，2025 年 4 月推出第一版，采用**经典传统算法 + 端到端算法的快慢双系统**架构。2026 年 GTC 发布 Alpamayo 1.5 版 VLA（含 5 亿与 100 亿参数两个版本）。

NVIDIA 明确主张：**端到端至少要做到 10Hz 才算合格**，因此在量产架构中端到端作为"慢系统"处理复杂/长尾场景，经典规则算法作为"快系统"兜底常规驾驶。

### 1.2 与 Apollo / OpenPilot 规划的本质差异

- **Apollo**：纯模块化、规则主导（EM Planner / Lattice Planner / Open Space Planner），开源完整、工程可控性最强，但状态机在面对强博弈场景易"状态爆炸"。
- **OpenPilot（comma.ai）**：极简 L2+ 路线，横向用端到端模型输出方向盘转角（车道居中），纵向用 LongitudinalMpc（模型预测控制）做 ACC，依赖车载原厂雷达，算力门槛极低（早期骁龙 821 即可）。
- **NVIDIA**：介于两者之间的"平台型"路线——既提供经典规则栈（SFF + DriveWorks），又自研端到端 VLA（Alpamayo-R1），并通过快慢双系统融合，强调可解释性与安全可证明性。

### 1.3 DriveWorks 规划模块

DriveWorks SDK 本身不直接提供完整的"行为决策 + 轨迹生成"业务逻辑，而是提供规划所依赖的**底层能力**：

| 模块 | 对规划的支撑作用 |
|---|---|
| Sensor Abstraction Layer | 统一传感器接口，为规划提供障碍物/车道原始输入 |
| Egomotion | 基于里程计/IMU 的自车位姿估计与预测，规划起始状态来源 |
| Image Processing | 车道线、特征点提取，支撑横向参考线生成 |
| Point Cloud Processing | LiDAR 累积、拼接、地面分割，支撑可行驶区域与障碍物 |
| Dynamic Calibration | 运行时传感器外参重估，保证规划坐标一致性 |

DriveWorks 的设计哲学是"让开发者专注于上层的自车规划算法"，而 NVIDIA DRIVE AV 软件套件在其之上构建了完整的规划业务栈。

## 二、NVIDIA 规划算法体系

NVIDIA 的规划算法可分为四条技术路线，按演进时间线与量产成熟度递进。

### 2.1 基于规则的规划

经典规则栈对应 NDAS 的"快系统"，吴新宙在 GTC 2025 明确描述其流程为：

```
BEV 特征提取 → 3D 重建 → 矢量化全局表示 → 基于规则的规划与控制
```

核心组件包括：
- **参考线（Reference Line）生成**：基于高精地图车道拓扑，与 Apollo 类似采用 Frenet 坐标系。
- **行为决策**：有限状态机（FSM）/ 行为树（BT）驱动跟车、变道、让行、停车等状态切换，100% 可解释、符合 ISO 26262 功能安全。
- **轨迹生成**：横纵向解耦，横向五次多项式、纵向速度规划（QP/MPC）。
- **SFF 安全监督**：作为独立监督员实时复核主规划系统的控制决策，不安全则否决并纠正。

### 2.2 学习类规划

NVIDIA 是端到端学习驾驶的早期先驱：2016 年发表《End to End Learning for Self-Driving Cars》（即 **PilotNet / DAVE-2** 路线），用 9 层 CNN 直接从单目图像回归方向盘转角，在 NVIDIA DRIVE PX 上以 30 FPS 运行。这是 NVIDIA 学习类规划的起点，后续演进为基于 Transformer 的预测-规划一体化网络。

### 2.3 混合规划（快慢双系统）

NDAS 的核心架构是**经典规则 + 端到端**的双系统融合：

- **快系统（经典传统算法）**：高频运行（≥10Hz），处理常规场景，输出可证明安全的轨迹，承担兜底职责。
- **慢系统（端到端算法）**：处理复杂/长尾场景，输出更拟人化的决策，但需通过 SFF 安全校验后才可执行。

这种设计避免了端到端黑盒在安全关键场景的脆弱性，同时保留其在复杂博弈中的优势。

### 2.4 端到端规划：Alpamayo-R1

Alpamayo-R1（AR1）是 NVIDIA Research 于 2025 年 12 月 1 日在 NeurIPS 开源的**推理型视觉-语言-动作（Reasoning VLA）模型**，论文标题《Alpamayo-R1: Bridging Reasoning and Action Prediction for Generalizable Autonomous Driving in the Long Tail》。这是 NVIDIA 端到端规划的最新代表作，详见第六章。

## 三、DriveWorks 规划详解

### 3.1 DriveWorks SDK 规划模块

DriveWorks SDK 采用模块化设计，包含一组完整的模块、工具与示例，解决 AV 开发的典型任务与工作负载。其规划相关的能力通过以下方式暴露：

- **Egomotion 模块**：使用运动模型跟踪并预测自车位姿，支持纯里程计模型与 IMU+里程计模型。运行时接受传感器测量输入，内部更新当前位姿估计，可在任意两个时间点之间查询自车运动——这是轨迹规划"起点状态"的官方来源。
- **动态标定（Dynamic Calibration）**：在运行时根据传感器测量与车辆运动重新估计外参，补偿道路坡度、胎压、载荷变化，保证规划坐标系的时变一致性。
- **点云处理库**：GPU 加速，提供点云累积、拼接、距离图/深度图生成、RANSAC 地面平面提取、按属性过滤——直接服务于可行驶区域判断与障碍物避让。

### 3.2 路径规划

DriveWorks 层面路径规划的工程实现要点：
- 基于车道中心线建立 Frenet 参考系（S 纵向、L 横向）。
- 静态障碍物在 (S,L) 空间投影，生成可行驶走廊（Path Boundary）。
- 路径几何用五次多项式或样条曲线生成，jerk 最小化保证舒适性。

### 3.3 轨迹生成

轨迹生成在 NVIDIA 体系中遵循 Werling（2010）的经典范式：
- **横向**：五次多项式 d(t) = a0 + a1·t + ... + a5·t⁵，给定初始/末态 [d, d', d''] 求解 6 个系数。
- **纵向**：四次多项式 s(t)，或采用 ST 图上的速度规划。
- **代价函数**：综合 jerk 平方积分（舒适度）、与参考线偏离（合规）、与目标状态距离（任务完成度）、碰撞风险（安全）等项加权求和，遍历候选轨迹择优。

### 3.4 行为决策

DriveWorks 不强制特定决策框架，NVIDIA DRIVE AV 套件中默认采用 FSM/BT 的规则系统，并与 SFF 形成双层决策：FSM 决定"做什么"，SFF 决定"这样做是否安全"。

## 四、NVIDIA 轨迹规划

### 4.1 Frenet 坐标系

NVIDIA 轨迹规划采用 Frenet 坐标系，以道路中心线（参考线）为基准：
- **S 轴（纵向）**：沿参考线弧长方向，描述车辆沿车道行驶距离。
- **L 轴（横向）**：垂直参考线法线方向，描述车辆偏离中心线距离。

Frenet 坐标系的优势在于：忽略道路曲率影响，可直观表达"偏离车道多少"，将笛卡尔坐标系下的复杂曲线运动转化为两个一维问题。Apollo、NVIDIA、Werling 原始论文均采用此坐标系。

### 4.2 五次多项式

Takahashi 已证明：对于一阶积分系统（状态 = [位置, 速度, 加速度]，输入 = jerk），从初始配置到目标配置基于 jerk 最优的轨迹必在一个五次多项式中，且必存在最小化解。NVIDIA 在横向规划中采用：

```
d(t) = a0 + a1·t + a2·t² + a3·t³ + a4·t⁴ + a5·t⁵
```

纵向规划采用四次多项式（恒速假设下 jerk 最优）或 ST 图速度优化。代价函数典型形式：

```
J = w1·∫jerk²dt + w2·∫(d-d_ref)²dt + w3·T + w4·CollisionCost
```

### 4.3 SFF 的 3D 时空轨迹

与传统 Frenet 横纵向解耦不同，**SFF 在 3D 时空（x, y, t）内统一运行**，不拆解纵向/横向。其核心机制：

1. 为每个对象计算"所有空间"（all-space）——执行安全程序时在时空占据的体积。
2. 当不同对象的所有空间重叠，即存在碰撞风险，SFF 立即计算最佳控制指令。
3. 利用"安全潜力"（Safety Potential）数学函数，通过扰动分析确定避免碰撞且对主系统干扰最小的控制组合（制动+转向）。
4. GPU 加速实现逐帧物理仿真。

SFF 的独特价值：**综合考虑纵向与横向**，在缺少车道线、停车场等难以分辨纵横方向的场景中仍可工作；同时兼顾制动与转向限制，避免单一维度优化导致的异常行为。

### 4.4 与 Apollo Lattice 的对比

| 维度 | NVIDIA SFF + Frenet | Apollo Lattice Planner |
|---|---|---|
| 坐标系 | Frenet（横纵向解耦）+ SFF 3D 时空 | Frenet（横纵向解耦） |
| 轨迹采样 | 五次/四次多项式 + SFF 扰动优化 | 横纵向独立采样，组合成候选集 |
| 安全机制 | 数学可证明零碰撞的 SFF 监督层 | 代价函数中的碰撞项 + 硬约束校验 |
| 优化目标 | jerk 最小 + SFF 安全潜力最大化 | 代价函数加权（jerk、偏离、碰撞、效率） |
| 横纵向关系 | 规划层解耦，SFF 层联合 3D 校验 | 完全解耦，分别 DP/QP |
| 适用场景 | 高速 + 城市 + 无结构化道路（停车场） | 高速 + 城市结构化道路 |
| 可证明性 | SFF 有数学零碰撞证明 | 工程启发式，无形式化安全证明 |

## 五、NVIDIA 行为决策

### 5.1 状态机（FSM）

NVIDIA DRIVE AV 经典栈采用有限状态机进行行为决策，典型状态包括：巡航（Cruise）、跟车（Follow）、变道准备（Lane Change Prepare）、执行变道（Lane Change Execute）、让行（Yield）、停车（Stop）、紧急制动（Emergency Brake）等。状态转移由感知/预测/路由信息触发，逻辑刚性、可解释、易 Debug，符合 ISO 26262。

### 5.2 规则系统

规则系统是 NVIDIA 量产方案的绝对主流实现方式（FSM/行为树）。优点是 100% 可解释、安全边界明确；缺点是面对强博弈（加塞、强行并线）易状态爆炸，代码充斥 if-else，决策呆板。

### 5.3 学习类决策

NVIDIA 在 Alpamayo-R1 中将行为决策升级为**因果链推理（Chain of Causation, CoC）**驱动的学习类决策：模型在输出动作前先生成自然语言推理链，例如"因为前方有行人横穿，且左侧车道空闲，所以减速并左变道"。这是一种介于纯规则与纯黑盒之间的"白箱"决策范式。

### 5.4 SFF 作为安全决策层

SFF 独立于主决策系统，作为运动规划堆栈中的安全决策策略，监控并预防不安全操作，让避障机制从复杂的道路规则机制中明确独立出来，为平台增加分集与冗余。

## 六、Alpamayo-R1 规划

### 6.1 VLA 模型输出轨迹

Alpamayo-R1 是基于 NVIDIA **Cosmos-Reason** 骨干网络（370 万条物理常识 VQA 样本后训练）的 Reasoning VLA，10B（100 亿）参数，架构分三部分：

1. **感知与自身状态输入**：多摄像头时空特征融合，SigLIP 视觉编码，BEV 空间对齐，轻量级 CNN + 时间注意力压缩 90% 视觉 token。
2. **因果推理引擎**：输出 Chain-of-Causation 推理 token，显式回答"为什么这样做"。
3. **动作解码器**：基于流匹配（Flow Matching）/ 扩散模型的轨迹解码器，输出 64 时间步的连续轨迹（以加速度 + 曲率控制量表示），误差 ±0.3m，兼顾动力学合理性与 VLM 联合建模。

输出三类 token：推理链（reasoning traces）、中层动作（meta-actions）、未来轨迹预测（trajectories）。

### 6.2 与传统规划的差异

| 维度 | Alpamayo-R1 | 传统规则规划 |
|---|---|---|
| 输入 | 多摄像头视频 + 语言指令 | 结构化感知结果 + 高精地图 |
| 决策方式 | 因果链推理 + 扩散轨迹生成 | FSM 状态转移 + 多项式采样 |
| 可解释性 | 自然语言推理链（白箱） | 规则代码（白箱） |
| 长尾能力 | 强（推理泛化） | 弱（状态爆炸） |
| 实时性 | 99ms 端到端延迟 | <50ms（高频） |
| 安全可证明性 | 弱（需 SFF 兜底） | 强（SFF + 规则） |
| 训练数据 | 1700 小时 Physical AI AV 数据集 + CoC 标注 | 无需训练 |

### 6.3 优势与劣势

**优势**：
- 规划精度提升 12%（开环 minADE@6s）
- 闭环越野率降低 35%、近距离接触率降低 25%
- 推理-行动一致性提升 37%
- 实车延迟仅 99ms，支持红灯识别与多步动作规划
- 可解释因果链，长尾场景泛化能力强

**劣势**：
- 10B 参数模型对算力要求高（量产需 Thor 级 SoC）
- 黑盒成分仍存在"幻觉"风险，需 SFF 安全兜底
- 训练依赖海量高质量 CoC 标注数据（10 万条推理样本）
- 99ms 延迟对超高速场景仍偏慢，需快系统补位
- RL 后训练调参复杂

### 6.4 三阶段训练策略

1. **动作注入（SFT）**：500 万公里驾驶数据预训练，建立视觉到动作的基本映射；Cosmos-Reason 在 370 万 VQA + 2.47 万驾驶视频样本上后训练获得"因果直觉"。
2. **推理引出（CoC Supervision）**：10 万条 CoC 数据集监督微调，显式教模型"先想清楚再开"；GPT-5 生成初版推理链 + 人工按因果覆盖度/时序正确性审核。
3. **RL 一致性优化**：多维奖励——推理质量（专家模型评估）、推理-行动一致性、轨迹平滑度与安全性。

## 七、NVIDIA 预测

### 7.1 预测模块

NVIDIA 预测模块在 DRIVE AV 套件中以 **PredictionNet DNN** 为代表，从传感器数据预测道路代理的下一步行动与轨迹。预测结果作为规划的核心输入，形成"感知 → 预测 → 规划"闭环。

### 7.2 多目标轨迹预测

NVIDIA 在可解释轨迹预测方向有重要专利布局——**US20250091618A1《Interpretable trajectory prediction for autonomous and semi-autonomous systems》**（发明人 Yuxiao Chen、Kai-Chieh Hsu、Karen Leung 等，含普林斯顿合作团队，源自 IROS 2023 论文）。核心创新是引入**反事实责任（Counterfactual Responsibility）**框架：

- **安全责任（Safety Responsibility）**：若被查询车辆采取不同行动，是否能保持更大安全距离？
- **礼貌责任（Courtesy Responsibility）**：若该车辆调整行为，是否能让其他参与者更舒适高效？

责任值量化为离散等级（0-7 共 8 级），作为条件信号输入底层轨迹预测模型（BITS 改进版），使预测结果天然附带可解释标签。在 nuScenes 上，训练 ADE 降低 26.5%（1.02m→0.75m），验证 ADE 降低 11.6%（1.64m→1.45m）——精度与可解释性同步提升。

### 7.3 与 Apollo 预测的对比

| 维度 | NVIDIA 预测 | Apollo 预测 |
|---|---|---|
| 核心网络 | PredictionNet + 责任感知框架 | MLP + CNN/RNN 轨迹生成器 + Evaluator |
| 可解释性 | 反事实责任等级标签 | 概率分布 + 意图分类 |
| 多模态 | 多假设轨迹 + 责任条件 | 多假设轨迹（MTR 类） |
| 数据驱动 | 深度学习 + 博弈论责任建模 | 深度学习为主 |
| 量产成熟度 | DRIVE AV 套件集成 | 开源完整、社区成熟 |

## 八、NVIDIA 规划数据

### 8.1 训练数据：Physical AI AV 数据集

NDAS/Alpamayo 配套的 **Physical AI AV 数据集**规模：

- **1700 小时**真实驾驶数据
- 覆盖**欧美 25 个国家、2500+ 城市**
- **306,152** 个 20 秒视频片段
- **298,326** 个激光雷达片段（1 个 128 线 360° 旋转 LiDAR）
- **160,761** 个毫米波雷达片段（10 个雷达）
- 总规模 **133 TB**

数据集在 Hugging Face 上下载量已超 1500 万次，是业界最大的开源物理 AI 驾驶数据集之一。

### 8.2 仿真数据：Omniverse + Cosmos

NVIDIA 构建了"真实数据 + 仿真数据"双轮驱动的数据飞轮：

- **NVIDIA Omniverse**：基于 RTX 的物理级光线追踪仿真平台，提供数字孪生（Digital Twin）、RTX 传感器仿真（ovrtx 库）、高保真场景重建。用于生成现实中过于危险或罕见的边缘场景。
- **Cosmos 世界基础模型**：面向物理 AI 的世界模型，2026 年 7 月发布 **Cosmos 3 Edge**（40 亿参数），可在边缘设备实时感知环境、预测未来、生成动作。支持结构化场景的高清视频合成与像素级对齐数据集构建。
- **Neural Reconstruction**：从车队数据自动重建真实场景，AI Agent 自动完成"数据 → 场景重建 → 合成场景生成"完整流程。

### 8.3 真实数据 + AlpaSim 闭环

**AlpaSim** 是 NVIDIA 专为评估端到端模型设计的开源端到端仿真框架，构建了 900 个高风险场景的数字化双胞胎，通过"推理-动作-结果"三重验证：
1. 语义合理性：推理链是否符合交规
2. 物理可行性：轨迹是否满足动力学约束
3. 结果安全性：最终行为是否避免碰撞

经 AlpaSim 验证的策略可使实车碰撞率降低 62%。AlpaSim closed-loop end-to-end driving challenge 已成为业界重要的闭环评测基准。

## 十一、AuroraDrive 规划升级建议

### 11.1 AuroraDrive 当前状态

AuroraDrive 当前规划栈为 **A\* 全局路径规划 + Pure Pursuit（纯跟踪）横向控制**：
- **A\***：图搜索全局路径，启发式估算，适合结构化道路全局路由。
- **Pure Pursuit**：基于前视距离的几何横向跟踪，实现简单、计算量小，但在低速、大曲率、动态避障场景下精度与平滑性不足，且无显式行为决策与速度规划。

**主要短板**：
1. 无显式行为决策层（FSM/规则），无法处理跟车、变道、让行等场景。
2. 无纵向速度规划（无 ST 图、无 MPC），无法做 ACC 与动态避障。
3. Pure Pursuit 在变道、避障时轨迹不连续，舒适性差。
4. 无安全监督层，缺乏形式化安全保证。
5. 无预测模块，无法应对动态障碍物。

### 11.2 借鉴 NVIDIA 规划思想

从 NVIDIA 规划方案中，AuroraDrive 可重点借鉴以下思想：

1. **Frenet 坐标系 + 横纵向解耦**：将 Pure Pursuit 升级为 Frenet 下的五次多项式横向轨迹 + ST 图纵向速度规划，显著提升平滑性与动态避障能力（NVIDIA 与 Apollo 共同范式）。
2. **SFF 安全监督思想**：引入轻量级安全校验层，对规划输出做碰撞预测与扰动修正，无需完整 SFF 也能显著提升安全性。
3. **快慢双系统理念**：保留 A\* + Pure Pursuit 作为快系统兜底，逐步引入学习类规划（如轻量端到端模型）作为慢系统处理长尾。
4. **可解释决策链**：借鉴 Alpamayo-R1 的 CoC 思想，在决策层输出自然语言理由，便于调试与审计。
5. **Omniverse/Cosmos 仿真闭环**：建立仿真验证体系，对规划策略做闭环测试后再上车。

### 11.3 AuroraDrive 规划升级方案（分阶段）

**阶段一（短期，1-2 月）：规则栈补齐**
- 引入 Frenet 坐标系，将全局 A\* 路径转为参考线。
- 横向：Pure Pursuit → 五次多项式轨迹生成（Werling 范式），jerk 最小化。
- 纵向：新增 ST 图速度规划（QP 或简单 MPC），支持跟车与限速。
- 行为决策：引入轻量 FSM（巡航/跟车/停车/避障 4 状态）。
- 输出：完整 [x(t), y(t), v(t), a(t), θ(t), κ(t)] 轨迹。

**阶段二（中期，3-6 月）：安全层 + 预测**
- 实现 SFF-Lite：简化版安全监督层，对候选轨迹做 3D 时空碰撞预测，否决不安全轨迹。
- 引入轻量预测模块（基于历史轨迹的卡尔曼/简单神经网络），输出动态障碍物多假设轨迹。
- 建立 ROS 仿真闭环（参考 NVIDIA AlpaSim 思路），离线验证规划策略。

**阶段三（长期，6-12 月）：双系统融合**
- 保留阶段一/二规则栈作为快系统（≥10Hz）。
- 引入轻量端到端模型（如 PilotNet 风格或小型 Transformer）作为慢系统，处理长尾场景。
- 借鉴 Alpamayo-R1 的 CoC 思想，在关键决策点输出可解释推理链。
- 通过 SFF-Lite 安全校验后融合双系统输出。
- 目标：在 AuroraDrive 算力范围内，接近 NVIDIA NDAS 快慢双系统的工程效果，但成本与复杂度显著降低。

**升级路线总结表**：

| 阶段 | 规划算法 | 决策 | 安全 | 预测 | 仿真 | 对标 NVIDIA |
|---|---|---|---|---|---|---|
| 当前 | A* + Pure Pursuit | 无 | 无 | 无 | 无 | — |
| 阶段一 | Frenet + 五次多项式 + ST | FSM(4态) | 无 | 无 | 无 | 经典规则栈雏形 |
| 阶段二 | + QP/MPC 速度 | FSM 扩展 | SFF-Lite | 轻量预测 | ROS 闭环 | DRIVE AV 规则栈 |
| 阶段三 | + 端到端慢系统 | CoC 推理 | SFF-Lite | 神经预测 | 仿真闭环 | NDAS 快慢双系统 |

### 11.4 关键风险与对策

- **风险**：Frenet + 多项式在复杂城市路口参考线断裂。**对策**：参考线平滑（借鉴 Apollo 离散点 QP 平滑）。
- **风险**：SFF-Lite 完整 3D 时空计算量大。**对策**：降维为 2D 椭圆碰撞检测 + 时间窗，后续再升级。
- **风险**：端到端慢系统黑盒不可控。**对策**：严格 SFF-Lite 兜底 + CoC 可解释输出 + 仿真闭环验证。
- **风险**：算力不足。**对策**：阶段三端到端模型控制在小参数量（<1B），或采用模型蒸馏。

## 十二、结论

NVIDIA 自动驾驶规划方案的核心特色是**"快慢双系统 + SFF 安全证明 + VLA 可解释推理"三位一体**：

1. **工程务实**：不盲目追求纯端到端，保留经典规则栈作为快系统兜底，符合 ISO 26262 功能安全要求。
2. **安全至上**：SFF 提供数学可证明的零碰撞安全监督层，是行业唯一有形式化安全保证的规划组件。
3. **可解释创新**：Alpamayo-R1 的因果链推理（CoC）将端到端从黑箱推向白箱，反事实责任预测框架同步提升精度与可解释性。
4. **数据飞轮**：Physical AI 数据集（1700h）+ Omniverse 仿真 + Cosmos 世界模型 + AlpaSim 闭环，构成完整数据闭环。
5. **平台开放**：从 DriveWorks SDK 到 Alpamayo-R1 开源，覆盖从底层中间件到顶层 VLA 的全栈能力。

对 AuroraDrive 而言，NVIDIA 方案最重要的启示是：**规划升级不必一步到位端到端，而应分阶段从规则栈补齐（Frenet + 多项式 + FSM）→ 安全层（SFF-Lite）→ 双系统融合**，在算力与安全之间取得平衡。
