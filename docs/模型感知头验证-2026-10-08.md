## 1. A. GAP 修复验证 —— ✅ 真修复（最关键回归）

### 1.1 背景

原 `LaneMaskEncoder` 用 `AdaptiveAvgPool2d((1,1))`（全局平均池化）→ **对空间求平均 = 平移不变**，
抹掉车道线的「横向位置」信息。这是「模型看得见车道线、却分不清左右、会开出车道线」的**架构根源**。

修复：`GAP(2,2)` 保留 2×2 位置块 + `spatial_proj` 投影回 64 维。

### 1.2 实测结果

| 检查项 | 实测 | 判定 |
|---|---|---|
| 结构已改 | `global_pool=AdaptiveAvgPool2d(output_size=(2, 2))`、`spatial_proj=Linear(256→64)` | ✅ |
| lane_feat 左 vs 右 | 最大差 **0.008965** | ✅ >0 |
| steer 左 vs 右 | 最大差 **0.002812** | ✅ >0 能传到输出 |
| 左/中/右 两两可分 | 左中=0.006098，中右=0.004671 | ✅ |
| **旧 GAP(1,1) 对照** | 最大差 **4.657e-10**（本质为 0） | ✅ **bug 复现** |
| **修复效果** | 新 0.008965 vs 旧 4.657e-10 → **提升 1.93e+07×** | ✅ |

> **对照公平性说明**：旧结构用**新模型的卷积权重**初始化，两者唯一差别 = 池化方式。
> 因此这个倍数差异**纯粹来自 GAP 修复**，不是权重差异造成的。

### 1.3 旧 checkpoint 兼容性

```
missing=34（spatial_proj 2 键 + 三头 32 键）
unexpected=0        ← 旧权重全部能被新架构接收
```
✅ 兼容：卷积权重可继承，新增头需重新训练才生效。

**⚠️ 重要提示**：**现有 `checkpoints/m9_v2/best_model.pt` 里 `spatial_proj` 与三头的权重全部缺失**——
GAP 修复与三头在**架构上**生效了，但要真正让它们影响输出，**必须重新训练**。

### 2.2b 🔴 部署级：trace 剪枝（仍未修，已派 w5）

CoreML 导出的前提是 `jit.trace`。实测：

```
jit.trace(5 输入)  →  OK
输出: [(1,1), (1,1), (1,1)]
图中含 GRU 算子: False      ← ★ 时序分支被完整剪掉
```

**原因**：导出脚本只传 5 个输入（`image/lane/dets/det_mask/vehicle_state`），
`history_feats` 默认 `None` → trace 时 `if history_feats is not None` 恒为 False
→ **时序分支被剪枝，导出的 CoreML 里根本没有 GRU**。

> **⟹ 即便模型级已通，上车后时序能力仍 = 0。**
> **修复要点**：导出时必须**传非 None 的 `history_feats` 假数据**做 trace，
> 保证时序分支进图；同时把 `history_feats`/`frame_mask` 加进 CoreML 输入契约。

## 7. G0. ★ 导入上下文陷阱（**已修复**）

### 7.1 问题

`model_v2.py:200-211`（修复前）用**软依赖**导入三个头：

```python
try:
    from src.heading_head import HeadingHead      # 注意前缀 src.
except ImportError:
    HeadingHead = None                            # ← 静默降级，无告警
```

### 7.2 实测复现（修复前，决定性）

| 运行方式 | `from src.heading_head import` | 结果 |
|---|---|---|
| `python3 -c "import model_v2"`（cwd 在 path） | ✅ 成功 | **三头正常挂载** |
| `python3 src/xxx.py`（`sys.path[0]=src/`，repo root **不在** path） | ❌ `ModuleNotFoundError: No module named 'src'` | **三头全变 None，无任何告警** |

修复前实测输出（只放 src、不放 repo root）：
```
HeadingHead      = None
TemporalEncoder  = None
RiskHead         = None
m.heading_head   = None
m.risk_head      = None
m.temporal_enc   = None
```

### 7.3 影响

**任何以脚本方式（`python3 src/xxx.py`）调用 `model_v2` 的下游，都会静默丢掉三个头。**

> 本验证脚本**第一次运行就被它坑了**：报了 15 个 FAIL，看起来像「三头全没集成」，
> 实际只是导入环境问题。补上 `repo root` 到 `sys.path` 后立刻大幅改善。
> **这正说明该陷阱的误导性** —— 会产生**假红**（误判没集成）或**假绿**（误判集成好了）。

### 7.4 ✅ 修复实现（t1 已改 `model_v2.py`）

改为**双路径回退 + 降级必告警**：

```python
def _import_head(mod_name: str, attrs: str):
    names = [a.strip() for a in attrs.split(",") if a.strip()]
    for path in (f"src.{mod_name}", mod_name):     # ① 包内路径 ② 脚本运行回退
        try:
            mod = importlib.import_module(path)
            if all(hasattr(mod, n) for n in names):
                return tuple(getattr(mod, n) for n in names)
        except ImportError:
            continue
    _warnings.warn(                                 # ② 都失败 → 必须告警，绝不静默
        f"[model_v2] ⚠ 无法导入 {mod_name}（{names}）—— 该感知头将被禁用…",
        RuntimeWarning, stacklevel=2)
    return (None,) * len(names)
```

### 7.5 ✅ 修复复验（两条都通过）

| 验证场景 | 结果 |
|---|---|
| **模块方式**（repo root 在 path） | 三头全部挂载 ✅ |
| **脚本方式**（path[0]=src，repo root 不在）← 原陷阱环境 | **三头仍全部挂载** ✅（双路径回退生效） |
| **模块真的不存在**（隔离目录） | 发出 **3 条 RuntimeWarning** ✅（不再静默） |
