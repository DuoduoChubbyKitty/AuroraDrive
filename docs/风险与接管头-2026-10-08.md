## 0. 一句话结论

模型侧现在有了一个**自评置信度 + 危险度**的感知头，加上**两条 TTC 路径**（无标定的框增速路径 + 需标定的绝对距离路径）和**带滞后的接管状态机**。合成一个可接线的"救车信号"：`TakeoverDecider.update(...)` 返回的 `state.active` = True 时就该把控制权交还用户。

**当前项目现状下的推荐 TTC 路径：`ApproachRateEstimator`**（不需要任何标定，见 §3.6 的数学证明）。

## 1. 模块结构（`src/risk_head.py`）

| 组件 | 输入 | 输出 | 用途 |
|---|---|---|---|
| **RiskHead** | 融合特征 [B,512] + 检测特征 [B,N,128]（可选）+ 速度 | (confidence [B], risk [B])，均 ∈[0,1] | 模型自评"我有多确定/多危险" |
| **ApproachRateEstimator** | 逐帧检测框 [N,12] + dt | 每框 {ttc, closing, samples, valid} | **无标定** TTC（框变大速率，§3.6） |
| **estimate_ttc** | 检测框 [B,N,12] + 自车速度 + 标定 K | (ttc [B,N], distance [B,N], valid [B,N]) | 需标定的绝对距离 TTC |
| **TakeoverDecider** | confidence / risk / ttc_min | TakeoverState（active + reason） | 阈值 + 滞后 → 稳定的接管信号 |
| **RangeCalibrator** | （距离, 框高）标定样本对 | K 常数 + 残差报告 | 单目距离标定 |
| **confidence_target_from_error** | pred/target | conf 真值 [B] | 训练信号（误差代理） |
| **confidence_target_from_temporal_change** | 控制量序列 [T,B,D] | conf 真值 [T,B] | 训练信号（**变化代理，无需真值**） |
| **risk_target_from_ttc** | ttc | risk 真值 [B] | 训练信号（TTC 映射） |

### 2.2 部署时的接管流（Swift 侧）

```text
每帧：
  1. RiskHead → confidence, risk
  2. 检测框 → estimate_ttc → ttc_min（最小 TTC；无标定则跳过）
  3. decider.update(conf, risk, ttc_min) → state
  4. state.active == True → 交还控制权给用户（UI 提示 state.reason）
```

`ControlCommand.confidence` 字段（Swift 侧已存在、没人填）从此有了模型侧来源：
`confidence` 直接填 RiskHead 的输出即可。

## 3. 关键设计决定（每条都写明理由）

### 3.1 confidence 用 sigmoid，不用 softmax
单值自评（"这一帧我多确定"），不是多分类。softmax 会强制归一化到"和为 1"，语义错位。与项目既有 steer(tanh)/throttle(brake)(sigmoid) 风格统一。

### 3.2 RiskHead 吃融合特征，不吃控制量输出
控制量已被压成 3 个数，丢掉了"我看到了什么"的上下文。自评需要看特征本身。

### 3.3 检测支路用 max_mean 池化
与 `model_v2.DetectionEncoder` 同款理由：max 抓"最危险的单个框"，mean 抓"整体交通密度"。

### 3.4 滞后（hysteresis）参数
- `conf_enter=0.35 / conf_exit=0.60`：进入比退出严格，中间是死区
- `risk_enter=0.70 / risk_exit=0.45`
- `min_release_frames=30`：解除需**连续** 30 帧满足条件，防单帧抖动
- **死区里的 reason 会如实说明**"处于滞后死区，置信度未回到 X 以上"，不显示过期原因

### 3.5 初始化偏置：risk 初始偏向"低风险"
`risk_head.bias = log(0.1/0.9) ≈ -2.2` → 初始 risk ≈ 0.1。
**理由**：部署时接管信号是"扰民"的（用户要手动接管），一上来就疯狂请求会毁掉体验。宁可冷启动保守，不可开局乱报警。

### 3.6 ★ 关键发现：TTC 其实不需要标定（K 被消掉）

Lead 指出"检测框只有归一化画面坐标、无物理距离，TTC 只能粗估"。本小姐推导后发现**更好的路径**——用「框变大速率」算 TTC，**数学上不需要任何标定常数**：

```
透视投影：h = K / Z        （h=归一化框高，Z=距离，K=标定常数）
      ⇒  Z = K / h

对时间求导：
      dZ/dt = −(K / h²) · (dh/dt)

接近速度：
      v = −dZ/dt = (K / h²) · (dh/dt)

碰撞时间：
      TTC = Z / v = (K/h) / [(K/h²)(dh/dt)] = h / (dh/dt)      ← K 消掉了！
```

**结论**：只需要「当前框高」和「框高变化率」，**不需要相机焦距、不需要目标真实尺寸、不需要任何标定**。

实现：`ApproachRateEstimator`（跨帧 IoU 匹配跟踪 + 有限差分 + EMA 平滑）。
自检验证：框高 0.10→0.18 线性增大（Δ=0.02/帧@24fps）时，TTC 精确等于 `0.14/(0.02×24)=0.292s` ✅。

**前提与失效条件（如实声明，见类文档）**：
1. 需要跨帧跟踪同一目标（检测器自带 track id 应优先用检测器的）
2. `dh/dt` 为有限差分，帧间抖动会放大 → 内部 EMA 平滑 + `min_samples=3` 门槛，样本不足时 `valid=False`（**不拿两次差分当真**）
3. 目标**真实尺寸变化**（行人走近又蹲下）会破坏 h∝1/Z 前提 → 错估
4. 目标**横向掠过**（Z 不变）→ dh/dt≈0 → TTC=inf（正确行为，已验证）
5. 大偏航角时透视关系变化 → 只做粗估

## 4. ⚠️ 诚实声明（必须读）

### 4.1 TTC 依赖标定，未标定时输出全无效
单目相机（含游戏第三视角）**无法从单帧得到绝对距离**。公式 `Z = K / h_norm` 的 K 必须**实测标定**（`RangeCalibrator` 提供最小二乘拟合 + 残差报告）。
**未标定时 `estimate_ttc` 返回 `valid` 全 False、`ttc`/`distance` 全 inf——不返回假数字。**
（出处：TTC = 距离/相对速度，[Kilicarslan 2018](https://scholarworks.indianapolis.iu.edu/bitstream/1805/18821/1/Kilicarslan_2018_predict.pdf)）

### 4.2 confidence 的训练信号是**误差代理**，不是真值
`confidence_target_from_error` 用「控制量预测误差」间接监督：误差大→该低置信。
**根本局限：模型可以"自信地犯错"**（误差小但方向完全跑偏），误差代理无法惩罚这种。

2. 建议掺入闭环信号（离线回放的偏离车道中心量）做真值增强。

### 4.3 TTC 无框速字段时的保守假设
检测框特征第 [9] 位（目标相对速度）游戏检测器多不提供（`use_box_speed_field=False` 默认）。此时假设**目标静止** → v_rel 取上界 → TTC 取**悲观值**。宁可早报警，不可漏报。

### 4.4 Lead 补充的两条输入现状（已按此设计）
1. **自车速度 `SpeedOCRReader.speedKmh` 未读到时是 -1**——调用方必须先判 `speedValid`（w3 已在 InferenceEngineV2 做硬门），**不要把 -1 直接喂进 TTC**（会被当成负速度）。`estimate_ttc` 的文档字符串已写明此约束。
2. **检测框只有归一化画面坐标，无物理距离（米）** → 绝对距离路径的 `estimate_ttc` 在当前现状下**只能靠标定或深度估计**。这正是 §3.6 的 `ApproachRateEstimator`（框增速路径，K 消掉、无标定）成为推荐路径的原因。
3. **accel 真值在包里但坐标系未标定**（scale÷10，单位推测 cm/s²，世界 vs 车体未实测）→ RiskHead 的 `speed` 输入暂用 **OCR 差分**（speed_kmh 差分 ÷ dt）或置 0；等 accel 标定后切真值。
4. **confidence 无"危险帧"标注** → 按**误差代理**实现（`confidence_target_from_error`）；Lead 建议的**变化代理**也已实现（`confidence_target_from_temporal_change`，无需真值，用控制量帧间变化）。两条代理互补，TODO 见 §4.2。
