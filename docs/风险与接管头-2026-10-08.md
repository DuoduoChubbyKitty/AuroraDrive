## 0.5 ★ M3 新增：24 步迭代中间步辅助（`docs/24步迭代精修-CoT-需求-2026-10-08.md` §3.2）

需求：**中间步有活干，不能偷懒**。
```
第 8 步：预测"车道中心偏移"（有真值监督）
第 16 步：预测"TTC 碰撞时间"（有真值监督）
第 24 步：预测最终 steer/throttle/brake
```

### 新增接口

```python
# ⚠️ step_feat_dim 默认 = 512（w7 IterationRefiner.feat_dim 实测值，2026-10-08 纠正）
#    曾误设 128 —— 那是 w7 step_head.fc 的**内部隐层宽度**，不是 step 特征维度。
risk_head = RiskHead(RiskHeadConfig(step_feat_dim=512))

# ① 中间步（第 N 步）→ 该步的 conf/risk/offset
conf, risk, offset = risk_head.forward_step(step_feat, step_index=8)
#    step_feat: [B, 512]（w7 每步 refined 特征）
#    conf/risk ∈ [0,1]；offset ∈ [-2.0, +2.0]（米，左负右正）

# ② 最终融合特征 → conf/risk/偏移
conf, risk, offset = risk_head.forward_with_offset(fused_feat, det_feat=None, speed=None)

# ③ 原有 forward 签名不变（向后兼容），仍返回 (conf, risk)
conf, risk = risk_head(fused_feat)
```

### ⚠️ 待裁决：中间步输出的职责重叠（W7 与 W4）→ **已裁决（方案 A）**

W7 的 `IterationRefiner` 已在每步输出 `step8: lane_offset(tanh∈[-1,1])` / `step16: ttc(softplus≥0s)`。本模块 `forward_step` 原本也出 offset。**Lead 2026-10-08 裁决**：

| 职责 | 归属 | 本模块行为 |
|---|---|---|
| 中间步 offset/ttc **预测** | **W7 refiner 内部**（天然在迭代里） | `use_step_offset=False`（默认关），offset 返回全零 |
| 中间步 **conf/risk 预测** | **本模块 `forward_step`**（W7 不出） | **照常输出**，不受 `use_step_offset` 影响 |
| offset/ttc **真值** | **本模块**（W7 没有真值函数） | `lane_central_offset` + `risk_target_from_ttc` 保留 |

**关键修正**：曾把 `use_step_offset=False` 写成"整个 step 头都关"，导致 conf/risk 也返回全零（自检 "conf/risk 仍非常数" 断言抓出）。Lead 裁决是"只关 offset 预测、conf/risk 照常出"。已改正，变异对照验证。

### `lane_central_offset(normalize=True)` —— 真值侧归一化（Lead 裁决）

两套量程差 ~48 倍（网格格数 ±80 vs tanh ±1），直接监督会互相拉扯。**Lead 裁决：归一化在真值侧做，t1 不用知道"÷80"这个魔数**：

```python
# 默认：网格格数（兼容旧调用）
offset_grid, valid = lane_central_offset(lane_mask)            # ±80

# 归一化：直接对齐 w7 的 tanh 预测口径，t1 可直接监督
offset_norm, valid = lane_central_offset(lane_mask, normalize=True)  # ∈[-1,1]
#  关系：normalize 版 = (质心列 − 80) / 80
```
`normalize=True` 时忽略 `offset_scale`（避免双重缩放歧义）。自检验证：`-38/80 = -0.475` 精确成立。

### 车道中心偏移真值（step8 监督信号）

```python
from risk_head import lane_central_offset, LaneOffsetConfig
offset_gt, valid = lane_central_offset(lane_mask)   # [B,1,160,160] 二值
```
- **口径与 `src/lane_geometry.py` 一致**：内容行 [35,125)，灰边行（0..35 / 125..160）**排除**——否则 letterbox 灰边会被当成车道线造成系统偏移。
- 算法：内容行内**按行取水平质心**再求均值（每行等权，避免近处宽线像素多而偏向近处）。
- 单位：**网格格数**（默认 scale=1.0）。换算成米需知道单格实际宽度——本项目**未标定**，故保持网格单位。
- **诚实声明**：这是**几何代理真值**（假设"车道线质心≈车道中心"），双实线/单虚线/无标线时各有偏差。做 step8 辅助监督足够，做精确定位不够。

### 设计约束（供 t1/w7 接线）

1. `forward_step` **不吃 det_feat/speed** —— 中间步信息应已由 IterationRefiner 融进 hidden。若 hidden 里没有检测/速度信息，step16 的 TTC 监督会缺输入（已告知 w7，必要时加可选入参）。
2. step 支路是**独立参数**（`step_*` 前缀），不与融合支路共享 —— 理由同 HeadingHead 的 Δ/绝对双分支：中间步特征语义不同，共享参数会让两种梯度互相拉扯。
3. `step_feat_dim` **默认 512**（= w7 `IterationRefiner.feat_dim` 实测值）；维度不符会**明确报错**，不静默。自检钉了 `step_feat_dim == 512` 断言防回退。
4. `use_step_offset=False`：`forward_step` 返回全零（退化兼容），`forward_with_offset` 明确报错。

## 1. 模块结构（`src/risk_head.py`）

| 组件 | 输入 | 输出 | 用途 |
|---|---|---|---|
| **RiskHead** | 融合特征 [B,512] + 检测特征 [B,N,128]（可选）+ 速度 | (confidence [B], risk [B])，均 ∈[0,1] | 模型自评"我有多确定/多危险" |
| **RiskHead.forward_step** | 迭代第 N 步特征 [B,128] | (conf, risk, **lateral_offset**) | **24 步中间步辅助**（step8 offset / step16 risk） |

| **confidence_target_from_temporal_change** | 控制量序列 [T,B,D] | conf 真值 [T,B] | 训练信号（**变化代理，无需真值**） |
| **risk_target_from_ttc** | ttc | risk 真值 [B] | 训练信号（TTC 映射） |

## 3. 关键设计决定（每条都写明理由）

### 3.1 confidence 用 sigmoid，不用 softmax
单值自评（"这一帧我多确定"），不是多分类。softmax 会强制归一化到"和为 1"，语义错位。与项目既有 steer(tanh)/throttle(brake)(sigmoid) 风格统一。

### 3.2 RiskHead 吃融合特征，不吃控制量输出
控制量已被压成 3 个数，丢掉了"我看到了什么"的上下文。自评需要看特征本身。

### 3.3 检测支路用 max_mean 池化
与 `model_v2.DetectionEncoder` 同款理由：max 抓"最危险的单个框"，mean 抓"整体交通密度"。

### 3.4 滞后（hysteresis）参数
- `conf_enter=0.35 / conf_exit=0.60`：进入比退出严格，中间是死区
- `risk_enter=0.70 / risk_exit=0.45`
- `min_release_frames=30`：解除需**连续** 30 帧满足条件，防单帧抖动
- **死区里的 reason 会如实说明**"处于滞后死区，置信度未回到 X 以上"，不显示过期原因

### 3.5 初始化偏置：risk 初始偏向"低风险"
`risk_head.bias = log(0.1/0.9) ≈ -2.2` → 初始 risk ≈ 0.1。
**理由**：部署时接管信号是"扰民"的（用户要手动接管），一上来就疯狂请求会毁掉体验。宁可冷启动保守，不可开局乱报警。

### 3.6 ★ 关键发现：TTC 其实不需要标定（K 被消掉）

Lead 指出"检测框只有归一化画面坐标、无物理距离，TTC 只能粗估"。本小姐推导后发现**更好的路径**——用「框变大速率」算 TTC，**数学上不需要任何标定常数**：

```
透视投影：h = K / Z        （h=归一化框高，Z=距离，K=标定常数）
      ⇒  Z = K / h

对时间求导：
      dZ/dt = −(K / h²) · (dh/dt)

接近速度：
      v = −dZ/dt = (K / h²) · (dh/dt)

碰撞时间：
      TTC = Z / v = (K/h) / [(K/h²)(dh/dt)] = h / (dh/dt)      ← K 消掉了！
```

**结论**：只需要「当前框高」和「框高变化率」，**不需要相机焦距、不需要目标真实尺寸、不需要任何标定**。

实现：`ApproachRateEstimator`（跨帧 IoU 匹配跟踪 + 有限差分 + EMA 平滑）。
自检验证：框高 0.10→0.18 线性增大（Δ=0.02/帧@24fps）时，TTC 精确等于 `0.14/(0.02×24)=0.292s` ✅。

**前提与失效条件（如实声明，见类文档）**：
1. 需要跨帧跟踪同一目标（检测器自带 track id 应优先用检测器的）
2. `dh/dt` 为有限差分，帧间抖动会放大 → 内部 EMA 平滑 + `min_samples=3` 门槛，样本不足时 `valid=False`（**不拿两次差分当真**）
3. 目标**真实尺寸变化**（行人走近又蹲下）会破坏 h∝1/Z 前提 → 错估
4. 目标**横向掠过**（Z 不变）→ dh/dt≈0 → TTC=inf（正确行为，已验证）
5. 大偏航角时透视关系变化 → 只做粗估

## 4. ⚠️ 诚实声明（必须读）

### 4.1 TTC 依赖标定，未标定时输出全无效
单目相机（含游戏第三视角）**无法从单帧得到绝对距离**。公式 `Z = K / h_norm` 的 K 必须**实测标定**（`RangeCalibrator` 提供最小二乘拟合 + 残差报告）。
**未标定时 `estimate_ttc` 返回 `valid` 全 False、`ttc`/`distance` 全 inf——不返回假数字。**
（出处：TTC = 距离/相对速度，[Kilicarslan 2018](https://scholarworks.indianapolis.iu.edu/bitstream/1805/18821/1/Kilicarslan_2018_predict.pdf)）

### 4.2 confidence 的训练信号是**误差代理**，不是真值
`confidence_target_from_error` 用「控制量预测误差」间接监督：误差大→该低置信。
**根本局限：模型可以"自信地犯错"**（误差小但方向完全跑偏），误差代理无法惩罚这种。

2. 建议掺入闭环信号（离线回放的偏离车道中心量）做真值增强。
3. conf_loss 在总 loss 的系数未定，建议 0.1 起调。

### 4.3 TTC 无框速字段时的保守假设
检测框特征第 [9] 位（目标相对速度）游戏检测器多不提供（`use_box_speed_field=False` 默认）。此时假设**目标静止** → v_rel 取上界 → TTC 取**悲观值**。宁可早报警，不可漏报。

### 4.4 Lead 补充的两条输入现状（已按此设计）
1. **自车速度 `SpeedOCRReader.speedKmh` 未读到时是 -1**——调用方必须先判 `speedValid`（w3 已在 InferenceEngineV2 做硬门），**不要把 -1 直接喂进 TTC**（会被当成负速度）。`estimate_ttc` 的文档字符串已写明此约束。
2. **检测框只有归一化画面坐标，无物理距离（米）** → 绝对距离路径的 `estimate_ttc` 在当前现状下**只能靠标定或深度估计**。这正是 §3.6 的 `ApproachRateEstimator`（框增速路径，K 消掉、无标定）成为推荐路径的原因。
3. **accel 真值在包里但坐标系未标定**（scale÷10，单位推测 cm/s²，世界 vs 车体未实测）→ RiskHead 的 `speed` 输入暂用 **OCR 差分**（speed_kmh 差分 ÷ dt）或置 0；等 accel 标定后切真值。
4. **confidence 无"危险帧"标注** → 按**误差代理**实现（`confidence_target_from_error`）；Lead 建议的**变化代理**也已实现（`confidence_target_from_temporal_change`，无需真值，用控制量帧间变化）。两条代理互补，TODO 见 §4.2。
