1. 为什么 `controls.csv` 全零 —— 录制时 UI 在前台，游戏根本没收到按键，`currentCommand` 恒为 0；

> **结论：现存 129 帧不具备任何训练价值，不只是"少"，而是"错"。**

#### 3.4 重录成本 —— 拆解 + 哪些需实测

## 5 · 已部署模型"只会直走"的根因 —— 实测坐实

用户症状："只会直走、不会跟车道线、会开出车道线"。
本报告对**当前部署的 `game_assist_control/best_model.pt`** 做了直接推理探针：

```bash
$ .venv-yolo26/bin/python -c "
import sys; sys.path.insert(0,'.')
import torch, numpy as np, glob
from PIL import Image
from src.model import build_m9_mono
ck=torch.load('checkpoints/game_assist_control/best_model.pt', map_location='cpu', weights_only=False)
sd = ck.get('model_state_dict', ck) if isinstance(ck,dict) else ck
sd = {k.replace('_orig_mod.',''):v for k,v in sd.items()}
m=build_m9_mono(deploy=False); m.load_state_dict(sd, strict=False); m.eval()
fs=sorted(glob.glob('data/raw_clips/*/frames/*.jpg'))[:30]
ss=[]
for p in fs:
    a=np.asarray(Image.open(p).convert('RGB').resize((320,180)),dtype=np.float32)/255.0
    x=torch.from_numpy(a).permute(2,0,1).unsqueeze(0)
    with torch.no_grad(): s,_,_=m(x,torch.zeros(1,6))
    ss.append(s.item())
ss=np.array(ss)
print('样本 %d 帧' % len(ss))
print('steer: min=%.4f max=%.4f 极差=%.4f 标准差=%.5f' % (ss.min(),ss.max(),ss.max()-ss.min(),ss.std()))
print('tanh 满量程 [-1,1]，实际只用了 %.2f%% 的动态范围' % ((ss.max()-ss.min())/2*100))
"
样本 30 帧
steer: min=-0.0397 max=-0.0388 极差=0.0008 标准差=0.00024
tanh 满量程 [-1,1]，实际只用了 0.04% 的动态范围
```

**模型对 30 张不同画面的 steer 输出极差仅 0.0008 —— 输出已完全塌缩为常数。**
换真游戏帧也是同一结果：

```bash
  steer=-0.0397 throttle=0.9842 brake=0.0147  <= 000000.jpg      (UI 帧)
  steer=-0.0352 throttle=0.9854 brake=0.0130  <= 2_城市转向_01.jpg (真游戏帧)
  steer=-0.0416 throttle=0.9923 brake=0.0069  <= 4_写实风格_02.jpg (真游戏帧)
```

**喂 UI 帧和喂真游戏帧，输出差异 < 0.007 —— 模型对画面内容完全不敏感。**
配合其训练日志的异常低 loss（`checkpoints/game_assist_control/training_log.json`：`best_val_loss = 1.15e-05`，30 epoch），**该模型实质学到了"输出常数"，即"直走"。**

> 这**不是**"模型架构不行"，而是**"喂进去的标签全是 0，模型正确地学到了 0"**。
> **换模型架构不解决这个问题；换数据才解决。**

### 7.2 分步路线（含前置条件与工作量）

| 步 | 内容 | 前置条件 | 工作量 | 验收标准 |
