### 1.3.1 `AuroraDrive` include/exclude mechanism

- `sources: ["Sources/AuroraDrive", "Vendor/MetalGoose/Engine"]` — directory-level whitelist
  (`Package.swift:189-192`). Comment at `:188` states new `.swift` files are auto-included, i.e. adding a
  file under those two dirs requires no manifest edit.
- `exclude:` spans `Package.swift:93-187`; the body is lines `94-186` = **89 quoted entries + 4
  comment lines** (`sed -n '94,186p' Package.swift | grep -c '^ *"'` → 89;
  same range `grep -c '^ *//'` → 4; 89+4 = 93 lines). Rationale documented at `:88-92`:
  the list is **not** a source registry; it exists so `path: "."` does not treat the whole repo
  (stated as `.build/` with "59 万个条目") as unhandled input and emit warnings.
- Two files are kept in place but excluded from compilation (`:85-87`):
  `Shaders.metal` (runtime-loaded by path at `Vendor/MetalGoose/Engine/GooseEngine.swift:456`)
  and `Sources/AuroraDrive/Capture/CaptureEngine.swift.bak-20260930` (historical backup).
- Maintainer check for repo-root drift: `bash scripts/check-package-sources.sh` (`Package.swift:92`).
- `docs` appears twice in `exclude` (`Package.swift:144` and again at `:186` inside the 2026-10-18
  cleanup block). Duplicate entry; SwiftPM tolerates it; no build effect.

### 1.3.2 Language-mode block — hard constraint, do not delete

`Package.swift:201-203` sets `swiftSettings: [.swiftLanguageMode(.v5)]`.
The comment at `Package.swift:193-200` records the incident: with `swift-tools-version:6.2` and **no**
explicit language mode, the default is Swift 6 strict concurrency, which makes `static let shared`
across "56 个文件" emit `#MutableGlobalVariable` / "main actor-isolated default value" —
stated as "500+ error" in one build. The comment also warns that a prior scripted edit of the
`sources:` block had its regex trailing match swallow this block, so the comment must be preserved
alongside the code.

### 1.3.3 OpenCV static-link contract

`Vendor/OpenCVFlow` wraps `cv::DISOpticalFlow` in plain C because Swift cannot `import` C++
(`Package.swift:4-9`). Library selection rationale at `Package.swift:11-14`: same-batch measurement on
this machine at 640×640 — Apple VTOpticalFlow 10.28 ms, Vision 27.43 ms, OpenCV DIS 1.91 ms; the
"光流 ≤5ms" red line is why OpenCV was chosen.

- `openCVFlowRoot = "\(packageRoot)/Vendor/opencv"` (`Package.swift:29`); package root derived from
  `#filePath` using stdlib-only string ops because SwiftPM's manifest sandbox has **no Foundation**
  (`Package.swift:20-28`).
- Two hard-won linker rules (`Package.swift:16-18`): `-L` paths **must be absolute** (relative `-L`
  is resolved against the build-product dir and fails with "library not found"); static libs must be
  real files, not nested symlinks.
- `openCVStaticLibraries` = 11 entries (`Package.swift:35-47`): `opencv_core` (5.02 MB),
  `opencv_imgproc` (8.05 MB), `opencv_geometry` (2.65 MB), `opencv_flann` (0.79 MB),
  `opencv_video` (0.67 MB, contains DIS), `tegra_hal`, `kleidicv_hal`, `kleidicv`,
  `kleidicv_thread`, `ittnotify`, `zlib`.
- Three dependency groups are required or you get cascades of undefined symbols
  (`Package.swift:31-34`): ① third-party HAL → else `carotene_o4t::*` undefined;
  ② `Accelerate` framework (LAPACK/BLAS) → else `_cblas_sgemm$NEWLAPACK$ILP64` undefined;
  ③ libc++ (auto-provided by the C++ target).
- `AuroraDrive` linker settings: `NetworkExtension`, `Network`, `pcap` (`Package.swift:204-208`).
