## 3. 步骤三：重点分析 chunk5 / chunk6（含 MoE）

### 结论：chunk5/6 全派 ANE，零 GPU，无需拆分

背景担心 chunk5/6（828节点含 MoE）会 preferred=GPU。**实测结果相反**：

- chunk5：347 算子，**225 个 preferred=ANE**（64.8%），122 个 const（nil），**GPU=0**。
- chunk6：347 算子，**225 个 preferred=ANE**（64.8%），122 个 const（nil），**GPU=0**。
- 两者的 **ANE cost 占比 = 100%**——所有真实计算算子全部落在 ANE 上。
- "非 ANE 算子"列表里**只有 `const → nil`**（权重常量），**没有任何一个计算算子落到 GPU 或 CPU**。

**为何与预期不同**：背景说的"828节点"是 PyTorch 层级节点数；编译为 MIL 后经图优化折叠为 347 个算子（含 122 个 const 权重常量 + 225 个计算算子）。225 个计算算子全部 preferred=ANE，未触发 >1000 节点 preferred=GPU 的阈值。

**延迟**：chunk5/6 各 0.69ms（min-of-60），单步约 0.17ms，完全可接受。

### 是否需要进一步拆分 MoE？

**不需要。** 当前 chunk5/6 已经是纯 ANE 派发，零 GPU。进一步拆分（如 MoE 步骤拆成 2 步一块）不会改善派发——已经是最优状态，只会增加模型数量和跨模型调度开销。

## 5. 总体结论

| 维度 | 结论 |
|------|------|
| **GPU 派发** | **8 个模型全部 GPU preferred = 0**，符合用户铁律（推理不碰 GPU） |
| **ANE 利用** | chunk5/6（含 MoE）**100% ANE 派发**；其余模型 CPU 派发（因算子小，CPU 反而更快） |
| **MoE 拆分需求** | **无需拆分**——chunk5/6 已是纯 ANE，0 GPU |
| **延迟** | 全部 sub-ms：chunk1-4 ~0.05ms，head ~0.07ms，tf ~0.12ms，chunk5/6 ~0.69ms |
| **优化方向** | 当前状态已满足铁律，无进一步动作必要 |

### 给 Lead 的建议

1. **8 个模型可直接用于推理管线**，GPU 零占用。
2. chunk1-4 + head + tf 走 CPU（这些是小算子 linear，CPU 0.05-0.12ms 已最优）；chunk5/6 走 ANE（MoE 重计算，ANE 0.69ms）。
3. 如未来要把 chunk1-4/head/tf 也推上 ANE，需研究 `specializationStrategy` 或算子融合——但**当前不推荐**，CPU 路径已足够快，强推 ANE 反而增加调度开销。
4. enc 模型（`models/split24/m9_v2_enc.mlmodelc`）未在本批检查范围内，建议 Lead 单独确认其派发。
