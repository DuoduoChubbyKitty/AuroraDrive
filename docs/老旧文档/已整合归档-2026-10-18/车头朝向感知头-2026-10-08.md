## 0. 摘要（TL;DR）

用户要"让模型自己感知车头朝向，而不是靠抓包喂"。本模块实现 **`HeadingHead`**：从视觉特征
（可叠加视角朝向）预测车头朝向，**训练时可监督、推理时可诊断**。

**核心设计：视角-车头差分解耦**

```
Δheading = carHeading − cameraHeading     ← 模型从画面学这个"小偏移"
carHeading = cameraHeading + Δheading     ← 推理时合成
```

这就是用户说的"两个小表：视角 + 车头，模型推导差"——**不是查表**，而是把
"绝对朝向"分解成"已知视角 + 待学偏移"，让网络只学小量 Δ（第三视角现实 |Δ| < 30°），
远比直接回归 ±π 的绝对角容易。

**自检 21/21 全绿**（含循环安全三组对照、compass 口径、Δ 相减、fail-safe、NaN 防护）。
**与真实 `model_v2.ImageEncoder` 对接验证通过**（256 维特征，shape 正确）。

## 1. 接口（Lead 集成用）

```python
from heading_head import HeadingHead

head = HeadingHead(in_dim=256, hidden=128, heading_unit="auto")

# 前向

# 训练（一步到位，内部处理 Δ 的 target）

# 诊断（同时拿到 Δ）
car, delta, delta_sin_cos = head.forward_parts(visual_feat, camera_heading)
```

| 参数 | shape | 说明 |
|---|---|---|
| `visual_feat` | `[B, 256]` | `model_v2.ImageEncoder` 输出（`IMG_FEAT_DIM=256`） |

| 返回 | `[B]` | 车头朝向，rad，wrap 到 `[-π, π]` |

## 2. 关键设计点

### 2.1 角度循环性 → sin/cos 双通道

**为什么不能用裸角度回归**：+179° 与 -179° 是"几乎同一方向"（短弧差 2°），
但裸角度 L1 会算出 `|179-(-179)| = 358°` 的巨大误差 → 训练被这个假惩罚主导。

本头回归 `(sinΔ, cosΔ)`，用 `atan2` 还原。自检里的三组对照**实测**钉死了这个性质：

| 对照 | (sin,cos) L1 损失 | 说明 |
|---|---|---|
| +179° vs -179°（跨边界，短弧差 2°） | **0.0349** | 如实反映"很近" |
| 1° vs 3°（不跨边界，同样差 2°） | **0.0361** | **与跨边界同量级 ⇒ 循环安全** |
| 0° vs 90°（真远角） | **2.0000** | 显著更大 |
| （反证）裸角度 L1 对 179/-179 | 358° | 荒谬 |

### 2.2 双分支独立参数（Δ 分支 + 绝对分支）

- **Δ 分支**：学"车相对相机的偏移"（小量，|Δ|<30°）
- **绝对分支**：fail-safe，学"全范围车头朝向"（`[-π,π]`）

**为什么独立**：Δ 分布窄、量级小；绝对角分布宽、量级大。共享输出头会让两组梯度
互相拉扯（小量学习被大量淹没）。独立后各自只在对应帧上被监督，各自专注。

### 2.3 fail-safe

`camera_heading=None`（抓包断线/未接入）→ 纯视觉绝对预测，**不崩、不降级为零**。
输出 shape 与有 camera 时完全一致，便于导出静态图。

### 2.4 数值防护

- 输出层 **fan_in 初始化**（与 `model_v2.FusionHead` 同因）：避免初始 `(sin,cos)` 幅值
  过大导致 loss landscape 陡峭（旧 `model.py` 的 tanh 饱和冻结坑，同源预防）
- `NaN → 0`（`nan_to_num`）：避免 NaN 传播进网络
- `[B,1]` 形状自动 squeeze
- 空 batch（`[0,C]`）前向不崩
- 维度不匹配**显式抛错**（不静默算错）

## 3. ⚠️ 单位口径（本项目实际会踩的坑）

本模块统一内部到 **rad `[-π,π]`**，支持四种输入口径：

| `heading_unit` | 输入语义 | 用在哪 |
|---|---|---|
| `"rad"` | 数学弧度 | Lead 接口约定 |
| `"deg"` | 数学角度 | 通用 |
| `"compass"` | **罗盘度**（0=正北、顺时针，`[0,360)`） | **本项目实际数据源** |
| `"auto"`（默认） | `max|h| > 2π+ε` 判为度 | 兼容 |

### 为什么 compass 是本项目的实际口径

- `NetworkLocator.cameraHeading`（`NetworkLocator.swift:310,560-562`）：
  `(atan2(east, north) * 180/π + 360) % 360` → **compass**
- 抓包真值 `carHeading`（Lead 情报：`CoordinateCapture.swift:215-229`，
  `rotation.yaw` → compass_heading 0-360）→ **同一 compass 口径**

**⟹ 两者同口径 ⇒ `Δ = car − camera` 可直接相减**，无需坐标系变换。
这是本设计成立的关键前提（若一个数学系一个罗盘系，必须先统一）。自检 ⑤c 实测：
350°→10° 得 +20°、10°→350° 得 -20°，符合预期。

### ⚠️ auto 的边界

auto **判不出 compass vs deg**（两者都是 `[0,360)` 度，数值范围相同）——
它只识别"这是度不是弧度"。**罗盘语义必须调用方显式声明**（或依赖 auto 的
compass 默认，因为本项目两个数据源都是 compass）。

## 4. 监督信号的演进路径

**现状**：训练数据里**没有 carHeading 真值**（抓包侧正在加字段，尚未进数据管线）。

| 阶段 | 监督方式 | 怎么做 |
|---|---|---|
| ① 现在 | **自监督/弱监督** | 只训 Δ 分支。弱标签：车在画面偏左 → Δ 为负。⚠️ 拿不到可信弱标签**宁可不训**（Δ=0 即"车头≈视角"也是合理先验） |
| ② 过渡 | **真值监督（主路径）** | `carHeading` 进管线后：`head.loss(feat, car_rad, cam_rad)`。有 camera 的帧训 Δ 分支，无 camera 的帧训绝对分支 |
| ③ 长期 | **辅助头联合训练** | `total = main + λ·heading_loss`，λ 建议 0.1~0.3。推理只取 car 做诊断，除非验证对 steer 有正贡献 |

**验收建议（阶段②）**：`wrap_to_pi(pred-gt)` 的 RMD，直行段 < 5°、转弯段 < 15°。
若误差接近随机（~90°）⇒ Δ 分支没学到东西。

### ⚠️ 一个必须注意的陷阱

`cameraHeading` 是**运动方向估计**（位移 atan2），`carHeading` 是**角色朝向**
（rotation.yaw）。**倒车/漂移时两者符号相反或大幅背离** → Δ 异常大。
训练前应**过滤 |Δ| > 120° 的帧**（视为标签异常），否则会把"倒车"当噪声学进去。

## 7. 自检中修掉的两个自身缺陷（留痕）

写自检时踩到并修正，**记录以便后人不再踩**：

1. **`torch.radians` 不存在** —— 是 `math.radians`（torch 无此函数）。
2. **用 `allclose` 比较角度是错的** —— `wrap_to_pi(π) = -π`，两者是**同一个角**
   但数值差 `2π`，`allclose` 会把正确行为误判为失败。**比较角度必须用
   `wrap_to_pi(a-b)` 的绝对值**。这条已写进自检注释。
