## 2. 离线补算可行吗（任务② · 读实现 + 实测）

### 2.1 两个 backfill 函数

| 函数 | 位置 | 模型 | 输入 | 输出 |
|---|---|---|---|---|
| `backfill_lane_masks` | `dataset_v2.py:1046` | `models/yolopx/yolopx_epoch195.pth`（132MB，✅ 文件真实存在） | `frames/*.jpg` + yolopx `ll` 头 | `lane_mask/{fno:06d}.png` uint8 0/255（160×160 grid） |
| `backfill_detections` | `dataset_v2.py:1121` | 同上 + `det` 头 + NMS | 同上 | `detections/{fno:06d}.json` `{boxes:[[x1,y1,x2,y2]像素], scores, classes, w, h}` |

关键设计：
- **`da`（可行驶区域）头被显式丢弃**（`_yolopx_forward` :997-998 `out[1]` 直接忽略）—— 与 model_v2「不接受 drivable_mask」一致。
- **车道线几何口径已修复**：通过 `logits_to_grid()` 逐行复刻 Swift `YolopxEngine.extractMask()`（ch1>ch0 → 4×4 多数表决 → 160×160），与运行时 MaskGrid **逐位同口径**（注释称"Swift 真跑对拍：25600 像素 0 差异"）。修复前存 640 全分辨率 argmax 再 resize，会错位最多 35 格。
- **检测框后处理**：obj×cls 阈值过滤 → 纯 numpy NMS → 退化框过滤（零面积丢）→ letterbox 坐标→原图坐标。
- 两者都声明是**伪标签**（yolopx 预测非人工标注），建议训练时给较低权重。

### 2.2 yolopx 模型加载方式

`_load_yolopx()`（`dataset_v2.py:973`）：
1. `root/tools/yolopx/`（仓库内 yolopx 源码）
2. `from export_yolopx_coreml import build` → `build(imgsz)[0]` 返回模型

### 2.3 ⚠️ 真问题①：补算在 ayolom 虚拟环境跑不起来

`tools/ayolom/.venv`（我之前几轮一直用的环境）跑 backfill **直接报错**：
```
ModuleNotFoundError: No module named 'prefetch_generator'
  (tools/yolopx/lib/utils/utils.py:12 imports it)
```
**能跑的环境是 `.venv-yolo26`**（有 `prefetch_generator`）。t1 / 训练线需注意：**补算脚本必须用 `.venv-yolo26`，不能用 ayolom 的 venv**。

### 2.4 ⚠️ 真问题②：实测 yolopx 对现有 129 帧预测车道线全为空

实测（`.venv-yolo26`，5 帧）：
```
stats: {'clips': 1, 'frames': 5, 'skipped': 0, 'empty_frames': 5}
```
**5/5 帧车道线掩码全 0**（PNG 文件 104 字节，min=0 max=0）。原因推测：这 129 帧是**桌面截图测试录制**（前几轮已确认 FPV 视角 + steer 全 0），不是游戏画面 → yolopx 当然识别不到车道线。

**含义**：现有 129 帧测试录制**连补算都补不出车道线**，无法用于训练车道分支。真实游戏录制帧（第三视角、有车道线画面）补算效果待验。

### 2.5 时间开销估算（实测，非推测）

| 场景 | 单帧 | 129 帧 | 1,000 帧 | 4,000 帧 | 10,000 帧 |
|---|---|---|---|---|---|
| 稳态 | 9.4s | 20 分钟 | 2.6 小时 | 10.4 小时 | 26 小时 |
| 首次含预热 | 15.6s | 34 分钟 | 4.3 小时 | 17.3 小时 | 43 小时 |

**成本极高**：4,000 帧（≈30 分钟录制）要补算 10~17 小时；10,000 帧要 26~43 小时。两路（lane + det）各跑一遍翻倍。**建议**：补算只跑一次、结果落盘缓存（已有 skip 机制），不要每次训练都重跑。

## 4. 补算失败时模型还能训吗（任务④ · 降级处理）

`dataset_v2.py` 的降级策略（头部 :38-46 + `__getitem__` :823-845）：

| 缺失字段 | 降级 | mask 标记 | strict=True |
|---|---|---|---|
| lane_mask | 全 0 掩码 | `lane_present=0.0` | **抛 RuntimeError** |
| detections | 全 0 张量 | `det_mask` 全 0 | **抛 RuntimeError** |

`strict` 默认 **False**（:701）→ 缺字段不报错，**用零值 + mask=0 让模型通过 mask 忽略该输入**。

**效果评估**：
- **strict=False**（默认）：能训，不会崩。但若**大面积缺车道线**（如现有 129 帧全空），等于车道分支**完全没监督信号** → 模型学不到"车道线在哪" → 这正是用户说"不会跟车道线"的一个嫌疑根因（与 T5 实验设计的 §1.2 弯道子集 MAE 互相印证）。
- **strict=True**：缺字段直接抛 → 适合"严格数据集只收有车道线的帧"。但现有 129 帧全空 → `strict=True` 会在第一个 clip 就崩（`n_lane=0`）。

**结论**：降级机制本身健全（不崩、有 mask 标记），但**降级不等于有效训练**——空车道线 = 车道分支没信号。真实录制帧必须确保 yolopx 能识别出车道线（第三视角、有标线的游戏画面）。
