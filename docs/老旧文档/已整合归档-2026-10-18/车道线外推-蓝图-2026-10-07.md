## 0. 一句话结论

车道线 `MaskGrid` 与检测框 `Detection` 走的是**两条不同的坐标系**，且光流只是**全局三标量摘要**（非稠密场）。要把「检测框外推」的套路搬到车道线上，正确落点是**新建一个独立的 `LaneExtrapolator`**，复用 `EgoMotionModel.estimate` 已算好的 `forwardRate`/`lateralRate`，对 `MaskGrid` 做**全局平移 + 可选径向缩放**，插入点选在 `updateMotionPipeline` 之后、`LaneFallback.evaluate` 之前。**不要扩展 `MotionPredictor`**——它是目标级 α-β 跟踪器，语义与"整幅栅格平移"完全不同。

## 1. 现状全链路（谁产、谁吃、刷多快）

### 1.1 车道线：`MaskGrid`（160×160 二值栅格）

**定义** `Sources/AuroraDrive/Inference/YolopxEngine.swift:45-83`：

```swift
struct MaskGrid: Equatable {
    let width: Int        // 160
    let height: Int       // 160
    let cells: [UInt8]    // 行优先，0=背景，1=前景
    func at(_ x: Int, _ y: Int) -> Bool { ... }  // :67，越界返回 false（fail-open 语义）
    var positiveCount: Int { ... }               // :76 前景格总数
    static let empty = MaskGrid(width: 0, height: 0, cells: [])  // :82
}
```

- **格子尺寸**：`YolopxEngine.swift:263` `nonisolated static let maskGridSize = 160`；`inputSize = 640`（`:260`）。
- **坐标系**：`:40` 注释明确 —— **letterbox 640 坐标系**，按 `gridStride = 640/160 = 4` 的 4×4 多数表决下采样而来。
- **可平移吗**：**没有**任何平移/变换 API，是纯数据 struct。平移要靠新建的变换函数**生成新 grid**。
- **mask 如何生成**：`extractMask(...)`（`:1265-1346`）对 `ll` 输出 `[1,2,640,640]` 逐像素 argmax（ch1>ch0 判前景），再 4×4 块多数表决（`positive*2 >= stride*stride`），得到 160×160。

### 1.2 车道线刷新频率（问题①的答案）

**被 P1 降频直接拖累**，实际约 8~15Hz，且带 1~2 帧 EMA 滞后。

推理提交门槛（`AuroraDriveApp.swift`）：
- `:6574` `adaptiveFrameCounter &+= 1`
- `:6575` `let decimationOn = adaptiveFrameCounter % Self.detectDecimate == 0`
- `:5385` `detectDecimate: UInt64 = 2`（30Hz tick → 15Hz 提交）
- `:6797-6805`：`if decimationOn { ... yolopxEngine.infer(image: cg) }` —— **yolopx 的 `ll` 仅在 decimationOn 帧才提交推理**。

再叠加两道闸：
- `YolopxEngine.swift:906` `guard !isInferencing else { return }`（防重叠：上一帧没跑完就整帧跳过）
- 异步推理耗时实测约 60ms（`MotionPredictor.swift:6` 记载），`finish` 才回主线程落 `laneMask = smoothedLL`（`YolopxEngine.swift:1070`）。

EMA 平滑又加滞后：`maskEMA = 0.35` / `maskThreshold = 0.5`（`:513`/`:516`），`smoothMask` 跨帧持久（`:1364-1380`）。

> 结论：`laneMask` 名义 15Hz 提交上限，工程实际 ~8–15Hz，且被 EMA 与防重叠门进一步压低/推后。**外推要补的正是这两帧之间的空窗**。

### 1.3 车道线消费点：`LaneFallback.evaluate`

`Sources/AuroraDrive/Inference/LaneFallback.swift:145`：

- 返回 `LaneAdvice`（`steer`/`brake`/`throttleCap?`/`confidence`/`reason`，`:29-54`），`nil` = 无可信建议（fail-open）。

- 唯一调用点：`AuroraDriveApp.swift:7152-7155`，位于 `Self.laneKeepTiers.contains(decided)`（默认 `rule,yolo`，`:7123`）门内。

### 1.5 光流：`OpticalFlowReading`（全局摘要，非稠密场）

`Sources/AuroraDrive/Inference/OpticalFlowBridge.swift:45-65`：

```swift
struct OpticalFlowReading: Equatable {
    let dx: Double          // 全局中位水平流（像素），正=内容右移
    let dy: Double          // 全局中位垂直流（像素），正=内容下移
    let divergence: Double  // 径向外向散度（像素），>0 前进

```

- **量纲（问题②）**：`dx`/`dy`/`divergence` 都是 **640 图像素**，**不是归一化**（`:47/50/55` 注释与 `EgoMotionModel.swift:228` 印证）。
- `static let workingSize = 640`（`:91`），与 YOLOPX/Yolo26s 的 letterbox 输入同坐标系（`:85-86` 注释专门强调，否则位移无法直接作用到框和掩码上）。
- **无稠密场**：`Vendor/OpenCVFlow/README.md` 明确不回传稠密流场。因此**无法按格子做逐点外推，只能全局平移/缩放**。

### 1.6 检测框外推：`MotionPredictor` 完整链路（问题④）

`Sources/AuroraDrive/Inference/MotionPredictor.swift`：

- 输入：

- 喂入方 `AuroraDriveApp.updateMotionPipeline(dt:)`（`:6397-6432`）：
  - `:6404-6411` 取真值（`yolopxEngine.detections` 非空优先，否则 `yoloEngine.detections`）→ `ingest`。

- 光流喂点 `runOpticalFlow(on:)`（`:6353-6368`）：每帧（**不受 decimationOn 影响**，`:6629/6634` 注释）转灰度→`opticalFlow.compute`→`motionPredictor.updateEgoMotion(reading)`（`:6366`）。
- 光流消费链（已在 `:6673-6680` 注释纠偏）：`currentEgoFlow → applyObservation(:371) → EgoMotionModel.verdict → egoVerdicts → predict() 的 egoBlocked 否决（:448-452）`。
- 调用顺序约束：`updateMotionPipeline` 在 tick 的 `:6813` 处每 tick 一次，`dt = 1/30`（`:6765`）。

## 2. 三大坐标系与换算（问题②、问题③核心）

| 对象 | 坐标系 | 关键换算 |
|---|---|---|
| `MaskGrid` | **letterbox 640** 网格，160×160 | 格子 `(gx,gy)` ↔ 640 像素 `(gx*4, gy*4)`；grid 坐标 = 640px / 4 |
| `Detection` | **原帧归一化 [0,1]**（中心+宽高） | 640px ↔ 原帧归一化：经 `LetterboxMetrics.toNormalized`（`YolopxEngine.swift:115`） |
| `OpticalFlowReading.dx/dy` | **640 像素** | 归一化 = dx/640；grid 位移 = dx/4 |

### 2.1 ⚠️ 关键坑：Detection 与 MaskGrid 基准不同

- `MaskGrid` 是 **640 letterbox 内容**的采样，**灰边也占网格坐标**（`extractMask` 只把灰边排除在 `validTotal` 之外，格子索引仍含灰边占位）。
- `Detection` 是 **原帧归一化**（`parseDetections:1231` 用 `metrics.toNormalized` 把 640 内容像素反变换回原帧比例）。

**结论：二者不能直接 `detection.x*160` 对号入座。** 要互转必须持有 `LetterboxMetrics`：
- 原帧归一化 → 640 内容像素：`px = metrics.padX + x_norm * ratio * srcW`（`toNormalized` 的逆，见 `:117`）。
- 640 内容像素 → grid 格子：`gx = round(px / 4)`。

> 但**车道线外推本身不需要 Detection**。这条坑主要是提醒"检测框推车道线"的标题容易让人误以为要把框坐标当输入；实际上车道线外推只需要 `MaskGrid + OpticalFlowReading + dt`，**不依赖 Detection**。Detection 与 MaskGrid 的唯一交集是"共享同一套 letterbox 几何"，要统一基准时经 `metrics`。

### 2.2 光流 dx/dy → MaskGrid 平移量（问题②的答案）

- `dx`、`dy` 是 640 像素。**平移 MaskGrid 需要：`gridShift = pxShift / 4`**（因为 1 格 = 4px）。
  - 横向：`shiftGx = dx / 4`（格）
  - 纵向：`shiftGy = dy / 4`（格）
- 更规范（走归一化，抗分辨率变化）：先 `dxNorm = dx / 640`，再 `shiftGx = dxNorm * 160 = dx / 4`，两边等价。
- 若用 `EgoMotionModel.estimate` 拿到 `lateralRate`（归一化/秒），则`shiftGx = lateralRate * dt * 160`。

**符号约定（需真机验证方向）**：
- `dx > 0` = 画面内容向右移 → mask 内容应向右平移（`new[gx+shift] = old[gx]`，`shift = dx/4` 取正）。
- `dy > 0` = 画面内容向下移（`:50` 注释，自车前进时向下扩散）→ mask 内容应向**行号增大**方向平移（grid 行 0 = 图顶，`YolopxEngine.swift:137` 注释）。

> ⚠️ 符号方向虽有注释，但"该平移 mask 还是反向平移"最终以**真机实跑**为准；蓝图给出的是依据注释的推导，实现代理务必加开关做 A/B 验证（未验证项）。

### 2.3 前向（divergence）→ 径向缩放（可选 v2）

- `divergence > 0` = 前进 = 路从画面中心（消失点 `centerX/Y = 320`，`EgoMotionModel.swift:173/176`）向外扩。
- 对 grid 做径向重采样：`forwardRate = divergence / (640/2)`（`EgoMotionModel.swift:247-248`），格点相对中心 `(gx-80, gy-80)` 乘 `(1+forwardRate)` 后取址。
- **v1 建议只做平移**（横向 `dx` + 纵向 `dy`），径向作为 v2 可选，因为车道线集中在画面下半部、径向模型在该区域误差放大（远小近大），且 `divergence` 是 3×3 分块平均的粗值。

## 3. 落点建议（问题⑤的答案）

### 3.1 新建 `LaneExtrapolator` 类（推荐，不要扩展 MotionPredictor）

**理由**：
1. `MotionPredictor` 是**目标级 α-β 跟踪器**（`MotionPredictor.swift:4-34` 头注释），状态是 `[Int: Track]`（`:158`），输出 `TrackedTarget`；车道线外推是**单张栅格的整幅变换**，无目标概念、无 id、无关联匹配，硬塞进去会污染其 fail-open 语义与帧驱动模型。
2. 车道线外推需要**新增状态**（上一帧 mask、EMA 或自适应门），与 `MotionPredictor` 完全无关。
3. 独立类符合项目"纯函数式 + 单测"纪律（`LaneFallback.swift:19`、`RuleController.swift:73` 同风格），且可单独 `reset()`。

### 3.2 建议接口（实现代理可直接照抄）

```swift
// 新文件：Sources/AuroraDrive/Inference/LaneExtrapolator.swift
import Foundation

/// 车道线栅格外推器：把 15Hz 的 laneMask 用光流补到 ~30Hz。
/// 复用 EgoMotionModel.estimate 的换算；只做整幅平移（v1），径向缩放 v2 可选。
final class LaneExtrapolator {

    // 可调参数
    /// 单帧外推位移上限（格）。超过则 clamp，防光流发散把 mask 甩飞。
    /// 对应 MotionPredictor.maxPredictStep(0.15) 的"视野 15%"：0.15*160 = 24 格。
    var maxShiftGrid: Int = 24

    // 内部状态
    private var lastLaneMask: MaskGrid = .empty
    private var lastEgo: EgoMotionEstimate? = nil
    private let egoModel = EgoMotionModel()   // 复用，无状态纯函数

    /// 输入：最新真值 laneMask + 本帧光流读数。
    /// 在"没有新真值掩码的帧"持续用上一帧 mask 外推。
    func update(laneMask: MaskGrid?, flow: OpticalFlowReading?, dt: Double) -> MaskGrid {
        // 1) 有新真值 → 重置基线（外推只在真值断供时介入，与 MotionPredictor 语义一致）
        if let m = laneMask, m.width == YolopxEngine.maskGridSize {
            lastLaneMask = m
        }
        // 2) 光流解读（复用现成换算；flow 为 nil 或 isUsable==false → 直接吐基线，fail-open）
        guard let f = flow, let ego = egoModel.estimate(from: f, dt: dt), ego.isUsable else {
            return lastLaneMask
        }
        // 3) 位移（格）：lateralRate 是归一化/秒
        let dxGrid = ego.lateralRate * dt * Double(YolopxEngine.maskGridSize)
        //   纵向：dy 是 640px，直接 /4；或统一走归一化 dyNorm = f.dy/640
        let dyGrid = f.dy / 4.0
        let shiftX = Int(dxGrid.rounded())
        let shiftY = Int(dyGrid.rounded())
        // 4) clamp + 平移（越界格＝背景，保持 160×160 尺寸不变，满足 LaneFallback 门②）
        return Self.shift(lastLaneMask, dx: shiftX, dy: shiftY, maxShift: maxShiftGrid)
    }

    /// 纯函数平移：返回新 grid，越界格填 0（背景）。
    /// 注意：mask 内容右移 = 源格子 (x,y) 写到 (x+dx, y+dy)。
    nonisolated static func shift(_ mask: MaskGrid, dx: Int, dy: Int, maxShift: Int) -> MaskGrid {
        let cx = max(-maxShift, min(maxShift, dx))
        let cy = max(-maxShift, min(maxShift, dy))
        var cells = [UInt8](repeating: 0, count: mask.width * mask.height)
        for y in 0..<mask.height {
            for x in 0..<mask.width where mask.at(x, y) {
                let nx = x + cx, ny = y + cy
                if nx >= 0, nx < mask.width, ny >= 0, ny < mask.height {
                    cells[ny * mask.width + nx] = 1
                }
            }
        }
        return MaskGrid(width: mask.width, height: mask.height, cells: cells)
    }

    func reset() {
        lastLaneMask = .empty
        lastEgo = nil
    }
}
```

### 3.3 接线点（插入位置）

## 5. 给实现代理的硬约束清单

1. **外推出的 mask 必须仍是 160×160**，否则 `LaneFallback` 门②（`LaneFallback.swift:169-181`）直接拒掉，外推等于白做。
2. **fail-open**：光流为 nil / `EgoMotionEstimate.isUsable == false` / dt 异常时，直接返回原 `laneMask`（基线），**绝不编造位移**（与 `MotionPredictor` 纪律一致，`MotionPredictor.swift:28-29`）。
3. **不读 `Detection`**：车道线外推输入只有 `MaskGrid + OpticalFlowReading + dt`。Detection 只在"需要统一两套坐标系"时才涉及，且必须经 `LetterboxMetrics`。
4. **单帧位移 clamp**：`maxShiftGrid`（建议 24 格 = 视野 15%）防光流发散（对照 `MotionPredictor.maxPredictStep = 0.15`，`:137`）。
5. **帧驱动语义**：`update` 每 tick 一次，新真值 mask 到达时重置基线；真值断供帧用上次 mask 继续外推——与 `ingest`/`predict` 的"真值校正、帧间外推"分工一致（`MotionPredictor.swift:401-415`）。
6. **reset 时机**：停止驾驶/切感知档时清空，防停车前 mask 当新基线（对齐 `MotionPredictor.reset`）。
7. **开关可回退**：建议加 `AURORA_LANE_EXTRAPOLATE=off` 环境开关，off 时 `update` 直接返回原 mask，行为与现状逐帧一致（项目"A17 迁移"里 `AuroraFlags` 同一套约定，`EgoMotionModel.swift:203-221`）。
