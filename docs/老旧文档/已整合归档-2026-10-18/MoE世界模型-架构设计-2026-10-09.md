# MoE 世界模型 · 架构设计文档 · 2026-10-09

> Lead 撰写。用户核心诉求：MoE 世界模型，3 专家（高速/低速/赛道专用），赛道专家手动切换。
> 总体积 ≤3MB（赛道专家 0.5MB，高速+低速各 1.25MB）。联合训练，不碰 GPU。

---

## 0. 一句话目标

> 在现有 M2Model 基础上加一个轻量 MoE 世界模型头：
> 输入当前 fused[512] + action[3]（steer/throttle/brake）+ 全部感知输入
> → 预测下一帧 fused[512]（自监督，不用额外标签）
> 3 个专家：高速(>100km/h)、低速(<100km/h)、赛道专用（手动切换）
> 总体积 INT8 ≤3MB

---

## 1. 用户需求拆解

### 专家分工
| 专家 | 触发条件 | 场景 | 体积(INT8) |
|---|---|---|---|
| **高速专家** | speed > 100km/h | 油门二值控制（全油门 or 无油门），高速过弯 | 1.25MB |
| **低速专家** | speed < 100km/h | 精细油门控制，跟车避障，城市驾驶 | 1.25MB |
| **赛道专家** | 玩家手动按钮切换 | 赛道专用，不走寻常路（抄近道） | 0.5MB |

### 路由方式
- 高速/低速：**速度路由器**自动切换（soft routing，基于 vehicle_state[0] speed）
- 赛道：**玩家手动按钮**，不参与自动路由（独占模式，选中时只跑赛道专家）

### 输入端（用户明确要求全部接入）
```
世界模型输入：
  ├─ fused[512]           ← 主模型的时序融合特征（已有）
  ├─ action[3]            ← 当前动作 steer/throttle/brake（训练时从录制数据取，推理时从主模型输出取）
  ├─ vehicle_state[8]     ← 速度、加速度、角度、角速度、曲率、横偏、方向角、reserved
  ├─ det_feat[128]        ← 检测框特征（行人/车辆/标志/障碍物）
  └─ det_mask[20]         ← 有效检测框 mask
```

### 输出
```
世界模型输出：
  └─ predicted_next_fused[512]  ← 预测的下一帧 fused 特征
```

### 体积预算
| 组件 | 参数量 | INT8 大小 | 说明 |
|---|---|---|---|
| 速度路由器 | ~1K | <0.01MB | Linear(523→2) → softmax |
| 高速专家 | ~640K | ~0.625MB | 含 GRU 隐状态预测 |
| 低速专家 | ~640K | ~0.625MB | 含 GRU 隐状态预测 |
| 赛道专家 | ~256K | ~0.25MB | 更小，只处理赛道场景 |
| 共享输入投影 | ~270K | ~0.27MB | (512+3+128+20)→256 |
| 共享输出投影 | ~130K | ~0.13MB | 256→512 |
| **总计** | ~1.94M | **~1.9MB** | ≤3MB ✅ |

## 2. 架构设计

```
                          ┌──────────────────────────────┐
                          │     主模型（现有，不改）         │
                          │  enc → tf → fused[512]         │
                          │  refiner → steer/thr/brake     │
                          └──────┬─────────────────────────┘
                                 │ fused + action + det_feat + det_mask + state
                                 ▼
                    ┌────────────────────────────────┐
                    │     世界模型输入投影              │
                    │  cat(fused, action, det_feat,    │
                    │       det_mask, speed_feat)      │
                    │  → Linear → wm_input[256]        │
                    └──────────┬─────────────────────┘
                               │
                    ┌──────────▼─────────────────────┐
                    │         路由器                   │
                    │  自动模式：speed → softmax        │
                    │    → [高速权重, 低速权重]         │
                    │  手动模式（赛道按钮ON）：          │
                    │    → [0, 0, 1]（只选赛道）        │
                    └──┬────────┬──────────┬──────────┘
                       │        │          │
              ┌────────▼──┐ ┌───▼──────┐ ┌─▼──────────┐
              │ 高速专家   │ │ 低速专家  │ │ 赛道专家    │
              │ GRU+MLP   │ │ GRU+MLP  │ │ MLP(轻量)  │
              │ → wm_h[256]│ │→wm_h[256]│ │→wm_h[256]  │
              └────────┬──┘ └───┬──────┘ └─┬──────────┘
                       │        │          │
                    ┌──▼────────▼──────────▼──────────┐
                    │  soft routing 加权融合            │
                    │  wm_fused = Σ(w_i × expert_i)    │
                    └──────────┬─────────────────────┘
                               │
                    ┌──────────▼─────────────────────┐
                    │     输出投影                     │
                    │  wm_h[256] → Linear → pred[512] │
                    └────────────────────────────────┘
                               │
                    predicted_next_fused[512]
```

### 关键设计决策

1. **为什么用 fused 而不是原始图像做预测目标**
   - 预测原始图像需要扩散模型/GAN（太大太慢）
   - 预测 fused 特征只需一个 MLP+GRU（轻量，≤3MB）
   - fused 已经包含图像+车道线+检测框+状态的全部信息

2. **为什么高速/低速分开**
   - 用户痛点：高速时油门二值（全油门 or 无油门），低速时需要精细控制
   - 单专家无法同时学好两种截然不同的动力学
   - 高速专家学「油门脉冲策略 + 大曲率预判」
   - 低速专家学「精细油门 + 跟车距离控制」

3. **为什么赛道专家更小（0.5MB）**
   - 赛道场景变化少（没有行人、红绿灯）
   - 只需学赛道动力学（弯道+坡道+抄近道）
   - 用户手动切换 → 不需要路由器开销

4. **为什么用 _StrictGRUStep（手展开 GRU）**
   - 和 refiner 一样：coremltools 把 nn.GRU 编译成 while_loop（CPU-only，ANE 阻断）
   - 手展开成 Linear+sigmoid+tanh+mul，消除 while_loop

## 3. 训练方案（联合训练）

### 数据需求
用户录制的连续视频天然提供：
- 当前帧 → fused（主模型编码）
- 当前动作 → action（方向盘/油门/刹车，从录制数据取）
- 下一帧 → next_fused（主模型编码下一帧）
- 世界模型目标：pred_next_fused → 拟合 next_fused（自监督）

### Loss 组合
```python
total_loss = α × main_loss + β × world_loss

main_loss  = steer/throttle/brake 的预测误差（现有）
world_loss = MSE(pred_next_fused, real_next_fused)（新增）

α = 1.0  （主任务权重）
β = 0.3  （世界模型辅助权重，不喧宾夺主）
```

### 专家负载均衡
```python
# MoE 负载均衡 loss（防止路由器只选一个专家）
balance_loss = num_experts × Σ(routing_prob_i²)  # 越均匀越小
total_loss += γ × balance_loss  (γ = 0.01)
```

## 4. CoreML 导出方案

### 导出结构
```
enc.mlmodelc          (已有，4.8MB，ANE)
ctl.mlmodelc          (已有，11MB，cpuOnly)  
world.mlmodelc        (新增，≤3MB，cpuOnly)
```

### 世界模型导出
- 单独 trace 为一个 CoreML 模型
- 输入：fused[1,512] + action[1,3] + det_feat[1,128] + det_mask[1,20] + vehicle_state[1,8] + track_mode[1,1]
- 输出：predicted_next_fused[1,512] + routing_weights[1,3]
- INT8 量化（借鉴 export_m9_v2_int8.py 的 palette+kmeans）
- computeUnits = .cpuOnly（不碰 GPU）

### 推理流水线（Swift）
```
每 tick：
  ① enc → feat（ANE）
  ② tf → fused（CPU）
  ③ refiner → steer/throttle/brake（CPU）
  ④ world(fused, action, ...) → predicted_next_fused（CPU，可选）
  
  下一 tick 的 feat ring buffer 可以用 predicted_next_fused 做预填充
  → 让 refiner 看到「未来预判」→ 更好的决策
```
