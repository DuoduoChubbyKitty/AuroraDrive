## 2. `toPose` 数学复核（独立实现，非复刻）

**被验代码**：`Sources/AuroraDrive/Capture/CoordinateCapture.swift:215-229`

```swift
func toPose(_ location: Vec3, _ rotation: Vec3) -> Pose {
    let pitch = rotation.0
    let pitchRad = pitch * .pi / 180.0
    let yawRad = rotation.1 * .pi / 180.0
    let viewDir: Vec3 = (cos(pitchRad) * cos(yawRad),
                         cos(pitchRad) * sin(yawRad),
                         sin(pitchRad))
    let north = dot(viewDir, kNorth)
    let east = dot(viewDir, kEast)
    var heading = atan2(east, north) * 180.0 / .pi
    if heading < 0 { heading += 360.0 }
    return (location.0, location.1, location.2, pitch, heading)
}
```

### 2.1 基向量正交性（`CoordinateCapture.swift:100-101`）

| 检查 | 实测 | 期望 |
|---|---|---|
| `kNorth · kEast` | `1.735e-18` | ≈0 ✅ |
| `‖kNorth‖` | `1.0000000000` | 1 ✅ |
| `‖kEast‖` | `1.0000000000` | 1 ✅ |

### 2.2 `atan2(east, north)` 方向约定

罗盘角的定义是**从北顺时针**。`atan2(y=east, x=north)` 正是该定义：

| 方向 | east | north | atan2 结果 | 期望 | 判定 |
|---|---|---|---|---|---|
| 北 | 0 | 1 | 0° | 0° | ✅ |
| 东 | 1 | 0 | +90° | 90° | ✅ |
| 南 | 0 | −1 | 180° | 180° | ✅ |
| 西 | −1 | 0 | −90° → +360 = 270° | 270° | ✅ |

### 2.3 pitch 不污染 heading（视线朝下时）

| pitch | yaw | heading |
|---|---|---|
| 0° | 45° | 135.788° |
| −30° | 45° | 135.788° |
| −60° | 45° | 135.788° |
| −89° | 45° | 135.788° |

**恒定** —— 因为 `cos(pitch) > 0` 只等比缩放 viewDir 的 XY 分量，不改变其方向。✅

### 2.4 边界（如实记录的一个数学边界，非 bug）

`pitch = ±90°` 时 `cos(pitch) = 0` → viewDir 的 XY 分量 = (0,0) → `atan2(0,0)` 无定义。
`hasValidRotation`（`:197`）限 `|pitch| ≤ 90.001`，理论上该点可达；实测 `pitch=90.001, yaw=45` 返回 315.788°（未崩溃但值不可信）。
**实际影响**：车头/相机 pitch 不会到 ±90°，属理论边界，仅作记录。

### 2.5 双重实现一致性

`NetworkLocator.swift:299-312` 的 `computeHeading()` 与 `toPose()` **逐字等价**（同一 `atan2(eastDot, northDot)` 公式）。
→ **两处独立实现给出同一结果，无分歧** ✅

### 2.6 ⚠️ 一处精确化（对 `换代约束通告` §3 表述）

先前的 `docs/换代约束通告-2026-10-08.md` §3 写「`toPose()` 的 heading = rotation.yaw 算的 compass_heading」。
**复核结论：成立，但需精确化** —— `pose.4` **不含 yaw 的数值**：

```
heading(yaw) = (yaw + 90.787960°) mod 360     ← 纯平移、双射可逆
```

| 项 | 值 |
|---|---|
| `kEast` 相对 +X 轴偏角 | **−0.787960°** |
| `kNorth` 相对 −Y 轴偏角 | **+0.787960°** |
| 两者同源 → 地图旋转校正量 θ | −0.787960°（与 `kCalibB` 同源） |
| 8 个 yaw 取值的 `(heading − yaw)` 环绕差 | **恒 = +90.787960°** |

**实践含义**：
- 「真值来源」的说法**成立**（pose.4 由真 yaw 唯一决定）
- 但**做训练特征时不能把 `pose.4` 当 UE5 yaw 用**——两者差一个 90.788° 常量
- 那个 0.788° **不是 bug**，是 `kNorth/kEast` 已吸收的地图倾角

> w1 已把这条写进 `NetworkLocator.swift:593-595` 的注释 ✅

## 4. w1 镜像 bug 修复复核

### 4.1 bug 是什么（我在 18:37 独立发现并向 Lead 报告）

**旧码** `NetworkLocator.swift:560`：`atan2(dx, dy)` —— 第二参取了地图 y 的**正方向（南）**。
**权威公式** `MissionConsole.swift:3007`（2026-09-30 已修复并实测）：`atan2(+Δx, −Δy)`（东=+Δx，北=−Δy，因地图 y 向下）。

**偏差异刻画**（先纠正我自己的一处措辞）：

> ⚠️ 我在 18:37 给 Lead 的消息里写「恒为 180°（南北镜像）」——**这个措辞不准确**。
> 实测 8 个方向的差值是 **{0°, 90°, 180°}**，并非常量。正确刻画是 **关于东西轴的镜像反射**：

```
现码 = (180° − 权威) mod 360
```

| 运动方向 | 权威罗盘 | 旧码 | 差 | 判定 |
|---|---|---|---|---|
| 正北 | 0° | 180° | −180° | ✗ 反 |
| 东北 | 45° | 135° | +90° | ✗ |
| 正东 | 90° | 90° | 0° | ✅ 镜面不动点 |
| 东南 | 135° | 45° | −90° | ✗ |
| 正南 | 180° | 0° | −180° | ✗ 反 |
| 西南 | 225° | 315° | +90° | ✗ |
| 正西 | 270° | 270° | 0° | ✅ 镜面不动点 |
| 西北 | 315° | 225° | −90° | ✗ |

→ **8 个方向 6 个错**，正东/正西是镜面不动点恰好不错。
