V2 引擎已接入驾驶主循环，**替代 M9 成为主驾**，M9 保留为冷启动/缺失时的回退路径。

| 场景 | 走哪个引擎 |

| V2 已加载 且 `timelineReady >= 2` | **V2**（8 帧时序 + 5 路输入 + 6 输出） |
| V2 冷启动（有效帧 < 2） | 回退**旧 M9**（真实单帧路径） |
| V2 模型缺失 | 回退**旧 M9** |

两者**互斥推理**（每帧只触发一个），省算力。

## 2. 冷启动降级（§4.3 要求）

**判据**：`inferenceEngineV2.timelineReady`（= `timelineFrames >= 2`）。

**为什么不是"V2 内部退回单帧模式"**（一个硬约束）：
- 导出脚本用 `num_frames`（=8）**固定** image 的 dim0
- CoreML **不支持动态 shape**（w5 实测：RangeDim 转换期崩、EnumeratedShapes 编译期崩）
⟹ Swift 传 `[1,3,180,320]` 会 shape 不匹配**直接报错**，不是"走另一条分支"。

**本实现**：V2 在 `timelineReady == false` 时**拒绝推理并如实记原因**
（`coldStartSkipReason`），调用方据此走 M9 —— 那才是真正的单帧路径
（`m9_mono` 契约就是 `[1,...]`）。比"硬塞 8 帧里 7 个零"诚实：后者会
**静默**产出一个基于"7 步零历史"的控制量。

**冷启动期约 `2/30Hz ≈ 67ms`**（两三帧），对驾驶无实质影响。

## 3. ControlCommand 对接

```swift
func v2CommandOf(_ engine: InferenceEngineV2) -> ControlCommand? {
    guard engine.isLoaded, engine.timelineReady,
          let result = engine.lastResult else { return nil }
    return ControlCommand(steer: result.steer,
                          throttle: result.throttle,
                          brake: result.brake,
                          confidence: engine.lastConfidence ?? 0.9)
}
let m9Command = v2CommandOf(inferenceEngineV2) ?? commandOf(inferenceEngine)
```

- **`confidence` 终于有真值**：V2 的 confidence 头输出 ∈ [0,1] 直接填入。
  该字段在旧链路里**一直硬编码 0.9 占位**（`:7069` 注释「占位，置信度估计器会覆盖」），
  V2 是第一个给它真实模型值的。未拿到时保留 0.9，不谎报高置信度。
- **`risk` / `car_heading`**：作为诊断字段存在于 `engine.lastRisk` /
  `engine.lastCarHeadingRad`（未接入控制逻辑，等验证后再议）。
- steer/throttle/brake：直接用 V2 的 `lastResult`（与旧 `InferenceResult` 同构）。

## 5. V2 用"上一帧的检测/车道线"（时序说明）

V2 `infer` 需要 `detections` + `laneMask`，但 tick 里检测推理
（`yolopxEngine.infer`）在驾驶推理**之后**（`:7050` vs `:6992`）。

故 V2 用**上一帧**的 `effectiveDetections` / `yolopxEngine.laneMask`——
这与 V2 本身的"异步推理 + 读 `lastResult`"语义一致（本就有 1 帧延迟）。
