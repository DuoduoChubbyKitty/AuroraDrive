## 1. heading 单位（★关键）

### 1.1 录入端

`RecordEngine.swift:28`（appendFrame 签名）：
```swift

```
`AuroraDriveApp.swift:7780+`（recordFrameIfNeeded 调用点）：
```swift

```
`locatorHeading` 来源 = `CoordinateCapture.readWithTier()` → `worldToMapPixel(pose).heading` → **度 [0, 360)**（上一轮 task-70 已核实）。

✅ **录入端写的是「度」**。

### 1.2 dataset 侧处理

`dataset_v2.py:297`（构造函数默认值）：
```python
heading_unit: str = "auto",
```
`:355-365`（处理逻辑）：
```python
hvals = [r["heading_raw"] for r in rows if r["heading_raw"] is not None]
unit = heading_unit        # "auto"
if unit == "auto":
    unit = _infer_heading_unit(hvals)    # ← auto 推断
…
r["heading_rad"] = math.radians(h) if unit == "deg" else float(h)
```

`:184-202`（auto 推断规则）：
```python
_HEADING_UNIT_AUTO_THRESHOLD = 2.0 * math.pi + 0.5   # ≈ 6.7832

def _infer_heading_unit(values, eps=None):
    m = max(abs(v) for v in values)
    return "deg" if m > 6.7832 else "rad"
```

### 1.3 ⚠️ 误判风险（量化）

| 场景 | heading 值（度） | max | auto 判定 | 正确？ |
|---|---|---|---|---|
| 车头全程朝北附近 | [0, 1.5, 3, 5.5, 6] | 6.0 | **rad** | ❌ 误判 |
| 车头朝北偏东 | [10, 25, 40, 50] | 50 | deg | ✅ |
| 车头转过东南 | [120, 150, 180, 200] | 200 | deg | ✅ |
| 车头朝南偏西 | [240, 270, 300] | 300 | deg | ✅ |

**误判后果**（以 heading=180° 为例）：
```
真值: 180° = 3.1416 rad → sin(π)=0, cos(π)=-1
误判为 rad: 180.0 直接当弧度 → sin(180)=-0.80, cos(180)=-0.60
→ 误差 57.3 倍，sin/cos 全错
```

`train_v2.py:260-265` 构造 dataset 的 kwargs：

### 1.5 当前是否触发

```bash

    awk -F, 'NR>1 && $7!="" {c++} END{print c+0}' "$c"
```

→ **所有 clip 的 heading 列全空**（0 行有值）→ auto 推断输入为空 → 返回 "rad" → **无值不转换，不触发**。

✅ **当前不触发**（桌面截图录不到定位）。
🔴 **但真实游戏录制一旦 heading 有值且车头朝北附近，就会误判**。

### 1.6 建议

**train_v2 显式传 `heading_unit="deg"`**（一行修）：
```python

```
或 dataset 构造时写死 `heading_unit="deg"`（因为录制端明确写的是度）。

### 3.3 nil → 空串（不是 0）

```swift

}
```
✅ 缺值写**空串** → `dataset_v2` 的 `_safe_float` 返回 None → mask=0 → **能区分"真值 0"与"读不到"**。
