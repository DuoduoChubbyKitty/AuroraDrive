> **核心问题**：怎么证明模型真的在用车道线，而不是忽略它？
> **交付物**：`src/verify_lane_usage.py`（验证工具）+ 本报告

## 0. 一句话结论（先说答案）

**当前模型「不会跟车道线」是「三重根因」叠加的结果，其中两重是新发现的：**

| # | 根因 | 层级 | 是否前人已发现 |
|---|---|---|---|
| R1 | 训练数据里**根本没有车道线标注**（5 个 clip 全无 lane 数据，标签全 0） | 数据 | ✅ 已发现 |
| R2 | 车道分支的 GAP 全局平均池化**抹掉了车道线位置信息**（平移不变） | 架构 | ❌ **本任务新发现** |
| R3 | 车道线几何口径曾错位（interpolate 拉伸 vs letterbox 640） | 数据管线 | ✅ 已发现（T1 正在修） |

**R2 是本任务最有价值的发现**：它独立于数据缺失——**即使补上数据，以当前的 GAP 架构，模型依然「分不清车道线左右」，照样会开出车道线**。

## 1. 任务 1：M4 损失设计审计

审计对象：`src/train_v2.py` 的 `V2Loss`（:791 起）与车道线辅助机制。

### 1.1 损失结构（实测）

`V2Loss.forward` 的损失组成：

| 损失项 | 权重默认 | 作用 | 状态 |
|---|---|---|---|
| `l_steer`（L1/MSE） | 1.0 | 主转向 | ✅ 生效 |
| `l_thr`（BCE logits） | 0.5 | 主油门 | ✅ 生效 |
| `l_brk`（BCE logits） | 0.5 | 主刹车 | ✅ 生效 |
| `l_ls`（lane_steer 探针 L1） | 0.5 | **★主力**：车道特征→steer | ⚠️ **从未生效**（见下） |
| `l_lc`（lane_consistency） | 0.05 | 主头与几何反推自洽 | ⚠️ 依赖 lane_mask，**无数据则跳过** |
| `l_seg`（lane_seg BCE） | 0.3 | 车道分割 | ❌ 当前 M2 无 `lane_logits`，自动跳过 |

### 1.2 三个关键问题的答案

**Q1：车道线分支的梯度真的能传到 steer 吗？**

✅ **架构上可以**。`M2Model.forward`（model_v2.py:876）：
```python
fused = torch.cat([img_feat, lane_feat, det_feat, state_feat], dim=1)  # [B,512]
return self.fusion_head(fused)
```
车道特征作为拼接分量进入 FusionHead，主 steer 损失的梯度可经 `cat` 回流到 `lane_encoder`。

**实测验证**（`experiment_gradient`）：对 steer 反传，
- `‖g_lane_encoder‖ = 5.474`
- `‖g_image_encoder‖ = 22.13`（lane/img 比例 ≈ 0.247）
- 证明车道分支参数**确实收到梯度**（非 0）。

> ⚠️ 但「梯度可达」≠「用了」。梯度能走到，但若 GAP 抹掉位置语义（见 §2），
> 这梯度也只会学到「线的总量」，学不到「线在哪」。

**Q2：有没有辅助损失（从融合特征预测车道线中心偏移）？**

⚠️ **有辅助损失，但设计的是「车道特征→steer」探针（不是「→中心偏移」），且从未生效**。

- `LaneSteerProbe`（:650）存在：64→32→1→tanh，只吃车道特征，监督目标=GT steer。
- 但这个探针**当前 checkpoint 里没有**（`has_training_probe: False`）。
- 更关键：训练日志 3 个 epoch 的 `lane_supervised_frac` **全是 0.0** —— 意味着
  「只在有车道线标注的样本上监督」的条件 `lane_valid.any()` **从未为真**。
  （因为数据里根本没有 lane_present=1 的样本，见 R1。）

**Q3：有没有车道线 dropout（训练时随机屏蔽车道线）？**

❌ **没有**。全仓搜索 `dropout` / `lane_drop` / `mask_drop`，只发现 FusionHead 的
**通用** `nn.Dropout(0.2)` / `nn.Dropout(0.1)`（:734/736），**没有针对车道线的输入级 dropout**。

> 这意味着：模型没有任何机制被「强迫」学会「车道线可用时要依赖它、不可用时要靠
> 图像兜底」。这正是用户痛点「不训练就停、会开出车道线」的推手之一。

## 2. 任务 2：验证方案实现 + 实测

新建 `src/verify_lane_usage.py`，实现四个实验（不修改任何训练脚本，加载真实
checkpoint + 自造合成输入）。

### 2.1 实验 1：消融（有车道线 vs 无车道线）

同一张固定图像，输入车道线 vs 置 None，量 steer 输出差：

| pattern | steer(有线) | steer(无线) | |Δ| |
|---|---|---|---|---|
| straight | +0.7210 | +0.0352 | 0.6858 |
| curve | -0.0564 | +0.0352 | 0.0916 |
| left | -0.3009 | +0.0352 | 0.3361 |
| right | +0.6840 | +0.0352 | 0.6488 |

**表面看**：Δ 很大（0.09~0.69），说明「加了车道线输出会变」。
**但深挖发现这是假阳性**（见 §2.4）：变化来自「线的总量」，不是「线的位置」。

### 2.2 实验 2：扰动（平移/镜像）

车道线整体左右平移或镜像，看 steer 是否跟着变：

| pattern | shift | Δsteer | 敏感度/格 |
|---|---|---|---|
| straight | -4 | -0.463 | 0.116 |
| straight | +4 | -0.463 | -0.116 |
| left | -8 | +0.985 | -0.123 |
| right | +8 | -0.985 | -0.123 |
| straight | flip | +0.000 | — |

**异常点**：`left` 平移 ±8 输出**完全相同**、`straight` 平移 ±4 与 ±8 输出**不对称**、
镜像后**零变化**。这不符合「学会的车道语义」应有的平滑/单调响应，更像是
**未训练随机滤波器的相位噪声**（见 §2.4 的干净实验）。

### 2.3 实验 3：梯度（分支梯度范数）

对 steer 反传，比较各分支梯度幅值：

| pattern | ‖g_lane‖ | ‖g_img‖ | lane/img |
|---|---|---|---|
| straight | 5.474 | 22.13 | 0.247 |
| curve | 8.214 | 25.38 | 0.324 |

车道分支梯度 ≪ 图像分支（≈1/4），但**非零** —— 梯度可达（层1 通过）。

### 2.4 实验 4：位置不变性（★ 本任务核心发现）

**单条 3 格宽车道线从左到右扫过整个 160×160 掩码，看 steer 是否随线位置变化。**

先看端到端输出（会被图像分支稀释）：

| 线 x（占宽比） | steer |
|---|---|
| 16 (0.1g) | +0.1189 |
| 48 (0.3g) | +0.1113 |
| 80 (0.5g) | +0.1113 |
| 112 (0.7g) | +0.1113 |
| 144 (0.9g) | +0.1113 |

**再看编码器内部的无歧义铁证**（GAP 前后差异对比）：

| 位置对比 | GAP 前特征图差异 | GAP 后向量差异 |
|---|---|---|
| x16 vs x48 | 1.5756 | **0.0010** |
| （全部相邻对平均） | 1.3666 | **0.0011** |

**关键发现**：`LaneMaskEncoder`（model_v2.py:454）最后一层是
`self.global_pool = nn.AdaptiveAvgPool2d((1,1))`（全局平均池化 GAP）。

GAP 对空间维度求平均 → **天然平移不变**：同样一条线无论放在左边还是右边，池化后
特征**完全相同**（差 0.0011，比 GAP 前小了 **1200 倍**）。

这意味着：**车道分支「看得见线，但分不清线在哪」** —— 它只能编码「有没有线、
大概多少条、总亮度」，无法编码「线在左还是右、车是否压线」。所以无论模型
参数训练得多好，只要走这条 GAP 通道，就无法学会「跟车道线」所需的
**车道横向位置/偏移**信息。

> 这才是「会直接开出车道线」的**架构级根源**：模型对「车道偏左偏右」天然失明。

## 3. 任务 3：改进方案（设计，待 T1 几何修复后落地）

> ⚠️ 纪律说明：`src/train_v2.py` 已归属 T1（几何口径统一优先），本任务不越界改它。
> 下面给出**可直接落地的最小改动设计**，供 Lead/T1 安排。

### 3.1 修 GAP（最高优先级，架构缺陷）

把 `LaneMaskEncoder` 末端的 `AdaptiveAvgPool2d((1,1))` 换成**保留位置的池化**：

```python
# 方案 A：Flatten（暴力，维度可配）
# conv3 输出 [B,64,10,10] → Flatten [B,6400]
# 但 6400 维会撑爆 FusionHead 的 512 输入，需加一层 FC 降维到 64。

# 方案 B（推荐）：带位置编码的浅池化
# 保留 [B,64,10,10]，用一个小型 FC 头学「车道线中心偏移」作为显式辅助输出。
# GAP 前信息还在，可以：
#   1) 用 (h,w) 坐标加权求和算出"车道质心 offset"作为显式特征
#   2) AdaptiveAvgPool2d((2,2)) 保留粗略位置块，flatten 成 64*4=256

# 最小改动（B 的子集）：
# self.global_pool = nn.AdaptiveAvgPool2d((1,1))          # 旧：抹位置
self.global_pool = nn.AdaptiveAvgPool2d((2, 2))           # 新：保留上下左右四块
# 输出 [B,64,2,2] → flatten [B,256]，FusionHead 需从 512 调大（或加 FC 降回 64）
```

> 核心原则：**车道分支必须有「横向位置可辨识性」**。GAP → 2×2 自适应池化是最小改动；
> 若要真正学「中心偏移」，最佳是加一个显式的**车道中心偏移估计头**（见 3.2）。

### 3.2 加辅助损失：车道中心偏移预测

M4 现有辅助损失是「车道特征→steer」（`LaneSteerProbe`），但更好的监督是
**「车道特征→车道中心横向偏移」**（几何上更直接、更可泛化）：

```python
# lane_geometry.py 已有质心几何（lane_geometry_steer 里算 offset），可复用其几何
# 新增一个只吃 GAP 前特征的小头：
class LaneCenterOffsetHead(nn.Module):
    def __init__(self):
        super().__init__()
        # 输入 [B,64,10,10]，直接回归横向偏移 ∈ [-1,1]
        self.net = nn.Sequential(
            nn.Conv2d(64, 16, 3, 2, 1), nn.ReLU(),   # [B,16,5,5]
            nn.AdaptiveAvgPool2d((1,1)),              # [B,16]
            nn.Flatten(), nn.Linear(16, 1), nn.Tanh()
        )
    def forward(self, lane_feat_2d):   # GAP 前特征
        return self.net(lane_feat_2d)  # [B,1] ∈ [-1,1]
```
监督目标 = 车道路面的**真实横向偏移**（从车道线掩码几何算出，`lane_geometry.py`
已有 `lane_geometry_steer` 的 offset 计算逻辑可作为真值来源）。

### 3.3 加车道线 dropout（概率可配）

在 `build_m2_inputs` 或 dataset 侧加**输入级车道线 dropout**：训练时以概率 `p`
把 `lane_mask` 置 None（→ 零向量），强迫模型学会「有车道线用它，没车道线靠图像兜底」。

```python
# train_v2.py 的 enable_lane 之后（建议放 dataset/data loader 侧，本任务建议独立文件）
if self.training and random.random() < lane_drop_prob:
    lane_mask = None   # 车道线 dropout
```
建议 `lane_drop_prob = 0.2`（可配），并确保 loss 的 `lane_valid` 逻辑不受影响
（dropout 后的样本 lane_present 应仍按原标注算，只是输入被屏蔽）。

### 3.4 加权策略

现有 steer 权重 1.0 已是最高。建议**保持**，但在「有车道线的样本」上给车道辅助
损失**更高权重**（而非全局固定 0.5），让有限的真车道线样本发挥更大作用：

```python
lane_steer_weight_effective = lane_steer_weight * (1.0 + 2.0 * lane_supervised_frac)
```

## 5. 结论与建议排序

**结论**：模型「不会跟车道线」是**数据缺失（R1）+ 架构缺陷（R2）+ 几何口径（R3）**
三重叠加。前人已修 R3（T1 进行中）、已发现 R1（数据无车道线），
但 **R2（GAP 抹位置）是本任务新发现，且是「即使补上数据也依然不会跟线」的架构级硬伤**。

**建议优先级**（给 Lead）：

1. **【立即】** 承认当前模型对车道线「天然失明」（GAP 架构），不要期望补数据就能好。
2. **【架构】** 改 `LaneMaskEncoder` 的 GAP（§3.1）——最小改动 2×2 池化，彻底改是加
   「车道中心偏移」显式头（§3.2）。
3. **【数据】** 重录数据，且录制端必须落盘车道线（`RecordEngine` 加 lane_mask 输出），
   否则永远训不出「会跟线」的模型。
4. **【训练】** 加车道线 dropout（§3.3），让模型学会「有线用线、无线兜底」。
