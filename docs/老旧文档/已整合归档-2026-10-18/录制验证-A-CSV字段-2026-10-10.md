## 6 · 验收点 6：stop ack 的视角 ⚠️ 数据 PASS / 回显 FAIL

### 6.1 实测现象

| 命令 | ack 回显 perspective | 同 session 落盘 view.txt |
|---|---|---|
| `record on --perspective third` | `"third"` / `视角=third(TPV)` ✅ | — |
| `record off`（不带 perspective） | **`"first"` / `视角=first(FPV)`** ⚠️ | **TPV** ✅ |
| `meta.json perspective` | — | **`"third"`** ✅ |

### 6.2 判定：**数据面 PASS，回显面 FAIL（cosmetic）**

**实测证据（同一次录制 session `clip_20261010_230930`）**：
```bash
$ cat data/raw_clips/clip_20261010_230930/view.txt
TPV
$ python3 -c "import json;print(json.load(open('.../meta.json')).get('perspective'))"
third
```
→ **落盘数据是正确的 TPV/third**，即 Lead 的修复目标达成。

### 6.3 根因（读代码确认）

`EngineMain.swift:1236-1237`：
```swift
let recPerspective = RecordEngine.normalizePerspective(
    (obj["perspective"] as? String) ?? "first")     // ← record off 不带该字段 → 回落 "first"
```
`EngineMain.swift:1269-1270`（ack 的 detail 用它）：
```swift
let viewLabel = recPerspective == "third" ? "TPV" : "FPV"
// → detail 里写 "视角=\(recPerspective)(\(viewLabel))"
```
而 Lead 的修复（`:1257` 附近）把**写状态**移到了 `if recOn {` 内：
```swift
if recOn {
    st.glyphMode = recGlyph
    st.expertMode = recExpert
    st.recordThirdPerson = (recPerspective == "third")   // ← stop 时不再执行
}
```
→ **两个变量被混为一谈**：
- `recPerspective`：本条命令的**入参**（stop 时缺省 first）
- `st.recordThirdPerson`：**会话级状态**（start 时已设为 true，stop 不再动）

**修复目标（防止 stop 覆盖 `st.recordThirdPerson`）已达成** ✅（落盘 TPV 证明）。
**但 ack 的 detail 仍在回显入参变量**，所以显示 `first` ❌。

### 6.4 影响评估

| 面 | 影响 |
|---|---|
| **落盘数据** | **无影响** ✅（view.txt/meta.json 正确） |
| **AI/脚本读 ack** | 会误以为"录的是 FPV" → 若脚本据此判分支，可能误判 ⚠️ |

### 6.5 修复建议（不在本任务写作用域，仅报告）

ack 的 detail 应回显**会话实际视角**（`st.recordThirdPerson`），而不是本条命令的入参：
```swift
// stop 时 recPerspective 是回落值，不代表实际；用会话状态才对
let actualThird = st.recordThirdPerson        // 会话级真值
let viewLabel = actualThird ? "TPV" : "FPV"
let actualPerspective = actualThird ? "third" : "first"
// detail/data 用 actualPerspective
```
