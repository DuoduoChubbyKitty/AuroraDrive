## 0. 摘要

UI 主循环与 tick dt 从 **30Hz → 45Hz**，与引擎侧（Lead 已改 `CaptureEngine` 的 1280×720@45fps）一致。

**共改 7 处**（2 处运行时 + 5 处注释），**刻意不改 11 处**（9 处自检 dt + 2 处非帧率数值）。

---

## 1. 运行时改动（2 处，核心）

### 1.1 `MissionConsole.swift:6035` — UI tick 定时器

```swift
// 改动前
timer.schedule(deadline: .now(), repeating: 1.0 / 30.0, leeway: .nanoseconds(0))
// 改动后
timer.schedule(deadline: .now(), repeating: 1.0 / 45.0, leeway: .nanoseconds(0))
```

**影响**：UI 主循环 tick 频率 30Hz → 45Hz（待机降频逻辑按比例同步，见 §2.1）。

### 1.2 `AuroraDriveApp.swift:7065` — tick 主循环 dt ★核心

```swift
// 改动前
let dt = 1.0 / 30.0
// 改动后
let dt = 1.0 / 45.0
```

**影响**：所有基于 `dt` 的物理计算（车速 EMA 系数、加速度差分、`SpeedLimitGuard.update(dt:)`、EgoMotion 估计等）按 45Hz 步长计算。
**这是本次改动的核心** —— 若只改定时器不改此处，物理计算会按 33ms 步长但实际每 22ms 调用一次 → **积分偏快 1.5×**。

## 3. ⚠️ 刻意**不改**的 11 处（附理由）

### 3.1 自检代码的固定 dt（9 处，**保留 1.0/30.0**）

| 行号 | 所在函数 | 理由 |
|---|---|---|
| `AuroraDriveApp.swift:3303` | `runMotionSelfTest()` | 固定测试基线 |
| `:3460 / :3490 / :3516 / :3528` | `runMotionSelfTest()`（`egoModel.estimate(dt:)`） | 同上 |
| `:3557 / :3588 / :3602` | 同为自检 | 同上 |
| `:3670` | `runLimitSelfTest()` | 同上 |

**为什么必须保留 30**：
1. **自检是固定基线**：断言（如「外推 3 帧后位置误差 ≤0.03」）是按 **30Hz 步长标定的**。
   改成 45Hz 会让 `speedPerFrame * dt` 的累积位移变化 → 断言阈值失配 → **假失败**。
2. **无性能收益**：自检路径不在 45Hz 主循环上，改它**不会让游戏快一帧**。
3. **Lead 已明确修正**：「自检 dt 改了没有性能收益，反而破坏测试基线。你只改上面 4 处。」

**验证**：`grep -c "1\.0 / 30\.0" AuroraDriveApp.swift` = **9**（全部保留）✅

### 3.2 非帧率数值（2 处，**绝不能改**）

| 行号 | 代码 | 真实含义 |
|---|---|---|
| `AuroraDriveApp.swift:1793` | `RoadCornerGuide.headingDiff(ex.exitHeading, incoming) > 30.0` | **30 度**角度阈值（不是帧率！） |
| `AuroraDriveApp.swift:5357` | `return 30.0` | **30 秒**卡死判定阈值（`stuckZeroThreshold`） |

**这两个改了会造成真实功能 bug**：前者会让路口转向判定从 30° 变成 45°（误判），后者会让卡死判定从 30s 变成 45s（安全护栏失效）。
