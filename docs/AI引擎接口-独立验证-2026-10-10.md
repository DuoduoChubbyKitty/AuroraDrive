### 2.1 `EngineMain.handleCommand`（`Sources/AuroraDrive/Core/EngineMain.swift:952`）

```swift
static func handleCommand(_ line: String, server: EngineSocketServer) {
    guard let data = line.data(using: .utf8),
          let obj = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
          let type = obj["type"] as? String else {
        engineLog("[ENGINE] 无法解析命令: \(line)")
        return
    }
    engineLog("[ENGINE] 收到命令: \(type)")
    switch type {
    case "start":  … DispatchQueue.main.async { MainActor.assumeIsolated { … } }
    case "stop":   …
    case "bye":    …
    case "status": …
    case "upscale": …
    case "record": …
    case "reloadmodel": …
    case "config": …
    case "set_capture_mode": …
```

**基线事实**：
- 命令解析入口只认 `obj["type"]`
- 现有 case：start / stop / bye / status / upscale / record / reloadmodel / config / set_capture_mode（+ ping / capturewarn）
- **除 `ping` 回 `pong` 外，其余命令无任何回执** → 确认 task-60 描述的 fire-and-forget 属实
- 执行模式统一为 `DispatchQueue.main.async { MainActor.assumeIsolated { … } }`（**异步**）

> ⚠️ **我关注的一点**（待 task-60 落地后验证）：ack 必须在该异步块**执行完成之后**回，
> 否则会出现「ack 已回 ok=true，但命令实际还没执行」的假绿。这是本次验证的重点之一。

### 2.2 `tools/engine_cmd.py`（现有通信方式，参考实现）

### 2.3 `CaptureEngine.applyMode`（`Sources/AuroraDrive/Capture/CaptureEngine.swift:604`）

```swift
604: func applyMode(_ mode: CaptureMode) async {
605:     print("[cap-deep] applyMode(\(mode.label)) 进入 isCapturing=\(isCapturing) …")
606:     desiredMode = mode
607:     lastModeError = nil
608:
609:     guard isCapturing, let stream else {
611:         print("[cap-deep] applyMode 早退：还没在捕获 → 只记 desiredMode（start() 时会用）")
612:         captureMode = mode        // ← ★ 问题点
613:         onModeChange?(mode)
614:         return
615:     }
```

🔴 **确认 task-63 描述的 bug 存在**：
早退分支（`isCapturing == false`）**只记了 desiredMode、并未真正切换 stream/filter**，
却把 **`captureMode` 直接置为 `mode`** —— 而 `captureMode` 的语义应是「**已生效**模式」。
→ 后果：`state` 读到的 `captureMode` 会**谎报已生效**，与真实捕获源不符。

**验证计划**：task-62 完成后，复跑本段并确认早退分支**只写 `desiredMode`**、不再改 `captureMode`。
