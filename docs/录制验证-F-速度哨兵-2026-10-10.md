## 0. 一句话结论

**录制侧 -1 哨兵处理正确**：`speedOCR.speedKmh >= 0 ? ... : nil` 守卫生效，

## 1. DriveState.speedKmh 定义（引擎模式双源）

## 2. 录制侧 -1 哨兵守卫（✅ 生效）

`AuroraDriveApp.swift:7797`（`recordFrameIfNeeded`）：
```swift
let recSpeed: Double? = speedOCR.speedKmh >= 0 ? speedOCR.speedKmh : nil
```
- 录制**直接用 `speedOCR.speedKmh`**（不经 `DriveState.speedKmh` 的引擎模式分支）

**关键**：录制侧**不依赖心跳**，直接从 OCR 读，guard 在这里。即使心跳侧裸写 -1，
CSV 也不受影响（录制路径不走 `remoteSpeedKmh`）。

## 4. 心跳侧无 guard（⚠️ 次要缺陷，**不影响 CSV 也不影响推理输入**）

`EngineMain.swift:1468`（`sendHeartbeat`）：
```swift
"speedKmh":\(String(format: "%.1f", st.speedKmh))
```
- **无 `>= 0` guard**，`st.speedKmh = -1` 时心跳会写 `"speedKmh":-1.0`
- 引擎进程 `st.speedKmh` 走 `speedOCR.speedKmh`（因引擎进程 `isActive=false`）→ OCR 读不到时 = -1 → 裸写心跳

**接收侧** `EngineClient.swift:416`：
```swift
if let v = obj["speedKmh"] as? Double { engineSpeedKmh = v }  // 无 guard，-1 直接收
```
→ UI 进程 `remoteSpeedKmh = -1`，`DriveState.speedKmh`（引擎模式）= -1

**★ 影响范围（实测厘清——`speedKmh` 与 `engineSpeed` 是两个不同字段）**：

心跳里有**两个**速度字段（`EngineMain.swift:1468`）：
```
"speed":\(st.effectiveSpeed)   →  EngineClient.swift:415  engineSpeed
"speedKmh":\(st.speedKmh)      →  EngineClient.swift:416  engineSpeedKmh
```
两者**用途不同**：
| 字段 | 来源 | 用途 | 是否受 -1 影响 |
|---|---|---|---|
| `engineSpeed` ← 心跳 `speed` | 引擎 `effectiveSpeed`（**已有 decay + `speedValid` 门控**，见 :7228-7238） | → `effectiveSpeed`（`AuroraDriveApp.swift:6545`）→ **推理输入** | ❌ 不受影响 |
| `engineSpeedKmh` ← 心跳 `speedKmh` | 引擎 `st.speedKmh`（**无 guard**） | → `remoteSpeedKmh` → `DriveState.speedKmh`（引擎模式）→ **仅 UI 展示** | ⚠️ 会收到 -1 |

- ❌ **CSV**：**不受影响**（录制用 `speedOCR.speedKmh` 直读，走 guard）
- ✅ **推理输入**：**不受影响**（`effectiveSpeed` 走 `engineSpeed` 链，其上游 `effectiveSpeed` 已有 `speedValid` 门控 + `<0.5 → 0` 衰减，见 :7238）
- ⚠️ **UI 展示**：`DriveState.speedKmh`（引擎模式）会是 -1 → 速度面板可能显示 -1

**修复建议**（非我 scope）：心跳发送侧 `speedKmh` 加 `max(0, st.speedKmh)`，
或接收侧 `engineSpeedKmh = max(0, v)`，与录制侧 guard 对齐。优先级低（仅 UI 展示）。

## 5. `_safe_float` 反证测试（task item 4）

```bash
$ ./.venv-yolo26/bin/python3 -c "..."
```

| 输入 | `_safe_float` 输出 | 期望 | 结论 |
|---|---|---|---|
| `"60.5"` | `60.5` | 60.5 | ✅ |
| `""`（空串） | `None` | None | ✅ |
| `"-1.0"` | `-1.0` | -1.0（返回原值，下游 mask 过滤） | ⚠️ |

**mask 逻辑实测**（`dataset_v2.py:397` 附近，speed_kmh 决定 `mask[0]`）：
```
speed_kmh=60.5 → state[0]=0.5042  mask[0]=1  ✅ mask=1
speed_kmh=""    → state[0]=0.0000  mask[0]=0  ✅ mask=0（缺失）
```

**关键发现**：`_safe_float("-1.0")` 返回 `-1.0`（不返回 None）——
**若 -1 哨兵漏进 CSV，dataset 侧不会自动过滤**。实测三条路径（严格照 `dataset_v2.py:399-402` 逻辑）：

```
真实值 60.5      → _safe_float=60.5   state[0]=0.5042  mask[0]=1   ✅
空串(正确)       → _safe_float=None   state[0]=0.0000  mask[0]=0   ✅
-1 哨兵(若漏进来) → _safe_float=-1.0   state[0]=0.0000  mask[0]=1   ❌ 语义错误
```
-1 的后果：`clip(-1/120,0,1)=0` → `state[0]=0`，**数值与"缺失"相同，但 mask 被误置 1**
→ 训练时模型会把「缺失」当成「真实速度 0」来学（正是 `vehicle_state_mask` 机制要防的事）。

✅ **幸好录制侧 guard（`>= 0 ? : nil`）生效，CSV 里没有 -1，此隐患不触发。**
（这也说明：**guard 必须留在录制侧**——dataset 侧对 -1 无防护。）
