## 2. tickGap 掉拍判据

### 2.1 tickGapMs 是什么

**定义**：`AuroraDriveApp.swift:5480`
```swift
@ObservationIgnored
var tickGapMs: Double = 0
```

**赋值点**：`AuroraDriveApp.swift:6848`
```swift
let tickNow = Date()
tickGapMs = tickNow.timeIntervalSince(lastTickTime) * 1000   // ← 实测间隔（毫秒）
lastTickTime = tickNow
```

**结论**：`tickGapMs` 是**实测间隔**（两次 `tick()` 调用之间的真实时间差），不是目标间隔。

### 2.2 掉拍判据吻合度

**task 提的判据**：`tickGap > 80ms` = 掉拍

| 项 | 值 |
|---|---|
| tick 目标频率 | 30Hz → 目标间隔 = **33.3ms** |
| 掉拍阈值 | **80ms** |
| 倍率 | 80/33.3 ≈ **2.4×**（目标间隔的 2.4 倍才算掉拍） |

**判据吻合** ✅：80ms 远超 33.3ms 正常值，不会误报；且留了足够缓冲（不到 2 帧不算掉拍）。
**注意**：如果 tick 频率动态切换（ayolom→45Hz，目标 22.2ms），80ms 阈值在 45Hz 下是 3.6×——更宽松，仍合理。

### 2.3 tickGapMs 的现有消费点

| 行号 | 用途 | 是掉拍检测吗？ |
|---|---|---|
| `:5109` | `return tickGapMs > 0 ? tickGapMs : (fps > 0 ? 1000.0 / fps : 0)` ← 计算属性 `effectiveTickGapMs` | ❌ 仅供诊断 |
| `:5929` | `let gap = self.tickGapMs; let assist = gap > 1 ? 1000.0 / gap : 0` ← HUD 帧率显示 | ❌ 仅显示 |
| `:7748` | 日志 `tickGap=\(Int(tickGapMs))ms` | ❌ 仅日志 |

**结论**：`tickGapMs` 目前**只用于诊断/显示**，**没有任何掉拍检测逻辑**。

### 2.4 连续掉拍计数器

```bash
$ grep -rn "consecutiveTick\|stallCount\|dropFrame\|missedTick\|slowTick\|tickStall\|badTick" Sources/AuroraDrive/ --include=*.swift
（空输出）
```

**结论**：❌ **无现成的连续掉拍计数器**，需从零写。

**建议实现**（照搬 `stuckZeroSince` 模式）：
```swift
// 在 DriveState 里新增（照搬 :5350 的 stuckZeroSince 模式）
@ObservationIgnored var dropStreakStart: Date?
// 在 tick() 里、tickGapMs 赋值之后（:6848 之后）新增：
if tickGapMs > 80 {
    if dropStreakStart == nil { dropStreakStart = Date() }
    let held = Date().timeIntervalSince(dropStreakStart ?? Date())
    if held >= 3.0, !takeoverActive {      // 3 秒持续掉拍才拉横幅
        takeoverActive = true
        dlog("⚠️ 推理掉拍 \(Int(held))s → 拉接管横幅")
    }
} else {
    // 恢复了 → 清横幅（照搬 :7336 的条件清除模式）
    if dropStreakStart != nil { dropStreakStart = nil }
    if takeoverActive { takeoverActive = false }
}
```

```
fps / detections / isDriving / isStreaming / mode / modeRaw / speed / speedKmh / confidence / recording / frames / pid / reason
```
**不含 isDegraded / maskFlags / degraded**。

### 3.4 结论

| 项 | 引擎侧 | UI 侧 |
|---|---|---|
| `isDegraded` 可读 | ✅ `yolopxEngine.isDegraded`（引擎进程内直接读） | ❌ **无路径**（shm 的 maskFlags bit0 没被 UI 读；heartbeat 不带） |
| `state` 命令 | ✅ ack.data 含 `isDegraded`（`:1173`） | ⚠️ 可通过 `tools/engine_ai.py state` 查（但那是 CLI 轮询，不是 UI 实时） |

**⚠️ 需要补的路径**（二选一）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | heartbeat JSON 里加 `"degraded":\(st.yolopxEngine.isDegraded)` 字段 | 改 `sendHeartbeat`（`:1755`）一行；UI 侧在 heartbeat 消费点加 `state.yolopxDegraded = …` |
| **B** | UI 侧从 shm 直接读 maskFlags bit0 | 需在 EngineClient 里加 `maskFlags` 的读代码；比 heartbeat 路径更底层、更实时，但改动更大 |

**建议方案 A**：最小改动，且 heartbeat 已是 UI 侧的既有数据源（`EngineClient` 已有 heartbeat 解析）。
