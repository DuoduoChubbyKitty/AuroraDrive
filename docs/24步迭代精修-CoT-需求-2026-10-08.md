## 1. 方案选择：方案二（展开成静态图）

### 为什么不用方案一（while_loop）
- 现有 8 帧 GRU 已是 while_loop，已让 ANE 编译失败回退 CPU
- 24 次 while_loop 只会更糟（5~10ms，编译不稳）

### 方案二：展开成 24 个静态 GRUCell 串

```
融合特征 → GRUCell#1 → GRUCell#2 → ... → GRUCell#24 → 精修特征 → 输出
```

- **无 while_loop** → ANE 友好（静态图）
- **预估耗时 1~2ms**（静态算子串联）
- **总预算**：12.4 + 2 = 14.4ms → 69Hz（余量 2.3×）

### 参数共享策略（优先尝试）

| 策略 | 参数量 | INT8 大小 | CoreML 兼容性 |
|---|---|---|---|
| **共享（24 个用同一套权重）** | +0.14MB | 3.51MB（不变） | ⚠️ 待实测 |
| 独立（24 个各自权重） | +3.39MB | 6.90MB | ✅ 静态图稳 |

**优先共享**，CoreML 不支持则退独立（6.90MB 仍 ≤10MB）。

## 2. 架构设计

### 2.1 在模型里的位置

```
ImageEncoder(8帧) → img_feat [1,256]
LaneEncoder       → lane_feat [1,64]
DetEncoder        → det_feat [1,128]
StateEncoder      → state_feat [1,64]
                        ↓ concat
                  fused [1,512]
                        ↓
            ★ IterationRefiner（24步迭代）★
                  fused → GRUCell×24 → refined [1,512]
                        ↓
                  FusionHead → steer/throttle/brake
                  + confidence/risk/car_heading（辅助头）
```

```python
        # return_intermediate=True: 返回每步的输出（训练用）
        # 返回: refined [B,512] 或 (refined, [step1, step2, ..., step24])
        ...
```

### 2.3 零初始化（与 temporal_proj 同理）

```python
nn.init.zeros_(self.refiner_proj.weight)  # 残差投影零初始化
nn.init.zeros_(self.refiner_proj.bias)
```
- 起步时 refined = fused + 0 = fused（与无迭代逐位一致）
- 训练中逐步学出迭代修正
- **不破坏现有行为**（ResNet 标准做法）

## 3. 训练信号设计（逼模型"真的用 24 步"）

### 3.1 逐步递减监督

```
第 1 步输出  → 损失权重 1.0（粗略猜）
第 8 步输出  → 损失权重 0.5
第 16 步输出 → 损失权重 0.3
第 24 步输出 → 损失权重 1.0（精细出）
```
- 强制"早期粗略、后期精细"
- 不让模型偷懒只依赖第 1 步

### 3.2 中间步辅助任务

```
第 8 步：预测"车道中心偏移"（有真值监督）
第 16 步：预测"TTC 碰撞时间"（有真值监督）
第 24 步：预测最终 steer/throttle/brake
```
- 中间步有活干，不能偷懒
- 复用现有 HeadingHead / RiskHead 作为中间步辅助

### 3.3 随机深度（防过拟合）

- 训练时随机跳过其中几步（如 24 步随机只用 12~24 步）
- 防止模型过度依赖"恰好 24 步"
