## 一、项目定位与构建目标（Package.swift）

**项目**：AuroraDrive（极光智行）——macOS 上针对《异环》(NTE) 的游戏辅助/自动驾驶系统。
**语言与平台**：Swift 6.2 工具链，`.swiftLanguageMode(.v5)`，平台要求 `.macOS(.v26)`，**零外部依赖**（`dependencies: []`）。

`Package.swift` 定义 **3 个 target**：

| Target | 类型 | path | 依赖 | 内容 |
|---|---|---|---|---|
| `AuroraDriveShared` | 库 | `Sources/AuroraDriveShared` | — | XPC 服务名与协议（21 行） |
| `AuroraDriveUserAgent` | 可执行 | `Sources/AuroraDriveUserAgent` | AuroraDriveShared | 用户会话 LaunchAgent 的 XPC 宿主（52 行） |
| `AuroraDrive` | 可执行 | `.`（项目根） | AuroraDriveShared | 主程序：**44 个 Swift 源文件入白名单**（39 个在 `Sources/AuroraDrive/` + 5 个 Vendor/Engine）；全仓 `.swift` 实为 **46 个**（另 2 个属 Shared/UserAgent target） |

> **AuroraDrive 主 target**（`Package.swift:204-208`）——原文记载准确：
> ```swift

> **`OpenCVFlow` target**（`Package.swift:64-71`，2026-09-27 新增，原文完全未提）：
> ```swift
> .unsafeFlags(["-I", "\(openCVFlowRoot)/include"])          // 头文件
> .unsafeFlags(["-L", "\(openCVFlowRoot)/lib", ...])          // 库路径（★必须绝对路径）
> + openCVStaticLibraries.map { .linkedLibrary($0) }          // 11 个静态库
> + [.linkedFramework("Accelerate")]                          // LAPACK/BLAS
> ```
>
> **11 个 OpenCV 静态库清单**（`Package.swift:35-47`，含体积注释）：
> `opencv_core`(5.02MB) / `opencv_imgproc`(8.05MB) / `opencv_geometry`(2.65MB) /
> `opencv_flann`(0.79MB) / **`opencv_video`(0.67MB) ← DIS 光流在这** /
> **`tegra_hal`（ARM SIMD HAL，必须链，否则 carotene 符号缺失）** /
> `kleidicv_hal` / `kleidicv` / `kleidicv_thread` / `ittnotify` / `zlib`
>
> **两个构建硬约束**（源码头注释 + `pitfalls.md` §11/12/13 同源）：
> 1. **`-L` 必须用绝对路径**——SwiftPM 在 link 阶段按**构建产物目录**解析相对路径，会报 "library not found"
> 2. **静态库必须是实体文件**，不能是符号链接嵌套（实测嵌套链接同样失败）
>
> **为何取包根不用 Foundation**（源码注释）：
> > SwiftPM 的 manifest 跑在受限沙盒里，**没有 Foundation**（用 `replacingOccurrences`
> > 会报 "value of type 'String' has no member"）。`#filePath` 在 manifest 里展开成
> > Package.swift 的绝对路径，用纯标准库的字符串 API 切掉文件名即可。
