# AuroraDrive 源码树与架构总览

> 本文档是文档库的导航页与源码树基准。基于当前仓库（commit d64873b 之后的文件树）逐单元编写，所有路径、行数、接口均以实际代码为准。

## 一、项目定位与构建目标（Package.swift）

**项目**：AuroraDrive（极光智行）——macOS 上针对《异环》(NTE) 的游戏辅助/自动驾驶系统。
**语言与平台**：Swift 6.2 工具链，`.swiftLanguageMode(.v5)`，平台要求 `.macOS(.v26)`，**零外部依赖**（`dependencies: []`）。

`Package.swift` 定义 **3 个 target**：

| Target | 类型 | path | 依赖 | 内容 |
|---|---|---|---|---|
| `AuroraDriveShared` | 库 | `Sources/AuroraDriveShared` | — | UI 与用户会话 Agent 共用的 XPC 服务名与协议（21 行） |
| `AuroraDriveUserAgent` | 可执行 | `Sources/AuroraDriveUserAgent` | AuroraDriveShared | 用户会话 LaunchAgent 的 XPC 服务宿主（52 行） |
| `AuroraDrive` | 可执行 | `.`（项目根） | AuroraDriveShared | 主程序：37 个 Swift 源文件（32 个在 `Sources/AuroraDrive/` + 5 个 Vendor） |

**关键机制：sources 白名单（不是目录递归）**。AuroraDrive target 的 `sources:` 数组**逐文件显式列出**全部 37 个文件：

- `Sources/AuroraDrive/App/` 5 个、`Agent/` 5 个、`Capture/` 3 个、`Core/` 7 个、`Control/` 4 个、`Inference/` 4 个、`Locate/` 3 个
- `Vendor/MetalGoose/Engine/` 5 个（GooseEngine、GooseUpscaler、Stubs、WindowCaptureManager、CaptureSettings）

**移动或新增源文件的硬性要求**：必须同步更新 `Package.swift` 的 `sources:` 白名单，否则该文件**静默丢出编译目标**（编译不报错、文件不存在于二进制）——这是本仓库历史上"整理后引用断了"的根因。

`exclude:` 数组排除项目根下的非源码目录与文件（docs、tools、MaaNTE、models、data、build、checkpoints、`Sources/AuroraDriveShared`、`Sources/AuroraDriveUserAgent`、Vendor/MetalGoose 根层 15 文件、`__pycache__` 等 **59 项**），防止白名单机制下的意外收录。

> ⚠️ **2026-09-20 整理订正**：此前 exclude 仅 28 项且漏掉了项目自己的 `build/`（2.1GB），导致构建时产生 **20436 个 unhandled 告警**；同时 `各类研究`、`backups` 两条已失效（目录不存在）触发 `Invalid Exclude`。现为 59 项，两类告警均已归零（冷启动 `rm -rf .build && swift build` 实测）。**新增根层文件/目录时必须同步此数组**。

`linkerSettings:` 链接 `NetworkExtension`、`Network` 框架与 `libpcap` 库（网络包捕获用）。

**职责分层口径**：`App`（SwiftUI 界面与入口）→ `Agent`（AI 技能与任务规划）→ `Inference`（看懂画面）→ `Locate`（知道在哪）→ `Capture`（拿到画面）→ `Control`（动手操作）→ `Core`（进程/通信/系统配置底座）。依赖方向大体自上而下，同 target 内全部直接符号可见（无 import 边界）。
