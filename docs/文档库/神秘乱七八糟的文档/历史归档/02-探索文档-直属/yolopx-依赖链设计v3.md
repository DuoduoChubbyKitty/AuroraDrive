# YOLOPX 接入收尾 —— 依赖链设计 v3（43 任务 / 66 依赖 / 16 层）

> 状态：**设计稿，未建任务**。等用户发话才建。
> 建任务即会自动派发，故本文件仅作评审用。

## 一、设计原则（四条）

1. **一任务一条线**：每个任务都有独立的依赖路径与独立产物，不做"同一件事拆两半"的凑数拆分。
2. **探索可并行，验证必串行**：探索线最多 4 条并行；所有验收/审查关卡一律排在产物之后，绝不与生产并行。
3. **交叉验证**：关键结论由**非生产者**独立复核（做实验的人不许自己验收自己）。
4. **打回重做**：所有 `review` 类关卡具备原生打回能力，失败自动生成修复任务并重审；最终关卡按「零疑虑」标准裁决（含无法量化的直觉疑虑）。

## 六、红线（写进每个任务）

- 分辨率不可改（用户红线）
- 禁 fp16，只允许 8 位（4bit 只报数据不采用）
- 30fps 不可降（33ms 预算）
- 严禁删用户文件、严禁覆盖既有产物
- 不改 vendored 官方仓库
- 优化不减功能、不减循环
- 感知禁裸上实车
