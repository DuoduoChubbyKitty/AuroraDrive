# App 和模型厂商是什么关系，以及「推荐谁」这件事谁来说、说多狠、说到什么时候停

> 【2026-09-19 复核标注】本文规则仍然有效，作为厂商线唯一准绳。文中描述的"管理员嘴里推荐 Agnes"流程尚未实现（实现状态核对见《AI-Agent最终实施方案.md》顶部【落地状态核对】）；当前 app 已实现的是：用户自配 OpenAI 兼容 LLM（Key 存本地小本本，0 钥匙串）+ 设置页 Agnes 示例入口（`AIAgentPanel.swift:2228`），均不违反"三个零"。

这份文件只管一件事：**模型服务商那条线上，App 站什么位置**。散在《AI-Agent最终实施方案》里的几条规则在这里集中成一处，两处冲突以这里为准。

---

## 总原则一句话

**App 不碰账号、不碰钱、不碰 Key。** 用户自己去注册、自己开户、自己付钱、自己承担服务商的条款。

App 提供的是「怎么接」的能力，不是「接谁」的服务。

---

## App 侧的三个零

| | 含义 |
|---|---|
| **零内置 Key** | 仓库、安装包、默认配置、示例文件里，没有任何一把真实的 Key。不许有。 |
| **零厂商绑定** | 代码不把任何厂商的域名、模型名写成默认值。用户没配，App 就没有模型，不许偷偷回落到某一家。 |
| **零背书** | 不声称与任何模型服务商有合作、代理、赞助、官方推荐关系。App 不替任何一家担保可用性、价格、合规。 |

唯一允许的例外是**管理员的免费嘴**：Pollinations `https://text.pollinations.ai/openai`、模型字段 `openai`。它零 Key 可用，且**看不见图**，只用来把用户教会配模型。它不是给游戏干活用的模型，不算「App 内置的干活模型」。

## 推荐规则

### 一、谁来说

**只有管理员能推荐。**

管理员是 App 里本地写死系统提示词的一个对话角色，和「引导员」是同一个角色，不要做成两套人。

**推荐这件事只发生在管理员嘴里。** 界面文案、README、授权文件、打包元数据、面向用户的正式文档——**一个字都不许写厂商推荐**。

### 二、推荐谁、为什么

推荐 **Agnes**。理由必须讲人话，不要甩术语：

- 便宜
- 能看图
- 这边实测验证过

给官网链接，说明点哪里登录、哪里生成 Key、Key 大概长什么样（`sk-` 开头）。

### 三、说多狠

**没配好之前，疯狂推，不要克制。**

只要还没配好（缺主模型、缺 Agnes、或测不通）：

- 管理员的**每一轮回复都必须带上 Agnes 的推荐**
- 基本每句话都要捎一个
- 用户问别的、闲聊、抱怨、说「等一下」「我考虑考虑」——推荐照带不误
- **提一次就以为尽到义务，是不合格的**

**唯一的要求**：用户问的那件事也得答。不能因为顾着推就把人晾在那。

### 四、什么时候停

**配好之后立刻停，一个字都不要再念。** 别变成甩不掉的推销员。

### 五、推的时候必须带的那句话

> 「你也完全可以选别家，只要那个模型能看图就行，我不替谁担保。」

**这句不能省。** 推得再狠也要带。用户要是自己有别的多模态 Key，管理员照收，照测，照写用途字段，不许因为不是 Agnes 就怠慢。

## Agnes 的定位（最容易记错的地方）

| | |
|---|---|
| **是** | 监视（每 10 秒看一次屏）<br>事后分析（演示宫格 → 总结成技能）<br>备用模型 |
| **不是** | 内置默认密钥<br>App 指定的供应商<br>规划的默认模型 |

**规划和监视是两个模型，不要混。** 规划走用户自己的主模型；监视走 Agnes。

用户强行要用 Agnes 当主模型，是用户主动提，管理员才带去做。

---

## 用户侧的义务，实现时要讲清楚

管理员收密钥前后必须说清，别含糊过去：

- 这是**你自己的账号**，自己去注册
- 这是**你自己的钥匙**，App 不代你付钱、不代你开户
- 用量、费用、服务商的条款和封禁规则，**都是你和服务商之间的事**
- App 里没有写死的 Key，也没有「用我们的额度」这种选项

---

## 边界：这套规则挡住什么，挡不住什么

**挡得住**——厂商关联那条线：

- 不代付、不代注册、不内置 Key，厂商的经济和法律关系跟开发者无关
- 不背书，不构成推荐关系或合作关系
- 推荐话术只由 App 内的虚拟角色说出，且明确「我不替谁担保」

**挡不住**——自动化本身那条线：

> 游戏辅助这件事的性质，**不因为换了谁的 Key 而改变**。

这份文件解决的是「别把厂商扯进来」，不解决「这件事本身合不合规」。后者不是靠改配置能解决的，实现者和使用者都应该知道这个边界在哪，不要误以为配好两把 Key 就万事大吉。
