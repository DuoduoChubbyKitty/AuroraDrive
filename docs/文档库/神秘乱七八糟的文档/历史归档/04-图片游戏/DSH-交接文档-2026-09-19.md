### 2.1 Providers 现状
| provider 名 | 显示名 | baseURL | key 环境变量 | 模型 | 思考 | 状态 |

### 2.2 两个致命配置坑（用户已亲自验证）
1. **vankit 的 baseURL 必须带 `/v1`**：DSH 的 openai-completions 适配器不会自动补 `/v1`，写成 `https://sub.vankit.top` 打错路径；改成 `https://sub.vankit.top/v1` 立刻通。**agnes 本来就带 `/v1`，所以一直正常。**
2. **claude 必须挂在 `bvvgvv` 下，不能挂在 `ah` 下**：`AH_API_KEY` 那个分组**根本没有 claude 模型**，用 ah 发 claude 直接 404 `Model claude-sonnet-5 is not supported by any configured account in this group`（这就是 ah+claude 在 DSH 里 terminated/空响应的真因）。

### 2.3 thinkingFormat 设置
- agnes / vankit glm：`thinkingFormat: zai`（DSH 能解析思考段）
- `bvvgvv`（claude）**没配 thinkingFormat** —— 但配了也没用，因为上游 Kiro 渠道根本不回吐思考数据

## 4. 错误码速查（DSH 日志里见过的）

| 错误 | 含义 | 性质 |
|---|---|---|
| `502 Upstream request failed` | 上游连不上/断了 | 临时，等等能好 |
| `Stream ended without finish_reason` | 流开了半路被掐 | vankit GLM 池半截断流；** Claudius 也偶尔报，但 claude 是 Kiro 不吐思考** |
| `Connection error` | 连不上（多为 ah+claude 404 路径错）| 配置错，不是网络 |
| `429 Upstream rate limit exceeded` | 上游账号池被限流 | 临时拥堵，等几分钟 |
| `502 Upstream access forbidden` | 上游账号被官方封/凭证失效 | ⚠️ 账号级，等不好，池子在死 |
| `ContextWindowExceeded` | 上下文超窗口（ah/deepseek-v4.1-flash 声明 256K 实际装不下）| 换小上下文或压缩 |
| `missing field tool_call_id` | agnes 吐空 id 工具调用污染会话 | 补 id（见 1.2）|
| `pi-ai stream idle timeout after 300000ms` | 压缩请求发出后上游 5 分钟没吐 token | 上游挂流，压缩死等超时 |

## 6. 铁律 / 血泪教训（务必遵守）

1. **绝不在 DSH 进程运行时重签 / 改其文件**：曾因 codesign 被打断导致 DSH 异常重启 → auto-continue 云端无限重试 → 烧掉约 3 万元。改配置前必须**完全退出 DSH**，改完重启才生效（DSH 退出时会回写配置，运行中改会被覆盖）。
2. **校准系数 ≈ 1.96 字节/token**，会话日志是多帧 zstd，**首帧必须正好 1 行会话头**；改内容只能重压含改动行的帧，单帧压缩会破坏会话（`corrupt Zstandard session log: first frame is not exactly one header line`）。
3. **我的 Bash shell 自带 `HTTPS_PROXY=http://127.0.0.1:12450`** → 测「直连」必须显式 `--noproxy '*'`，否则假象。
4. **DSH 被杀后清锁**：`~/Library/Application Support/dsh-desktop/Singleton{Lock,Cookie,Socket}`。
5. **agnes-3.0-flash 是畸形工具调用（空 id/name）的已知来源** —— 会话污染先查它。
6. **不要用中转站（vankit）当主力**：超卖池子，断流/限流/封号是常态。免费且稳的只有 agnes 直连；要 GLM-5.3 走官方 API。
