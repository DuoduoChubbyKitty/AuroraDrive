## 6. 报告给 Lead 的发现（S7 不自己改）

S7 的扫描模式是 `/Users|/Volumes`（个人路径）。下列**绝对路径**不在该模式内，S1–S6 未动，但与「拷到别的路径还能不能跑」相关，交 Lead 定夺：

### 6.1 `python3.11` 绝对路径（训练功能）
```
$ grep -n 'python3.11' Sources/AuroraDrive/App/AuroraDriveApp.swift
6063:    /// 一键训练：拉起 python3.11 训练脚本（只训控制模型）
6075:        proc.executableURL = URL(fileURLWithPath: "/usr/local/bin/python3.11")
$ ls -la /usr/local/bin/python3.11
lrwxr-xr-x  1 root  wheel  73 May  3 02:06 /usr/local/bin/python3.11 -> ../../../Library/Frameworks/Python.framework/Versions/3.11/bin/python3.11
$ uname -m
arm64
```
- **现状**：硬编码 `/usr/local/bin/python3.11`。本机（arm64）是 Python.org 官方安装的软链，存在。
- **风险**：换到没装 Python.org 3.11 的机器（如纯 Homebrew 环境、或 Intel 老机）→ **一键训练按钮会失败**（`/usr/local/bin/python3.11` 不存在）。
- **影响范围**：仅「一键训练」功能（B4/B5 同函数 `startTraining()`），不影响主程序启动/推理/自检。
- **建议（供 Lead 判断，S7 不改）**：可仿 B6 的做法，`AURORA_PYTHON` 环境变量优先 + `which python3.11` 回退 + 失败明确报错。优先级低于 B1–B6（那些是必挂，这个只在特定机器+用训练时挂）。

### 6.2 `aurora-priority.sh` 绝对路径（性能提权器）
```
$ grep -n 'aurora-priority' Sources/AuroraDrive/Core/PrioritySetup.swift
12://    1) 安装 /usr/local/bin/aurora-priority.sh（root 常驻循环）
25:    static let scriptPath = "/usr/local/bin/aurora-priority.sh"
$ ls -la /usr/local/bin/aurora-priority.sh
-rwxr-xr-x  1 root  wheel  185 Sep 26 13:15 /usr/local/bin/aurora-priority.sh
```
- **性质**：这是**部署目标路径**（root 守护脚本的安装位置），不是源码树引用。`PrioritySetupManager` 会用 sudo 把脚本**写到**这个系统位置，然后 LaunchDaemon 拉起它。
- **判定：合理用法，不改。** `/usr/local/bin` 是 macOS 系统 daemon 脚本的标准位置，跨机器一致（不像 `/Users/dupi` 因人而异）。拷项目到别的路径不影响这个——它是写出去的，不是读项目里的。

### 6.3 其他系统绝对路径（合理用法，记录在案，不改）
- `/dev/bpf*`（`BPFSetup.swift:28,46`）—— BPF 设备文件，系统设施。
- `/usr/bin/route`、`/usr/sbin/netstat`、`/bin/netstat`（`CoordinateCapture.swift:976,987`）—— 系统命令。

- `NSHomeDirectory()` / `homeDirectoryForCurrentUser`（多处）—— 用户主目录，Apple API，机器无关。

这些都是系统标准位置，**合理用法，不改**。
