# 06 · 人机共驾与 RL 训练管线

> 本文描述 AuroraDrive V3 的**人机共驾数据 → 强化学习微调 → 回灌 → 导出部署**整条链路。
> 定位：这是「真训完 → 能上线」之间那条此前缺失的桥的**设计说明 + 可运行脚手架**，
> 不是「已经训完了」的成果汇报。真正的 BC/PPO 训练必须在**云端 GPU** 上跑，本机
> （任何本地 Mac）**禁止训练、禁止推理**；本机只做文本编辑、加载校验、键对齐 dry-run
> 这类只读动作。

## 一、为什么需要这条管线（缺口背景）

V3 主模型是「端到端 + 输出头」的架构：视觉骨干与时序主干产出定长 `state_token`，再由
`output_head` 的三把小分类头（`vertical` 纵向 W/NONE/S、`horizontal` 横向 A/NONE/D）和一组
安全头（handbrake/brake/confidence/risk 等）给出决策。原来的训练路径到此为止：训出一个
完整 checkpoint，然后拿去导出 CoreML 部署。

人机共驾 RL 想做的事，是**在真人接管的那些帧上，把两个决策头再教一遍**——让模型学会「这
个弯该不该拐、该不该给油」。但 RL 训练脚本（`tools/v3_rl/train_rl.py`）出于安全和体积考虑，
**只保存可训练的那几把小头**（纵向头、横向头、以及 PPO 用的价值头 value），键名形如
`vertical.weight` / `horizontal.weight` / `value.*`。它并不产出一份完整的、能被导出脚本
接受的 checkpoint。

导出脚本（`tools/v3_exp/export_v3_checkpoint_int4.py`）要的则是一份**结构严格匹配**的完整
checkpoint。把「只有几把小头」的 .pt 直接喂给它，`strict=True` 加载会当场失败。这就是缺口：
**训完的头权重，回不到完整模型里，也就走不到导出部署**。本文档配套的
`tools/v3_exp/fold_rl_heads.py` 就是把这一环补上的脚本——把头权重折回完整 checkpoint，
之后一切照旧走现有导出链路。

## 二、完整数据流（一张图看全）

```
【采集】codrive.csv（9 列逐帧共驾标注）+ controls.csv + frames/
   │
   ▼
【特征缓存】features.extract_all → 每个 clip 一个 .npz（state_token + 行为策略概率）
   │
   ▼
【奖励】reward.py：逐帧稠密奖励 + 人类评分回填 + 逐 episode GAE（不跨 clip 泄漏）
   │
   ▼
【训练·BC】train_rl.py --stage bc （只在人类帧上做模仿学习）
   │        --out-ckpt 输出 head_state_dict（BC 冷启动头）
   ▼
【训练·PPO】train_rl.py --stage ppo --init-from <BC 头.pt>
   │        （AI 帧走 PPO 策略梯度 + 人类帧继续模仿，λ 衰减）
   │        --out-ckpt 输出 head_state_dict（最终头）
   ▼
【评测】eval.py 过弯指标（仅在人类帧上算：犹豫率 / 刹停率 / 纵向横向一致率）
   │
   ▼
【回灌】fold_rl_heads.py：把头权重折回完整 V3 checkpoint
   │        （vertical./horizontal. 写回；value.* 是 critic，跳过不写）
   ▼
【导出部署】export_v3_checkpoint_int4.py → fp16 / INT4 → .mlpackage / .mlmodelc
            → InferenceEngineV3 接入
```

一句话概括每一步的因果：**采集**记下「模型当时想做什么、人到底做了什么」；**特征缓存**把
画面固化成模型真正消费的那枚 `state_token`（外加原模型的行为概率，供 PPO 算重要性比）；
**奖励**把「开得好不好」变成逐帧标量；**BC**先让新头学会模仿人；**PPO**再让新头在 AI 帧上
按奖励往好里调、同时不忘人；**评测**用「敢不敢过弯」这类业务口径校验；**回灌**把学到的小头
装回完整模型；**导出**才是部署。

## 三、逐环节详解与文件职责

### 3.1 采集：codrive.csv 的 9 列

共驾采集只在开启共驾开关时生效；关闭时整条链路不写 `codrive.csv`，行为与引入该功能前逐字
一致（向后兼容）。写入逻辑在 Swift 侧的精简录制引擎里，训练端只负责读。`codrive.csv` 与
同目录的 `controls.csv` 的 `frame` 列**逐帧对齐**：`controls.csv` 才是硬契约（画面 + 8 个
按键 + 待离线回填的 speed_kmh），`codrive.csv` 是旁路标注，某帧缺行可被忽略。

9 列含义如下：

| 列名 | 含义 |
|---|---|
| `frame` | 帧号，与 `controls.csv`、`frames/00000.jpg` 一一对应（训练端按它关联） |
| `source` | 本帧来源：`AI`=模型在开；`HUMAN`=人类接管在开（由**真人物理按键触发的接管信号**决定，绝不用「物理键是否等于 AI 意图」反推） |
| `took_over` | 本帧是否发生人工接管（1/0）。为 1 时 PPO 侧按强负奖励处理，并把人类动作当作模仿标签 |
| `ai_vertical` | 模型**本帧想下发**的纵向分类（0=W / 1=NONE / 2=S）；不可用时记 -1。即使人类接管也照记，用于分析「模型想做 vs 人类实际做」 |
| `ai_horizontal` | 模型**本帧想下发**的横向分类（0=A / 1=NONE / 2=D）；不可用时 -1 |
| `ai_shift` | 模型本帧想下发的 shift 键位（0/1） |
| `ai_space` | 模型本帧想下发的 space 键位（0/1） |
| `collided` | 本帧是否碰撞/剧烈减速（1/0），由离线或上层视觉判定，缺省 0（不臆造） |
| `lane_offset` | 视觉车道横向偏置（负=偏左、正=偏右、±1=出界），定点 4 位小数写入，缺省 0（未知按居中处理） |

要点：`source` / `took_over` 的**唯一真源**是真人接管信号，`ai_*` 只作诊断。这条红线是为了
避免把「AI 正常开、人没动」误判成人类接管（键盘监听会过滤掉程序注入的 AI 按键，若用键位比对
推断接管会大面积误判）。

### 3.2 特征缓存：`features.py` 的 `extract_all`

`features.extract_all` 是「录制数据」与「训练循环」之间诚实的一层桥。它加载**真实的、已训好
的 V3 checkpoint**（严格加载），冻结视觉骨干，把每个录制帧跑一遍，取到 stage-2 的
`state_token`（256 维）——这正是真实 V3 输出头消费的那枚向量。同时它把**原模型在这一帧上的
纵向/横向概率**也存下来，供 PPO 算重要性比时作分母。

> **重要限制（诚实标注）**：这枚「原模型概率」是**基础 checkpoint 的 softmax 输出**，并**不是**
> 采集时某个随机行为策略真正采样出该动作的 log-prob。部署端是 argmax（确定性）+ 控制覆盖，
> 并不按这个 softmax 采样。所以后续 `--stage ppo` 的比值 π_θ/π_0 只衡量「新头相对基础模型
> softmax 漂移了多少」，**不构成标准 on-policy PPO 的合法离策略修正**——请把 `--stage ppo`
> 当作**在录制 AI 帧上的离线近似微调**，而非理论严格的 PPO。要得到严格 PPO，必须在采集时用
> 随机行为策略记录 (action, logprob, 模型/版本, 覆盖标志)，该采集管线目前**尚未实现**。

另外两点强调：一是训练跑在**真实的 V3 表征**上，不是手搓的运动学特征；二是 `state_token`
只由图像 + 车道 + 检测 + 上一帧车辆状态构成，**当前帧动作不会泄漏进输入**。另，缓存会记录每行
的**真实帧号**（`frame_ids`），下游按真实帧号而非压缩序号去查 `codrive.csv`/时间戳，避免数据集
跳帧后标签错位。产出是缓存目录下每个 clip 一个 `.npz` 加一份 `manifest.json`，已缓存的 clip 会
跳过重算。

### 3.3 奖励：`reward.py`

`reward.py` 是纯 numpy、无 I/O、完全可单测的奖励整形模块。它有三条硬约束：**不依赖世界坐标**
（只用云端能拿到的信号：速度表 OCR、碰撞/急减速、视觉车道偏置、接管）；**人类评分回填要按真实
帧时间戳回溯**到人所评判的那些帧上（不能用「按键时刻四舍五入到帧号」那种会错记到未来帧的做法，
越界按键直接丢弃）；**GAE 逐 episode 计算**，独立 clip 之间绝不能互相泄漏奖励。

奖励由「逐帧稠密项」（速度/卡死/碰撞/急减速/车道偏置）加「接管强负项」加「人类评分项」组成，
再用每段的价值估计算 GAE 得到优势与价值目标，供 PPO 使用。

### 3.4 训练脚本：`train_rl.py`（BC 冷启动 + PPO）

`train_rl.py` 是这条管线唯一的训练入口，它把特征缓存与 `codrive.csv` 合起来，按帧切成 AI 帧 /
人类帧 / 未知帧（未知帧两边都不用），逐 episode 算奖励与 GAE，然后分两个阶段训：

- **`--stage bc`**：只在**人类帧**上做模仿学习（对纵向、横向两把头的交叉熵）。这是冷启动，
  让新头先学会「人类是怎么开的」。
- **`--stage ppo`**：接在 BC 之后（用 `--init-from <BC 阶段 --out-ckpt 产物>` 载入 BC 头权重），
  在 **AI 帧**上走裁剪策略梯度、在 **人类帧**上继续做模仿（模仿项权重 λ 按回合衰减）。
  关键安全语义：人类抢救动作**永远不进策略梯度项**，所以接管的强负奖励不会把人类动作的概率
  压下去。

> **PPO 语义限制（见 3.2 说明）**：`--stage ppo` 的 `old_probs` 来自基础模型 softmax，不是
> 采集行为策略的 log-prob，因此它是一个**离线近似微调**，不是严格 on-policy PPO；代码在启动
> 时会打印该警告。动作标签取自 `controls.csv`（实际按下的键）；对部署驱动产生的帧它等于执行
> 动作，但离线重放无法完美还原控制覆盖，真正可靠需要单独的「实际执行动作」通道（尚未采集）。

两个阶段都会在结尾把 `policy.head_state_dict()` 保存成 `.pt`（含 `vertical.*` /
`horizontal.*` / `value.*`，以及 stage/frames/history 元信息），这就是「RL 头产物」，也是下一
步回灌的输入。训练只在云端 GPU 上跑，本机不跑。

配套：`policy.py` 定义 `TorchPolicy`（冻结整个 V3、只解冻纵向/横向两把头 + 一个价值头，并提供
头权重的存取方法）；`run_tests.py` 是这套 RL 代码的单测总入口（带断言数下限门禁）。

### 3.5 评测：`eval.py`

`eval.py` 回答的是业务问题「**模型敢不敢过弯**」。它只在**人类帧**上算指标：人类打了方向但
策略说 NONE 的**犹豫率**、人类打方向但模型给 S（刹车/停车）的**刹停率**、以及纵向/横向与人类
的**一致率**。所有输入都做长度/取值范围校验；没有转弯帧时相关比率报 N/A 而不是误导性的 0%。

### 3.6 回灌：`fold_rl_heads.py`（本次新增的桥）

这就是补上缺口的那一环。它把 RL 头 `.pt` 里的权重折回一份**完整的、可部署的** V3 checkpoint：

- 只回灌部署会消费的两把决策头：`output_head.vertical` 与 `output_head.horizontal`（各 weight +
  bias，共 4 个张量）；
- `value.*` 是 PPO 的 critic（价值基线），**不参与部署**，只用于训练期优势估计，这里跳过并打印
  提示，不写进 checkpoint（写进去只会在导出图里多一个没人用的张量）；
- 骨干、trunk 和其余安全头一律不动，保持原 checkpoint 字节不变。

脚本复用导出脚本的 `load_trained_model` 来严格加载原始 checkpoint，确保「折回」和「导出」对
checkpoint 的理解完全一致；随后逐键核对：键是否存在、形状是否一致，任何**键缺失 / 形状不符 /
未知前缀**都**带键名**报错并以非零码退出，绝不吞异常。它原样保留原 checkpoint 的**训练态**
state_dict（骨干多分支权重不折叠——导出脚本的契约就是「先按训练态 build → strict 加载 → 再
reparameterize」），只替换那 4 个 Linear 头键后整体存盘。最后还会把折叠后的完整 state_dict
再 strict 加载进一个全新模型，证明「写出去的这份也能被下游接受」。

参数：`--ckpt`（原 V3 checkpoint）、`--head-ckpt`（RL 头 .pt）、`--out`（输出完整 checkpoint）、
`--dry-run`（只校验键对齐、不写盘）。本机只允许跑 `--dry-run`（只 load + 键对齐校验，不 forward、
不训练）；生成真实可部署 checkpoint 的动作应在云端或明确允许写盘的机器上做。

用法示例：

```
# 键对齐 dry-run（本机可跑）
/usr/local/bin/python3.11 tools/v3_exp/fold_rl_heads.py \
    --ckpt models/aurora_v3_best_ep13_20261115.pt \
    --head-ckpt /path/to/rl_head.pt \
    --out /tmp/aurora_v3_rl_folded.pt --dry-run

# 真正落盘（云端执行）
/usr/local/bin/python3.11 tools/v3_exp/fold_rl_heads.py \
    --ckpt models/aurora_v3_best_ep13_20261115.pt \
    --head-ckpt /path/to/rl_head.pt \
    --out models/aurora_v3_rl_folded.pt
```

### 3.7 导出部署：`export_v3_checkpoint_int4.py`

折回得到的完整 checkpoint 直接走既有的导出脚本：`--stage load` 先做严格加载体检，`--stage fp16`
导 fp16 基线，`--stage int4` 在 fp16 上做 4-bit palettize（纯权重 k-means，配逐层敏感度与真实验证
集漂移评估），最终得到 `.mlpackage`，必要时编译并原子替换部署目标 `.mlmodelc`，由
`InferenceEngineV3` 接入。导出同样必须在允许运行模型的环境（云端）执行——本机禁止真实推理与
量化。

## 四、每个文件的职责（一句话清单）

| 文件 | 一句话职责 |
|---|---|
| `tools/v3_rl/features.py` | 加载真实 V3、冻结骨干，把录制帧固化成 `state_token` + 行为策略概率并缓存成 `.npz` |
| `tools/v3_rl/reward.py` | 纯 numpy 的逐帧奖励整形 + 人类评分按时间戳回填 + 逐 episode GAE，无世界坐标依赖 |

| `tools/v3_rl/train_rl.py` | 唯一训练入口：`--stage bc` 人类帧模仿、`--stage ppo`（`--init-from` 接 BC）AI 帧 PPO + 人类帧模仿，产出头权重 `.pt` |
| `tools/v3_rl/eval.py` | 只在人类帧上算「敢不敢过弯」指标（犹豫率/刹停率/一致率），纯函数可单测 |
| `tools/v3_rl/run_tests.py` | 跑全部 v3_rl 单测并强制断言数下限门禁 |
| `tools/v3_exp/fold_rl_heads.py` | 把 RL 头权重（vertical/horizontal）折回完整 V3 checkpoint，跳过 value critic，`--dry-run` 只校验键对齐 |
| `tools/v3_exp/export_v3_checkpoint_int4.py` | 完整 checkpoint → CoreML fp16/INT4，含严格加载与量化漂移评估 |
| Swift `LeanRecordEngine.swift` | 采集落盘：写 `controls.csv` 与 `codrive.csv`（共驾逐帧标注），S/E 两段逻辑同帧对齐 |

（Swift 侧文件名以当前分支为准；采集触发与自检在 `LeanRecordSelfTest.swift` 等文件中，行号会漂移，
此处只给文件名定位。）

## 五、边界与诚实声明（务必读）

- **本交付 = 可运行脚手架 + 文档，不等于「已训完」**。本次没有、也不允许在本机跑 BC/PPO 训练，
  没有跑真实推理与量化。`fold_rl_heads.py` 的 `--dry-run` 用的是**合成的头权重 fixture**（按
  `train_rl` 真实产出的形状构造：纵向/横向各 weight+bias，value critic 若干），对真实 checkpoint
  只做了 load + 键对齐校验，**不 forward、不训练**。真实头权重要等云端训练产出后才有。
- **真训练在云端 GPU**：BC/PPO 与 INT4/CoreML 导出都需要能跑模型的环境；本机（本地 Mac）**禁止
  训练与推理**，只做只读校验。
- **接缝口径**：`fold_rl_heads.py` 与 `export_v3_checkpoint_int4.py` 对 checkpoint 的理解严格一致
  （同一套 `load_trained_model`），这是「折回→导出」能无缝衔接的前提。
- **行号免责**：文中涉及文件名处均以 `fix/codrive-rl-phase0` 分支为准；任何「行号/行数」若被
  后续改动刷新，请以当前分支源码为准，文档不承诺坐标稳定。
- **缺失 codrive 的语义必须显式**：一个 clip 没有 `codrive.csv` 可能是「纯人工示范」，也可能是
  「共驾旁路录制失败被降级成普通录制」。训练端**不得**把它一律当人类示范。因此 `train_rl.py`
  提供 `--require-codrive`：共驾训练时缺 codrive 直接报错（不静默当人类数据）；只有显式声明是
  纯示范数据时才按「整段人类」处理。
- **未做同源/版本指纹绑定（已知缺口）**：缓存 `.npz`、头权重 `.pt`、fold 基座三者目前只做形状/
  键对齐，**未**记录并强校验「基座 checkpoint 指纹 + 预处理版本 + 数据 schema」。用结构相同但
  权重不同的 checkpoint 也能通过，特征空间却不一致。上线前应补：缓存与头产物都带基座/数据指纹，
  失配即重建或拒绝。（Codex round-2 #5，本次未做，登记为遗留。）

## 六、端到端命令参考（云端执行，非本机）

下面给出一次完整流程的命令骨架，**仅供云端 GPU 机器参考**；本机不执行任何训练/推理/导出。
注意：`features.py` 与 `eval.py` 目前**是库模块、没有自己的 CLI**（`extract_all` / 评测函数由
Python 代码直接调用，实践中在训练脚本或云端笔记本里调起）；真正带 argparse CLI 的是
`train_rl.py`、`fold_rl_heads.py`、`export_v3_checkpoint_int4.py`。命令以当前分支的 `argparse`
定义为准，本文只给流程骨架，不承诺每个参数名与默认值长期不变。

```
# 0) 特征缓存（库调用；会跑真实 V3，需 GPU/推理环境）
python -c "from tools.v3_rl.features import extract_all; from pathlib import Path; \
extract_all(Path('data/lean_clips'), Path('models/aurora_v3_best_ep13_20261115.pt'), Path('/tmp/v3_rl_cache'))"

# 1) BC 冷启动（云端 GPU；train_rl 有 CLI）
python tools/v3_rl/train_rl.py --cache-dir /tmp/v3_rl_cache --ckpt models/aurora_v3_best_ep13_20261115.pt --stage bc --epochs 5 --out-ckpt /tmp/rl_bc.pt

# 2) PPO（接 BC 头；云端 GPU）
python tools/v3_rl/train_rl.py --cache-dir /tmp/v3_rl_cache --ckpt models/aurora_v3_best_ep13_20261115.pt --stage ppo --init-from /tmp/rl_bc.pt --epochs 8 --out-ckpt /tmp/rl_ppo.pt

# 3) 头权重回灌（可先加 --dry-run 只做键对齐校验）
python tools/v3_exp/fold_rl_heads.py --ckpt models/aurora_v3_best_ep13_20261115.pt --head-ckpt /tmp/rl_ppo.pt --out models/aurora_v3_rl_folded.pt

# 4) 导出（云端）：--stage all 只做「导出 + 量化」，不部署
python tools/v3_exp/export_v3_checkpoint_int4.py --ckpt models/aurora_v3_rl_folded.pt --stage all

# 5) 真正部署（可选，需 CoreML 编译/验证环境的 macOS）：必须显式给 --modelc 目标目录，
#    否则 export 会明确跳过部署（会打印「未提供 --modelc，跳过部署」）
python tools/v3_exp/export_v3_checkpoint_int4.py --ckpt models/aurora_v3_rl_folded.pt --stage all --modelc models/v3_int4.mlmodelc
```

> **注意**：仅跑 `--stage all`（不带 `--modelc`）**不会**把新模型部署到运行端——导出脚本在没有
> 部署目标时会明确跳过部署。部署还需要在具备 CoreML 编译与验证能力的环境里指定目标，并在运行端
> 验证加载的是新模型。

> 评测环节（`eval.py`）同上，是库函数（如 `evaluate_predictions` / `evaluate_clip_with_policy`），
> 在训练/评估脚本里直接调用，无独立 CLI。
