# 07 · 在线训练接入设计（state_token 加速器 + digest 安全）

> 本文回答一个问题：V3 主模型每一帧算出的 256 维 `state_token`，怎样接进
> `DriveState.tick` 的驾驶回路，让策略头（PolicyHead）边跑边采样、观测奖励、
> 交给 `OnlineTrainer` 收集并在 episode 边界训练——同时**默认不真按键**，出不了事故。
>
> 范围界定（必须先说清）：本文是**设计方案**，配套一个**已实现的加速器**
> （`StateTokenAccelerator`，见第二节）。把 `tick` 真正改成「策略头驱动」的那一步
> **尚未实施**，按团队纪律应在评审通过后单独做成一个改动，不要在本文落地时顺手改
> 生产 `DriveState.tick`。
>
> 写作约定：与 06 篇一致，**不写「文件:行号」式断言**——行号会随代码演进漂移，
> 写死在文档里就是给自己埋过期断言。文中点到的类型名、方法名、环境变量均以**当前
> main 分支实测**为准，仅供定位。
>
> ⚠️ 交付范围（如实界定，勿过度宣称）：**本次交付 = 在线训练"底座"**——可训练的
> Swift PPO 策略头、state_token 加速器、在线 collect/GAE/周期训练循环，均以合成数据
> 自检验证正确性；**但把 `DriveState.tick` 真正改成「策略头驱动 + 实时训练」的生产接线
> 尚未做**（本文件第二部分给出方案）。因此当前**不等于"已经边玩边训在跑"**，生产接线
> 是评审后的下一步单独提交。
>
> 关于在哪训练：用户已明确「训练就在本机 Mac 上跑」——约束的是**代理不许擅自乱跑**、
> 不是**程序不允许**。所以本方案以「本机即可训练」为前提设计（Swift 核心，Accelerate 加速），
> 不再要求必须上云端。是否上云端由用户决定，代码本身两者都支持。

## 一、为什么需要这个接入（缺口）

现在生产用的 `InferenceEngineV3` 只吐**决策头**：纵向 `vertical[3]`、横向
`horizontal[3]`、四个安全头（handbrake/brake/super_brake/ultimate）、confidence、risk。
它把内部时序主干算出的 **256 维 `state_token`** 用在了自己内部解码上，但**没有把它暴露
出来**。

而在线 RL 的训练接口 `OnlineTrainer` 恰恰要的就是 `state_token`：它的 `PolicyUpdatable`
协议里，`forward(stateToken:)` 吃的就是这个 256 维向量，`RLTransition.stateToken` 存的也是它。
换句话说，**决策链路不缺，缺的是「把 state_token 从模型里拿到手并逐帧喂给训练器」这一步**。

这条链上有两个断点：

1. **模型不吐 state_token**：生产 `v3_int4.mlmodelc` 的输出只有 8 路决策头。要拿到
   state_token，需要一份**额外输出 `state_token[256]`** 的导出模型——由 A 域
   `tools/v3_exp/export_state_token_model.py` 产出。
2. **引擎不暴露 state_token**：即便模型吐了，`InferenceEngineV3` 的公开接口也只到
   `lastDecision`。与其去改这个被评审反复加固、承载全部生产安全的引擎（风险高、牵一发动全身），
   不如**新增一个旁路加速器**专门吃这份 state_token 模型。

第一步的落点就是 `StateTokenAccelerator`；第二步的落点就是本文第三~五节描述的 tick 接入。

## 二、加速器：`StateTokenAccelerator`（已实现）

`StateTokenAccelerator` 是一个**纯推理封装**：加载带 `state_token` 输出的 CoreML 模型，
跑一帧，返回 `(stateToken:[Float](256), vLogits:[Float](3), hLogits:[Float](3))?`。
它**不按键、不驱动控制、不写 DriveState**——只是在线循环里「取 state_token」的那一步。

### 2.1 输入契约：复用，不另抄

六个输入（`image_hi` / `image_lo` / `lane` / `dets` / `det_mask` / `vehicle_state`）的名字、
形状、归一化口径**全部复用** `V3InputContract` 与 `V3FrameRingBuffer` 的既有实现：

- 形状常量取自 `V3InputContract`（双分辨率 24 帧窗口：3 帧高清 224×384 + 21 帧低清 112×192）。
- 帧窗口的「新→旧」取法直接用 `V3FrameRingBuffer.hiWindow()/loWindow()`，与训练侧口径一致。
- 图像预处理直接调 `InferenceEngineV3.renderNormalized`（`/255` 归一化 + RGB 平面顺序）。
- `vehicle_state` 按训练口径，仅 `[6]` 写上一帧 A/D（A→−1 / D→+1 / 其余 0）。

**为什么强调「复用而不另抄」**：V3 的输入契约里每一个数字手抄错一次，都会造成
「Swift 传得进去、但模型算出来是垃圾」的**静默错误**（CoreML 对形状错误并不总是报错）。
复用同一处常量，就把这类错误从源头掐掉。

### 2.2 两个方向不同的 dtype 纪律（关键反例）

这是本加速器最容易踩、也是最有价值的一条纪律，直接取自 `InferenceEngineV3` 文件头
记录的实测反例：

- **输入必须 `.float16`**：模型六路输入是 `compute_precision=FLOAT16` 导出的。同一全零输入，
  用 float32 与 float16 两种 `MLMultiArray` 推理，输出**完全不同**（vertical
  `[1.05,3.61,1.57]` vs `[-0.85,0.76,0.15]`），而 CoreML **不报错**——照抄 float32 写法会静默中招。
  所以加速器写输入用 `dataPointer.assumingMemoryBound(to: Float16.self)`。
- **输出必须按真实 dtype 读**：导出模型的**输出** dtype 可能是 fp16 也可能是 fp32（取决于
  导出时的 compute_precision）。若照抄输入的 fp16 指针去读一个 **fp32** 输出，会把每 4 字节
  当 2 个 fp16 解释 → 维度翻倍、全是垃圾/NaN。所以读输出**一律走 `MLMultiArray[i].floatValue`**，
  按数组真实 dtype 自动转换——这是唯一与 dtype 无关的正确读法。

一句话记法：**输入用 fp16 指针写，输出用 `.floatValue` 读，两者绝不混用。**

### 2.3 输出解析：容忍 A 域命名未定

`stateTokenAndLogits` 对输出名做**双保险**解析，避免「A 域导出名和 B 域约定名对不上」时
无谓地跑不起来：

- state_token：先按约定名（默认 `state_token`，可配），否则找模型输出里**唯一**长度=256 的输出。
- logits：优先 `vertical[3] + horizontal[3]`（与 V3 决策头同名）；兼容 A 域若合并成单路
  `logits[6] = [vertical(3), horizontal(3)]` 的布局。

任一路找不到时**不崩溃**，返回 nil 并把「约定名、可用输出名」写进 `failureReason`，
便于上层如实上报。

### 2.4 路径可配 + 缺文件清晰降级

模型路径优先级：`AURORA_STATE_TOKEN_MODEL` 环境变量（绝对路径）→ 缺省
`models/v3_state_token.mlmodelc`。输出名可用 `AURORA_STATE_TOKEN_OUTPUT_NAME` 覆盖。
计算单元默认 `.cpuAndNeuralEngine`，`AURORA_COMPUTE_UNITS` 可覆盖（复现跨单元数值一致性）。

**模型文件不存在时返回 nil 并清晰说明，不崩溃**——见 2.5 自检的 SKIP 行为。

### 2.5 自检 `-rl-accel-selftest`（不假装通过）

命令行自检挂在启动入口、**UI 单实例锁之前**分发（与 `--v3-selftest` 同处），因此不需要
登记进 `oneShotFlags`。行为分两种，都如实打印：

- **模型在**：用生产同款预处理造一帧真实输入 → 压入 24 帧缓冲 → 跑一帧 → 断言
  `stateToken 维度 == 256`、`非全 NaN`（并附带断言 vLogits/hLogits 维度=3）。任一不过 → 退出码 1。
- **模型文件不存在**：打印 `SKIP：<路径> 不存在` + 一句说明「该模型由 A 域导出脚本产出，
  产物就绪后重跑即可；本次未做任何断言，不冒充通过」，退出码 0（SKIP ≠ FAIL，也 ≠ PASS）。
- **模型文件存在但加载/推理失败**（损坏/权限/格式错）：打印 `FAIL：模型文件存在但加载失败 —— <原因>`，
  退出码 1。**绝不把它误判成 SKIP**——那会让坏模型静默变绿，是假绿陷阱。

这条 SKIP 是刻意的：**A 域产物尚未落盘时，自检必须明说「没测」，而不是给一个假的绿。**
把「没测（文件不在）」与「测挂了（文件在但坏）」两种退出语义分清楚，才不会两头都骗人。

### 2.6 返回值不吞 NaN

`stateTokenAndLogits` 只校验维度，原样返回模型算出的数值（含可能出现的 NaN）。这是刻意的：
判定 NaN 是**调用方**的事——自检据此断言「非全 NaN」；在线循环必须**丢弃**含 NaN 的帧
（见 4.3 护栏）。若加速器自己把 NaN 帧换成 nil，自检就分不清「模型吐了 NaN」与「读取失败」，
诊断信息就丢了。

## 三、在线循环如何挂进 `DriveState.tick`

设计目标：在**不改动现有控制安全链**的前提下，给 `tick` 加一条**旁路观测链**——它只读取
每帧的 state_token 并喂给训练器，最终仍复用既有 `applyCommand` / `ControlEngine` 注入按键。
下面按一个 tick 内的执行顺序叙述（这是设计，不是已落地的代码）。

### 3.1 每 tick 的六步

**① 取 state_token**
`tick` 采集到当前帧后，先走既有 `V3FrameRingBuffer` 入窗，取 `hiWindow()/loWindow()`，
调 `StateTokenAccelerator.stateTokenAndLogits`。得到 `(stateToken, vLogits, hLogits)`；
返回 nil（模型缺失/推理失败/维度错）时**本帧跳过在线链**，生产驾驶链不受影响。

**② PolicyHead 采样动作**
把 `stateToken` 交给 `OnlineTrainer.sampleAction(stateToken:)`。它内部用**推理快照**做
`forward → stochasticSample`，返回 `(action, logProbV, logProbH, value)`。注意这里用的是
**策略头自己采样的动作**，不是生产 V3 决策头的动作——这正是「让策略头学着开」的采样来源。

**③ 经 ControlEngine 注入（默认 digest 消化，不真按键）**
把采样出的 `RLAction(vClass, hClass)` 映射成既有的 `ControlCommand`（steer/throttle/brake），
再交给 `applyCommand` → `ControlEngine.press/release(.steerLeft/.steerRight/.throttle/.brake…)`。
映射口径与 V3 决策头一致：纵向 `W→throttle` / `S→brake` / `NONE→松`，横向 `A→steerLeft` /
`D→steerRight` / `NONE→松`。

> **安全前提（硬性）**：此路径要求 `ControlEngine.digestMode == true`。消化模式下
> `press/release` 除最后一步 `CGEvent.post` 外**行为逐字一致**——计数照涨、UI 照亮，
> 但事件不离开本进程，既不会真的按键、也不会打扰系统/游戏。在线采集**必须**在 digest 下跑
> （开关细节见 4.1）。这也是为什么把「保留原按键决策」写在这里：**生产决策链不变，
> 在线链只是在 digest 镜像上演练**。

**④ 观测奖励信号**
按 `OnlineTrainer.collect` 需要的信号收集：`speedKmh / speedValid`（速度 OCR 读数，
引擎模式下用回传车速）、`collision`（碰撞判定）、`laneOffset`（车道偏置）、`tookOver`
（本帧是否人工接管）。这些信号当前代码里都已存在——共驾录制快照
（`captureLeanSnapshot` 写 codrive.csv 时用到的就是这四类：AI 动作 / 是否被接管 / 碰撞 /
车道偏置），在线链直接复用同一批观测量即可，无需另造一套传感器。

**⑤ `OnlineTrainer.collect`**
把**采样快照**（`stateToken / 实际采样动作 vClass,hClass / 采样时的 logProbV,logProbH / 采样时的 value`）
连同 `tookOver / speed / collision / laneOffset / isTerminal` 交给 `collect`。**关键**：old 概率/value
必须是**动作被采样同一时刻**的快照原样传入，**绝不**在 collect 内二次 forward 重新取（否则动作来自 π0、
old 来自已发布的 π1，ratio 失真）。collect 内部**逐帧算奖励**（与离线 `reward.py` 同语义：speed/stuck/
collision/decel/lane/takeover 六项，跨帧维护 prev_speed），组成 `RLTransition` 入缓冲；到量
（`trainEvery`，缓冲截断时扣下末条、用其 value 作 tail bootstrap）或真正 episode 结束才触发 `flush`。

**⑥ 训练边界（三种必须区分，别混为一谈）**
- **真终止**（一局结束 / 主动复位）：`isTerminal=true`，本帧为终局，GAE 不向后续 bootstrap。
- **缓冲截断**（到 `trainEvery` 上限但 episode 未结束）：**不是**终止——扣下末条不作训练，用它
  的 value 作 `tailBootstrapValue` 去 bootstrap 前段（`computeGAE(...tailBootstrapValue:)`），避免
  丢下一状态价值。
- **UNKNOWN 缺口**（丢帧/模型失败/非有限值）：调用 `markInvalid()`/`sealEpisode()` 封口已有轨迹
  且**不伪造 transition**；封口时**丢弃没有可靠后继的末条**（不可用 tail=0 冒充终止，否则把"观测
  缺失"当成"环境终止"、伪造价值归零监督）。
`flush` 在**后台串行队列**上跑 PPO 更新（双缓冲发布），主线程不阻塞。

**⚠️ 两种"边界"语义必须严格区分，不可混用：**
- **人工接管 = 训练终止**：`tookOver=true` 帧**不建策略 transition**（人类救援动作不是策略采样），
  −takeover 惩罚加到**上一条 AI 帧**并把该 AI 帧置为 `isTerminal=true` 收尾（视为本 AI episode 结束，
  不做 tail bootstrap）。单条 AI 帧被加罚时其 advantage 不能被归一化成 0（n==1 返回原优势），
  否则接管惩罚对 actor 失效。
- **UNKNOWN 缺口 = 丢弃末条、代理 bootstrap**：与接管不同，UNKNOWN 是观测缺失不是任务结束，
  封口时丢弃无可靠后继的末条、用其自估 value 作前缀的 tail bootstrap（不伪造归零 terminal）。

### 3.2 为什么挂在 tick 的「旁路」而不是重写决策

现有 `tick` 里所有安全机制（降级链、限速刹车、人工接管、专家模式）都挂在
`applyCommand` 这条连续量链路上。把在线链做成**旁路**——读 state_token、在 digest 上演练、
把动作喂给训练器——就能让**既有安全机制全部原样生效**，无需为在线训练单独开一条可能绕过安全
的注入路径。真正把 tick 改成「生产按键也由策略头采样驱动」是另一件事，风险高，
必须评审后单独做（见第六节）。

## 四、开关与安全护栏

在线训练是「让模型自己动手」的功能，安全护栏必须**先于功能**想清楚。以下是硬性设计要求。

### 4.1 开关（两把锁，缺一不可）

1. **`AURORA_DIGEST=1`（必须为 1 才允许在线链启动）**
   现状要说清：`ControlEngine.digestMode` 的默认值其实是**跟随 `AURORA_DIGEST` 环境变量**，
   **不设时默认 `false` = 正常注入、会真按键**。因此在线链**不能只依赖默认值**，必须在启动时
   **硬校验** `digestMode == true`；若为 false，直接拒绝开启在线训练并打印醒目告警
   （"在线训练要求消化模式，请先设 AURORA_DIGEST=1"）。这条是防事故的第一道闸。
2. **`AURORA_RL_ONLINE=1`（显式开启在线链）**
   独立的在线训练总开关，默认关。只有它开启**且** digest 开启，旁路链才在 tick 里激活；
   否则 tick 完全走原路径，零额外开销（每 tick 一个 Bool 判断）。

### 4.2 急停与接管即让位

- **急停**：复用既有 `EmergencyTakeover.shared.takeoverActive` 与 EscapeController。一旦急停/应急
  接管激活，在线链**立即停采**（不再 sample、不再 collect），并 `releaseAll()` 松掉 AI 键；
  恢复后也不自动续采，需重新显式开启。
- **接管即让位**：任何一帧检测到人工接管（`tookOver == true`），本帧标 `isTerminal=真` 的
  边界语义之外，**立刻把控制权交还既有降级链/人工**，在线链不再注入。这也符合训练语义：
  人类接管的帧正是「模型犯错」的负例，`collect` 会用高 `takeover` 奖励惩罚把它们学进去
  （`RewardConfig.takeover` 默认 10.0，是六项里最大的惩罚权重）。

### 4.3 数值与降级护栏

- **NaN/Inf 丢帧并封口**：加速器不吞 NaN（2.6）；在线链在 `collect` 前**丢弃**含非有限值的
  state_token / logits 帧，不喂给训练器（脏数据进 PPO 会污染整批梯度），并调用
  `markInvalid()` **封口**已有轨迹（切段、不跨缺口 bootstrap），避免恢复后 GAE 跨缺口传播。
- **模型/维度异常降级**：加速器返回 nil、或 stateToken 维度 ≠ 256 时，本帧跳过在线链，
  生产驾驶照常。绝不因为「训练侧没数据」而让驾驶停摆或崩溃。
- **失败不静默**：模型缺失、输出名对不上、推理异常，都要把 `failureReason` 冒泡到日志/UI，
  不能吞掉（隐蔽的失败是排查噩梦）。

### 4.4 训练在哪跑

本机在线链在 digest 下的 dry-run 只验证**接线与数值健全性**（sample/collect 能否跑通、信号
是否对齐、维度是否 256）。真正的 PPO 梯度更新，**本机即可跑**（PolicyHead 为纯 Swift+Accelerate，
不依赖云端）；用户明确「本机可训练」。是否改用云端 GPU 由用户决定——代码两者都支持，不再设
"必须云端"的前置。

## 五、「云端游戏经窗口链接」场景的接入点

有一种使用形态：游戏不在本机跑，而是通过窗口链接（远端画面经窗口呈现在本机）呈现。本设计的
接入点很干净：

- **画面来源可替换为窗口捕获，按键注入不变。**
  在线链吃的 `image` 来自采集层。把采集层从「本机游戏窗口抓屏」换成「远端窗口捕获的画面」，
  对 `StateTokenAccelerator` 与 `OnlineTrainer` **完全透明**——它们只认 `CGImage`，
  不关心这张图是本机 GPU 画的还是远端串流过来的。
- **按键注入路径不变。** 采样动作仍走 `ControlEngine.press/release` 注入到**本机窗口**；
  窗口链接层负责把本机按键转发到远端游戏。digest 消化模式同样在这一层截住 `CGEvent.post`，
  所以窗口链接下「不真按键」的安全性完全等价。
- **延迟要单独评估。** 远端串流会引入额外往返延迟，`V3` 的 24 帧窗口有 1.5 倍名义跨度的
  时间轴容差（`maxWindowSpanRatio`）。窗口链接场景下，帧到达节奏可能偏离 15Hz 训练分布，
  上线前必须实测窗口真实跨度是否仍在容差内，否则模型看到的运动尺度失真。这是**该场景特有的
  风险点**，与本机场景不同，需单独验证。

换言之：**画面是可插拔的输入源，按键注入是不可变的输出口**——把窗口链接当成另一种画面源接进来，
控制与安全逻辑一行不改。

## 六、与现有代码的边界（本文为什么这么切）

| 组件 | 本文是否改动 | 说明 |
|---|---|---|
| `InferenceEngineV3` | **不改**（只读复用契约） | 它承载全部生产安全，改动风险极高；加速器旁路复用其 `V3InputContract`/`V3FrameRingBuffer`/`renderNormalized`。 |
| `DriveState.tick` | **本次不改** | 真正把 tick 改成策略头驱动的接线属高风险改动，评审后单独做（下一节）。 |
| `AuroraDriveApp` | 由 swift-core **统一接入**（D 域不改） | 自检分发 `-rl-accel-selftest`（`args.contains` 同时认单横杠/双横杠）由 swift-core 统一加到启动入口 UI 锁之前，并把两种写法登记进 `oneShotFlags`；D 域只暴露 `StateTokenAccelerator.run()`。 |
| `StateTokenAccelerator` | **新增** | 本文配套实现，见第二节。 |
| `OnlineTrainer` / `ControlEngine` | **不改**（调用其既有 API） | 在线链只调 `sampleAction/collect`、`press/release`、`digestMode`。 |

**真正把 tick 改成「策略头驱动驾驶」的那一步，为什么必须单独做**：它会把生产按键决策从
「V3 决策头」切到「RL 策略头」，直接改变车的实际行为。这类改动必须满足：
①策略头权重训练好（本机或云端均可）并通过过弯评测；②digest/急停/接管让位护栏逐项做行为级自检；
③灰度与回滚开关齐备。把它塞进本文一次做完，等于把「设计方案 + 加速器」和「改变生产驾驶」
混在一个 diff 里，不可评审、不可回滚。
