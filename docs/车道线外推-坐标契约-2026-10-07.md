## 二、★ 换算关系（外推最易错点，已实测钉死）

| 量 | 单位 | 换算到 MaskGrid | 换算到 Detection |
|---|---|---|---|
| 光流 dx/dy | **640 像素** | **÷ 4 = 格子位移**（640/160=4） | ÷ 640 = [0,1] 归一化位移 |
| MaskGrid 格子 | 160 格 | — | × 160 → 像素；÷ 640 → 归一化 |
| Detection | 归一化 [0,1] | × 160 = 格子 | — |

**⚠️ P2 光流内部降到 160 算，但 `flow_bridge.cpp:340-357` 已 `×scaleBack` 放大回 640 单位**，
所以下游拿到的 `OpticalFlowReading.dx/dy` **仍然是 640 坐标系的像素**，直接 `÷4` 即可到 MaskGrid。

**示例**：光流 dx = +8.0（内容右移 8 像素）→ 车道线掩码整体右移 **2 格**。

## 三、✅ 根因（为什么车道线"不准"）—— Lead 实测确认

1. `yolopxEngine.infer(...)`（产车道线 `ll` 掩码）在 **`if decimationOn` 门内**（`AuroraDriveApp.swift:6797`）
2. 而 `laneFallback.evaluate(laneMask: yolopxEngine.laneMask, ...)` **每 tick 都调**（`AuroraDriveApp.swift:7163`）
3. `decimationOn = adaptiveFrameCounter % 2 == 0` → **偶数帧才刷新 yolopx**，奇数帧 `laneMask` 是**上一帧冻结旧值**
4. 结论：**车在动、掩码不动 → 奇数帧车道线滞后一整帧**，这就是"不准"的一个根因

**外推器的精确价值** = 奇数帧时，用光流 (dx,ddy) 把上一帧的旧 `laneMask` **平移推到位**，而不是让 `laneFallback` 读冻结旧快照。

## 四、检测网偶奇帧错开（E4 目标）

当前（P1 遗留，**同相位**，有真空帧）：
```
帧0: yolopx✅  yolo26s✅
帧1: yolopx❌  yolo26s❌   ← 真空，纯靠外推
帧2: yolopx✅  yolo26s✅
```

目标（错开，检测框每帧有真值）：
```
帧0: yolopx✅  yolo26s❌
帧1: yolopx❌  yolo26s✅   ← 每帧至少一个检测源
帧2: yolopx✅  yolo26s❌
```

**代价**：车道线 `ll`、可行驶区 `da` 只有 yolopx 的偶数帧刷新 → 掉 15Hz（这正是外推器要补的）
