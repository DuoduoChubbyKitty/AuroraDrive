## 2 · 错开正确性（源码层验证，不靠跑）

### 2.1 门判定源码（`AuroraDriveApp.swift:6571-6586`）

```
adaptiveFrameCounter &+= 1
let parityEven = adaptiveFrameCounter % 2 == 0
let decimateFallback = Self.detectDecimate == 1
let detectGateA = decimateFallback || parityEven    // yolopx：偶数帧
let detectGateB = decimateFallback || !parityEven   // yolo26s：奇数帧
```

### 2.2 门实际门控的三处提交点

| 提交点 | 门 | 网络 | 行号 |
|---|---|---|---|
| 直通 `inferFast`（待机/驾驶都跑） | `detectGateB` | yolo26s（奇数帧） | 6634-6641 |
| 驾驶分支慢路径 `yoloEngine.infer` | `detectGateB` | yolo26s（奇数帧） | 6836-6839 |
| 驾驶分支 `yolopxEngine.infer`（三合一 ll/da/det） | `detectGateA` | yolopx（偶数帧） | 6845-6847 |

**判定**：✅ **错开正确，非同相**。三处提交点全部按「yolopx 偶数帧 / yolo26s 奇数帧」错开，每帧至少一网出检测框真值，不再有「真空帧」。`AURORA_DETECT_DECIMATE=1` 可一键回退两门恒真（恢复每帧都跑）。

## 3 · 车道线外推（E2/E3/E5）源码核验

### 3.1 接线已落地 — ✅


`LaneBridge()` 便捷构造（`LaneBridge.swift:92-97`）现已**直接绑定真实 E2**：
```

    ext.extrapolate(previous: prev, flow: flow).mask

```
车道线消费点从「读冻结的 `yolopxEngine.laneMask`」改为「读外推后的 `extrapolatedLaneMask`」，链路已接。

### 3.2 🔴 架构矛盾 A + Lead 已闭环

**（已化解）** 最初核实的「默认 A-YOLOM 档下外推退化为快照回退」矛盾，Lead 在 17:04~17:07 用「ayolom 不降频」修正了决策：

| 步 | 事实 | 位置 |
|---|---|---|
| 1 | 默认档 `perceptionMode = .ayolom` | App:5301 |
| 2 | `.ayolom.needsOpticalFlow == false` | YolopxEngine:242-247 |
| 3 | 光流唯一调用点被 `needsOpticalFlow` 门控 | App:6763-6764 |
| 4 | `lastOpticalFlow` 唯一写入在 `runOpticalFlow` 内 | App:6373 |
| 5 | 外推实参 `flow:` = `lastOpticalFlow` | App:6440 |
| 6 | 门③ `flow==nil` → 快照回退（不调 E2） | LaneBridge:145-147 |

**Lead 的修正（App:6616-6617）**：
```
let isAyolom = (yolopxEngine.family == .ayolom)
let detectGateA = decimateFallback || isAyolom || parityEven   // ayolom 恒跑
let detectGateB = decimateFallback || !parityEven              // yolo26s 奇数帧
```

**化解逻辑**：ayolom 每帧跑 → 真值恢复「每帧都有」→ A2「每帧有真值不需光流」前提重新成立 → A 档 `flow==nil` 回退快照不再有害（真值本就每帧刷新，无奇数帧断档）。而 legacy 档 `needsOpticalFlow=true` 光流照跑、外推有 flow 可用，语义自洽。

**判定**：✅ 缺陷 A 已闭环，是**有意的档位设计**而非 bug。E4 原「ayolom 也给 yolopxEngine.infer 降频」确实是过杀（ayolom ANE p50 10.4ms 跑不满 30Hz 预算），修正正确。

### 3.3 🔴 缺陷 B（legacy 档外推仍可能失效，待修）

即使缺陷 A 修好了，legacy 档（26S+光流+YOLOPX）的**光流外推仍可能不触发**，根子在真值判断用错了字段：

```
App:6437   let hasYolopxGroundTruth = yolopxEngine.isLoaded && !yolopxEngine.detections.isEmpty
App:6439   rawLaneMask: hasYolopxGroundTruth ? yolopxEngine.laneMask : .empty
```

问题：`yolopxEngine.detections` 是**持久字段**（`private(set) var detections`，YolopxEngine:369，只在 `infer` 完成时 `detections = dets` YolopxEngine:1068 覆盖、`reset()` 清空 YolopxEngine:1101）。legacy 档奇数帧 `detectGateB=false` 不调 `infer`（App:6862 门在 `detectGateA`），`detections` **残留偶数帧的旧数组**，`!isEmpty` 恒 true → `hasYolopxGroundTruth` 恒 true → 奇数帧仍传「旧 laneMask」被 LaneBridge 门①当「真值帧」直通缓存返回，**跳过光流外推**。

**结果**：legacy 档奇数帧车道线仍是上一帧旧快照，E2 外推被那个失效的「真值帧」判断短路。判定「本帧是否有新真值」应用 `inferenceCount`（YolopxEngine:406/1075）的帧间增量、或 `generation`（YolopxEngine:417），而非持久 `detections` 的非空性。

**判定**：🔴 **代码问题**，需 Lead 修：`hasYolopxGroundTruth` 应改为「本帧确实产出了新真值」的判据（如比较 `inferenceCount` 是否变化，或引入帧号戳）。不修则「车道线外推」在 legacy 档实际不生效，E2/E5 目标落空。
