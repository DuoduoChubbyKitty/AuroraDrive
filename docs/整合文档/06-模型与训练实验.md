## ② M9 → V2 → V2 split 演进线

### 阶段 0：M9（旧主驾）

- **模型**：`src/model.py` 的 `M9Model`（10 摄像头 + 2 激光雷达 + 13,318 维融合头，8.65M 参数 → FP16 16.5MB，**超 10MB 硬约束**）
- **部署形态**：`models/m9_mono.mlmodelc`（15MB）——但 `metadata.json` 的 `generatedClassName = "game_assist_control_fpv"`（**不是 M9Model**）。它是 `game_assist_control` 系列 FPV 模型被 `deployTrainedModel()` 复制改名而来（`AuroraDriveApp.swift:6192`）。
- **契约**：`image [1,3,180,320]` + `vehicle_state [1,6]` → `steer/throttle/brake`（3 输出）
- **废弃原因**（M1 侦察三根因）：
  - R1：部署的不是 M9，是 FPV 游戏辅助模型
  - R2：训练数据是 macOS 桌面截图（非游戏画面），标签全零
  - R3：数据管线默认 `skip_zero_label=True` 在全零数据上直接抛异常

### 阶段 1：M2 / model_v2（新模型架构）

- **模型**：`src/model_v2.py` 的 `M2Model`（RepVGG-A0 轻量变体，2.76M 部署态 / 3.30M 训练态）
- **契约**：`image [8,3,180,320]`（8 帧时序）+ `lane [1,1,160,160]` + `dets [1,20,12]` + `det_mask [1,20]` + `vehicle_state [1,8]` → `steer/throttle/brake` + `confidence/risk/car_heading`（6 输出）
- **导出脚本**：`tools/export_m9_v2_coreml.py`（INPUT_NAMES = 5 输入，OUTPUT_NAMES = 6 输出）
- **部署产物**：`models/m9_v2.mlmodelc`（16M Float16）——**⚠️ 旧产物**（Oct 9 07:21 编译，temporal.py 用 nn.GRU → WhileLoop=1 → ANE 编译失败，全退 CPU 453 算子）
- **已知缺陷**：
  - `temporal.py` 的 `nn.GRU` 被 coremltools trace 成 `while_loop` 算子（仅 CPU）→ 整图被踢出 ANE。**S5 已在 commit `561f1fa` 修复**（手工展开成 `_StrictGRUCell` 静态图），但 `m9_v2.mlmodelc` **未重新导出**
  - `tools/export_m9_v2_coreml.py:480` trace 时传 `camera_heading=None` → CoreML 导出契约**无 camera_heading 输入** → Swift 侧 `V2InputContract.cameraHeading`（`InferenceEngineV2.swift:271`）声明的常量**空转**（部署态车头朝向头的 Δ 主路径完全失效）

### 阶段 2：双模型拆分（enc + ctl）—— **当前生产默认**

- **导出脚本**：`tools/export_split_models.py`
- **产物**：`m9_v2_enc.mlmodelc`（2.6M palette）+ `m9_v2_ctl.mlmodelc`（6.5M palette）
- **流水线**（每 tick @20Hz）：
  1. enc（ANE）：`image [1,3,180,320]` → `feat [1,256]`
  2. 特征环形缓冲：推入 feat，保留最近 8 帧 → `[8,256]`（零计算）
  3. ctl（CPU）：`feat_seq [1,8,256]` + lane + dets + det_mask + vehicle_state → 6 输出
- **computeUnits 分配**（`InferenceEngineV2.swift:1799-1802`）：
  - enc → `.cpuAndNeuralEngine`（图像编码 preferred=ANE，0.34ms，不碰 GPU）
  - ctl → `.cpuOnly`（主控 646 算子全 CPU，0.54ms，不碰 GPU）
- **性能**（Lead min-of-60 实测，2026-10-09）：串联 p50=0.83ms / p95=1.07ms / GPU=0%
- **体积**：enc 2.6M + ctl 6.5M + wm 1.3M = **10.4M**（双模型 9.1M 不含 wm）
- **数值等价性**：拆分 vs 单模型 maxdiff=0.00e+00（PyTorch 内部逐位一致）

### 阶段 3：9 模型串联（multi_split）—— **保留但生产不可达**

- **导出脚本**：`tools/export_multi_split.py`
- **产物**：`models/multi_split/` 下 8 个 + 复用 `split24/m9_v2_enc` = 9 模型
- **流水线**：enc(ANE) → tf(CPU) → chunk1-6(CPU) 串联 → head(CPU)
- **性能**（S3 实测）：串联 p50=1.98ms / p95=2.30ms / GPU=0%（比双模型慢 2.1×、大 4.4×）
- **⚠️ 生产不可达**：`InferenceEngineV2.swift:1552` 声明 `var enableMultiSplit = false`，全仓 grep 无任何处置 `true` 的语句（唯一引用在 `:1726` 的加载分支条件里读它）。即 9 个 mlmodelc 全在磁盘（70M），但代码路径**永远走双模型分支**

### 阶段 4：世界模型（world_model）—— **加载但推理被注释掉**

- **导出脚本**：`tools/export_world_model.py`
- **产物**：`models/world_model.mlmodelc`（1.3M palette）
- **契约**：`fused[1,512]` + `action[1,3]` + `det_feat[1,128]` + `det_mask[1,20]` + `vehicle_state[1,8]` + `track_mode[1,1]` → `predicted_next_fused[1,512]` + `routing_weights[1,3]`
- **⚠️ 推理被注释掉**：三条推理路径的调用点（`InferenceEngineV2.swift:2237/:2318/:2409`）全部被注释（`// if let wm = self.worldModel { ... }`）。注释原因（2026-10-14 性能优化）：`consumePredNextFeat()`（`:2502`）全仓零调用 → `lastPredNextFused` 从不被消费
- **⚠️ 但仍加载**：`loadIfNeeded()`（`:1691`）在世界模型未加载时仍执行 `MLModel(contentsOf:)` + `warmUp`，**常驻 1.3MB 内存**。注释说"省 0.083ms/帧 + 1.3MB 常驻"——但只省了推理耗时，**加载和预热的开销仍在**

## ④ 各实验结论与现状

### 4.1 INT8 量化（INT8导出与实测 / 端到端训练打通）

| 方案 | 体积 | 分布内翻转 | 分布内最差偏差 | 建议 | 仍适用? |
|---|---|---|---|---|---|
| **palette kmeans gs=1** | 2.963M | 0/40=0% | 5.59e-03 | ✅ 首选 | ✅（用户铁律 INT8） |
| fp16 | 5.796M | 0% | 2.83e-03 | 🛡️ 兜底开关 | ✅ |
| w8a16 | 2.942M | 0% | 1.54e-02 | ❌ 同体积误差 4.2× | — |
| linear int8 / uniform | 2.963M | 0%（分布内） | 8.1e-02~1.04e-01 | ❌ 毁车道线细结构 | — |

- **关键区分**：「INT8 掉车道线 10×」指的是 **全量化（uniform/linear）**；palette + 关键头保 fp16 是另一回事
- ⚠️ **数据前提**：量化偏差用 `checkpoints/m9_v2/best_model.pt`（65.74% 随机初始化）测的——绝对误差幅度不能外推为真实驾驶精度

### 4.2 骨干对比（骨干对比实验 / 骨干网络候选清单）

- **结论**：不换 M2 的 RepVGG-A0 轻量变体。三条硬约束（INT8≤10MB / 多模态 / 30Hz⁴）全部满足且余量巨大
- **候选清单打假**：文档候选清单的参数量**全部含 ImageNet 分类头**，去掉分类头后：
  - ShuffleNetV2 0.5x：文档 2.28M → 实测 0.34M
  - MobileNetV3-Small：文档 2.5M → 实测 0.93M
  - GhostNet 0.5x：文档 2.6M → 实测 1.31M
  - EfficientNet-Lite0：文档 4.7M → 实测 3.37M
- **真机基准**（Apple M3 CoreML，部署态）：

| 骨干 | 端到端参数 | CoreML 体积 | p50 | p95(最差轮) | 30Hz?⁴ |
|---|---|---|---|---|---|
| RepVGG-A0 轻量变体 | 3,014,659 | 5.80M | 1.22ms | 5.29ms | ✅ |
| MobileNetV3-Small | 1,122,194 | 2.23M | 0.70ms | 1.72ms | ✅ |
| ShuffleNetV2 0.5x | 666,995 | 1.36M | 0.93ms | 9.60ms | ✅ |
| GhostNet 0.5x | 1,548,785 | 3.04M | 1.80ms | 5.89ms | ✅ |

> ⁴ 文档写「30Hz」——⚠️ **已过期**：tick 已定档 20Hz（`EngineMain.swift:686`），20Hz 帧预算=50ms，余量更大

### 4.3 ANE 阻断根因（ANE阻断根因 / 量化压缩调优）

- **真凶**：`nn.GRU` 被 coremltools trace 成 `while_loop` 算子（仅 CPU）→ 整图被踢出 ANE
- **不是**帧数、不是图大小：1帧 4.08MB → ANE 可用；2帧 4.18MB（只大 0.1MB）→ ANE 失败
- **修复**：`temporal.py` 手工展开 GRU 成 `_StrictGRUCell` 静态图（commit `561f1fa`），maxdiff=2.98e-08（float32 极限）
- **修后**：8帧 fp16 静态展开 → WhileLoop=0，ANE 609 算子可用，p95=3.46ms（vs 循环版 21.19ms，快 6×）
- ⚠️ **当前 `m9_v2.mlmodelc` 仍是旧产物**（Oct 9 07:21 编译，WhileLoop=1）——需用当前 temporal.py 重新导出

### 4.4 GAP 修复（模型感知头验证）

- **bug**：`LaneMaskEncoder` 末端 `AdaptiveAvgPool2d((1,1))`（全局平均池化）→ 平移不变 → 抹掉车道线左右信息
- **实测**：旧 GAP(1,1) 左右差 4.657e-10（本质为 0）；修复 GAP(2,2)+spatial_proj 左右差 0.008965 → **提升 1.93e+07×**
- **修复**：GAP(2,2) 保留 2×2 位置块 + `spatial_proj` 投影回 64 维

### 4.5 双模型 cpuOnly 完胜（双模型cpuOnly完胜 / Lead/S1/S3 ANE 派发）

| 方案 | 串联 p50 | p95 | 体积 | GPU | 仍适用? |
|---|---|---|---|---|---|
| **双模型 enc(ANE)+ctl(cpuOnly)** | **0.83ms** | 1.07ms | 15.8MB⁵ | 0% | ✅ **生产默认** |
| 9 模型串联 | 1.72ms | 2.05ms | 70MB | 0% | ⚠️ 保留但不可达 |

> ⁵ 文档写 15.8MB（Float16 双模型）；现产 palette 版 enc 2.6M + ctl 6.5M = 9.1M（更小）

### 4.6 车头朝向（车头朝向鉴定 / 车头朝向感知头 / 真车头抓包实验设计）

- **鉴定结论**：`pose.4` = **相机朝向**（UE5 ControlRotation），不是车体朝向（6 条独立证据链）
- **HeadingHead 设计**：`Δheading = carHeading − cameraHeading`（视角-车头差分解耦，模型只学小量 Δ）
- **⚠️ 部署不可达**：导出脚本 trace 时 `camera_heading=None` → CoreML 契约无此输入 → Δ 主路径失效，只能走纯视觉绝对预测兜底
- **真车头数据源**：目前**没有**（ControlRotation 不是车体）；`motionHeading`（atan2 位移方向）是近似

### 4.7 风险与接管头（风险与接管头）

- **RiskHead 参数**（2026-10-18 实测）：主支路 115,330 + step 头 82,434 = **197,764**
- w7 实测总参数 9,086,774 → INT8 8.67MB ≤ 10MB ✅

## ⑤ 已废弃模型/方案 + 原因

| 方案 | 废弃原因 | 出处 |
|---|---|---|
| **M9（M9Model）** | 8.65M 参数 FP16 16.5MB 超 10MB；从未部署到 m9_mono 位置（被 game_assist_control_fpv 顶替） | 主驾驶模型换代-需求与方案 §2.1 |
| **nn.GRU 时序** | trace 成 while_loop → ANE 阻断；已手工展开成 _StrictGRUCell | ANE阻断根因 / 量化压缩调优 |
| **logical_and 布尔运算** | risk_head 的 `a & b` → logical_and（CPU+GPU 不含 ANE）；改 `a * b`（float 乘法） | ANE阻断根因 §4.2 |
| ⚠️ **m9_v2_ctl 的 logical_and 仍有 17 处**（model.mil grep） | 文档（ANE阻断根因）称"已移除"，但 2026-10-18 实测 `grep -c logical_and model.mil = 17`；metadata histogram 有 `Ios18.logicalAnd ×5` | 🔴 **文档与产物不符** |
| **4 帧折中** | ANE 安全边界=1 帧是假结论（真凶是 WhileLoop 不是帧数）；拆分后 8 帧完整保留 | 图结构分析 §6 |
| **4bit 量化** | 全方案 maxdiff≥0.19 有损，违反"不降质量"红线 | 量化压缩调优 |
| **linear/uniform int8 全量化** | 毁车道线细结构（1-2px 细线差 19-63×） | INT8导出与实测 |
| **9 模型 multi_split 作为默认** | 比双模型慢 2.1×、大 4.4×；双模型 cpuOnly 已足够好 | 双模型cpuOnly完胜 |
| **单模型 m9_v2.mlmodelc（8帧原图）** | WhileLoop=1 → ANE 失败全退 CPU（453 算子）；需重新导出 | 量化压缩调优 §3 |
| **history_feats / frame_mask 外部输入** | w7 方案 A 重构：时序改为 image batch 维承载窗口，废弃外部 history_feats | 模型感知头验证 §2.2 |
| **GAP(1,1) 车道线池化** | 平移不变 → 抹掉车道线左右信息 → 模型分不清左右 → 开出车道线 | 模型感知头验证 §1 |
| **CIContext 亮度计算** | Apple Silicon 上 .useSoftwareRenderer 被静默忽略 → 走 Metal → 阻塞等 GPU → 12fps 卡顿 | ConfidenceEstimator.swift :244-264 |
| **旧录制数据（桌面截图+FPV+全零标签）** | 域错误（桌面≠游戏）+ 视角错（FPV≠TPV）+ 无监督信号 | 多篇文档 |
