## 3. 已废弃路线（两篇）

### 3.1 Tauri App Plan —— 已废弃的替代路线

**判定：是，已废弃。** 425 行细节不应保留，只保留下面这段"当初想做什么 / 为什么没走"的摘要。

**当初想做什么**：把 AuroraDrive 从「浏览器 + Python 沙箱后端」升级成 macOS 原生 App。
方案是 **Tauri v2（Rust 主进程 + WKWebView）做壳**，**PyInstaller 打包 Python 运行时做 sidecar**（`aurora-sidecar`），
C++ 的 `autodrive_core` 一并打包，前端 `frontend/dist` 由 Tauri 托管。分 8 个阶段施工，
MVP 里程碑是"阶段 1-3 跑通原生窗口 + 3D SR + WebSocket"。

**为什么没走（实测证据）**：

1. **Package.swift 里没有任何 Rust/Tauri 依赖**。
   ```bash
   grep -n -i "tauri\|rust\|cargo" Package.swift   # → 无命中
   ```
   全仓 `Cargo.toml` 也是 0 个：`find . -maxdepth 3 -name "Cargo.toml" -not -path "./build/*"` → 无输出。
2. **方案里 8 个阶段要新建的目录，今天一个都不存在**：
   `src-tauri/`、`packaging/`、`frontend/`、`cpp/` 全部不存在（`ls` 实测）。
3. **方案依赖的文件全部已删**：`run_web.py`、`src/web_server.py`、`src/web_simulator.py`、
   `src/cpp_bridge.py`、`src/inference.py`、`data/fujian_map.bin`、`CMakeLists.txt`。
4. **架构换了三次，Tauri 只是第一站**：
   Python Sidecar → 纯 C++（Route B，中间路线）→ **Swift 原生**（当前）。
   今天 `Sources/` 下 **73 个 .swift，0 个 .cpp/.mm/.hpp**；唯一的 C++ 是 `Vendor/OpenCVFlow` 的
   光流 C 桥（`Package.swift:5-23`），那也不是 Tauri 的 sidecar。
5. **用户核心诉求最终由 Swift 原生满足**：Dock + Applications、三指拖拽、不依赖浏览器、
   独立运行时 —— 现在由 `AuroraDriveUI.app`（14,193,680 B）与 `AuroraDriveUserAgent` XPC 服务提供
   （`Package.swift:72-78` 两个 executable target）。

**给读者的三句话**：这份文档里关于「双模式（仿真 3D + 联动 2D）」「OpenCV 30fps 车道线」
「CGEvent 注入」「zstd 压缩地图外置」的设计思考，有一部分以**别的形式**活在今天的代码里
（截屏走 `CaptureEngine`、注入走 `ControlEngine`、地图走 `models/route_graph.json`）；
但**Tauri + PyInstaller + React 前端这条实现路径本身，一次都没走过**。

### 3.2 离线全国地图 500MB —— 已废弃

**判定：是，已废弃。** 原文第 3 行自己已经写了「本文件仅作存档，不作为现状依据」。

**当初想做什么**：在 500MB 硬盘预算内装下**全国** OSM 数据（路网 + 建筑 + POI），
画质零损失、纯离线。手段是 Valhalla tiles 精简到 200MB、马里奥瓦片法把 500 万建筑压到 58MB、
POI 精简到 62MB，现场生成 MVT 瓦片，R-tree 索引 + 并行生成 + 预取把查询压到 5ms。

**为什么没走（实测证据）**：

1. **预算表里的四类数据源，今天一个都不在**：
   `libvalhalla` / `pmtiles` / `cpp/tools/build_offline_data.cpp` / `poi_store.h` 全部不存在。
   spec 里点名的 `cpp/include/ad/*` 12 个路径、`AuroraDriveApp/NavigationView.swift` 也全部不存在。
2. **当前地图资产量级完全不同**：当前链路是
   `docs/roadnet/v5/V5_line_全分辨率.png`（**978,499 B ≈ 0.96 MB**）+
   `models/route_graph.json`（**102,681 B ≈ 0.10 MB**），
   合计约 **1.1 MB**，比 500MB 预算小 **约 450 倍**。
   （`README.md:38`：路网先验 664 节点 / 932 边，断头率 19.3% → 5.4%。）
3. **载体换了**：不是"全国 OSM + Valhalla + 现场 MVT 生成"，而是
   **单一游戏地图**（13056×13056 地图像素，`MissionConsole.swift:2791` `static let mapPixels = 13056`）
   + 静态路网 JSON + 网络抓包定位（libpcap 解 UE5 位流）。
4. **问题域也换了**：spec 面向"真实世界全国导航"（POI 搜索、地址生成、建筑轮廓），
   现在面向"单个游戏内的寻路与全收集标记"（`--quest-selftest` 跑的 3819 个任务目标）。

**唯一仍然有效的继承**：spec 里「R-tree 加速空间查询」「视觉优先级加载」「渐进式渲染」
这几个**思路**，与今天 `MarkerCluster.swift` / `RouteGraph.swift` 的聚类与规划有精神上的延续，
但实现、数据、指标全不相同，**不要把 spec 里的任何数字当成现状**。
