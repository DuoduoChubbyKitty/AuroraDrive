## 2 · vehicle_state 数据流全链路（决定"模型能不能训"）

这条链路有 **3 段**，每段维度不同，缺字段的影响在每段都在变：

```
RecordEngine CSV(5列) → dataset_v2 组装 vehicle_state[10] + mask[10]
                      → train_v2 裁 10→8 (_state_from_batch)
                      → model_v2 用 vehicle_state[8]
```

### 2.1 第一段：dataset_v2 组装 STATE_DIM=10（`src/dataset_v2.py:122`，布局注释 :57-74）

```
 idx  name               来源 CSV 字段
 0   speed_norm         speed_kmh         ← ❌ 缺 → 0, mask[0]=0
 1   curvature_x5       curvature          ← ❌ 缺 → 0, mask[1]=0
 2   heading_sin        sin(heading_rad)   ← ❌ 缺 → 0, mask[2]=0
 3   heading_cos        cos(heading_rad)   ← ❌ 缺 → 1, mask[3]=0  （★见下文）
 4   speed_limit_norm   speed_limit        ← ❌ 缺 → 0, mask[4]=0
 5   reserved           恒 0
 6   accel_norm         accel_mps2（由 speed_kmh 差分算）  ← ❌ 缺 speed → 算不出
 7   accel_mps2         同上               ← ❌ 缺 speed → 算不出
 8   heading_wrapped    wrap_to_pi(heading_rad)/π  ← ❌ 缺 → 0, mask[8]=0
 9   curvature_raw      curvature          ← ❌ 缺 → 0, mask[9]=0
```

**heading 缺失的特殊处理**（`src/dataset_v2.py:420-421`）：
```python
else:
    # 降级：等价 heading=0，与 InferenceEngine.buildVehicleState 的
    # 「无遥测 → sin=0/cos=1」运行时行为保持一致，但 mask=0 明确标记为缺失
    st[2], st[3] = 0.0, 1.0
```
→ heading 缺失时 st[2]=0, st[3]=**1**（不是 0！等价"正北"），但 mask[2]=mask[3]=0。

**accel 缺失的连带效应**（`src/dataset_v2.py:380-390`）：accel 由 `speed_kmh` 逐帧差分算（`(s1-s0)/3.6/dt`）。speed_kmh 全 None → `continue` 跳过 → st[6]=st[7]=0, mask=0。

### 2.2 第二段：train_v2 裁 10→8（`src/train_v2.py:397-405`）

```python
out = torch.zeros(B, M2_STATE_DIM, device=device, dtype=vs.dtype)  # M2_STATE_DIM=8
out[:, 0] = vs[:, 0]            # speed_norm        ← 缺 → 0
out[:, 1] = vs[:, 7] / 10.0     # accel_mps2 → accel/10  ← 缺 → 0
out[:, 2] = vs[:, 8]            # heading_wrapped（已是 /π）  ← 缺 → 0
out[:, 4] = vs[:, 1]            # curvature_x5      ← 缺 → 0
# M2[3] heading_rate / M2[5] lateral_offset / M2[6] steer_angle 无数据源 → 保持 0
```
**注意**：vs[2]（heading_sin）、vs[3]（heading_cos）、vs[4]（speed_limit）在 10→8 裁剪里**被丢弃**——即使录了 heading，模型用的也不是 sin/cos 而是 `heading_wrapped`（vs[8]）。

### 2.3 第三段：model_v2 用 STATE_DIM=8（`src/model_v2.py:278`）

```
M2 vehicle_state[8] 布局（model_v2.py 注释 :277）：speed, accel, heading, heading_rate, curvature, lateral_offset, steer_angle, reserved
```

**缺 4 个 CSV 字段后，model_v2 收到的 vehicle_state**（实测推断，§3 逐维论证）：

| M2 idx | name | 值 | 来源 |
|---|---|---|---|
| 0 | speed | **0** | speed_kmh 缺 |
| 1 | accel | **0** | speed_kmh 缺 → accel 算不出 |
| 2 | heading | **0** | heading 缺 → heading_wrapped=0 |
| 3 | heading_rate | 0 | 无数据源（即使录了也 0） |
| 4 | curvature | **0** | curvature 缺 |
| 5 | lateral_offset | 0 | 无数据源 |
| 6 | steer_angle | 0 | 无数据源 |
| 7 | reserved | 0 | 恒 0 |

→ **8 维里 3 维有真实数据源、但全缺；5 维本来就没数据源**。模型收到的 vehicle_state **8 维全 0**。

## 3 · 每个缺失字段的后果（逐维）

### 3.1 speed_kmh 缺 ❌
- dataset：st[0]=0, mask[0]=0（`src/dataset_v2.py:400-402`）
- 连带：accel 算不出（`src/dataset_v2.py:380` `continue`）→ st[6]=st[7]=0, mask=0
- train_v2：out[0]=0（speed）、out[1]=0（accel）
- model_v2：vehicle_state[0]=0（speed_norm）、[1]=0（accel_norm）
- **后果**：模型以为车**完全静止 + 零加速度**，与真实驾驶（20-120 km/h）严重不符。

### 3.2 heading 缺 ❌
- dataset：st[2]=0, st[3]=**1**, mask[2]=mask[3]=0（`src/dataset_v2.py:425-427`，等价正北）
- st[8]=0（heading_wrapped）, mask[8]=0
- train_v2：out[2]=vs[8]=0（**注意**：用的是 vs[8] heading_wrapped，不是 vs[2]/vs[3]）
- model_v2：vehicle_state[2]=0
- **后果**：模型以为车头**永远朝正北**，学不到转弯。

### 3.3 curvature 缺 ❌
- dataset：st[1]=0, st[9]=0, mask[1]=mask[9]=0（`src/dataset_v2.py:408-411`）
- train_v2：out[4]=vs[1]=0
- model_v2：vehicle_state[4]=0
- **后果**：模型以为道路**永远笔直**，学不到弯道。

### 3.4 speed_limit 缺 ❌
- dataset：st[4]=0, mask[4]=0（`src/dataset_v2.py:432-434`）
- train_v2：**无映射**（_state_from_batch 不读 vs[4]）
- model_v2：vehicle_state 无对应位
- **后果**：M2 的 speed_limit 经由 `InferenceEngine` 走 `vehicle_state[4]`，但 train_v2 的适配器没把 dataset 的 speed_limit 映射进 M2[4]——**即使录了 speed_limit 也不会进 M2**（这是另一个独立 gap，见 §4）。

## 4 · ★ 关键发现：vehicle_state_mask 是死字段

**证据**（全仓 grep，`vehicle_state_mask` 在 train_v2.py 只出现 3 处，全在数据结构定义里，从不消费）：

| 位置 | 用途 | 是否消费 |
|---|---|---|
| `src/train_v2.py:27` | docstring 字段说明 | ❌ 文档 |
| `src/train_v2.py:232` | 空批次占位 `torch.zeros(10)` | ❌ 占位 |
| `src/train_v2.py:1641` | self-test 占位 `torch.ones(10)` | ❌ 占位 |

**没有任何一处**把 mask 用于 loss 加权、过滤、或传给 model_v2 的 forward。

**后果**：dataset 生成 mask 标记"这一维是真实值还是缺失补零"，**但训练链路完全忽略它**。模型收到的 vehicle_state 全 0，mask 也全 0——但模型**不知道这是缺失**，会把全 0 当真实状态学（梯度照样回传）。

**这就是"录了一次全废"的根因**：缺字段本身可以降级，但 mask 不被消费 → 降级无效 → 模型学到错误的"全停、正北、笔直"分布。

## 7 · 另一个独立 gap（顺带发现）：speed_limit 映射断裂

即使补录了 `speed_limit` CSV 字段，**train_v2 的 `_state_from_batch` 也没把它映射进 M2**：
- dataset 组装 st[4]=speed_limit_norm（`dataset_v2.py:432-434`）
- train_v2 的 `out[:, 4] = vs[:, 1]`（curvature_x5），**不是 vs[4]**
- M2 的 vehicle_state[4] 在 model_v2 注释里是 `curvature`（`model_v2.py:277`）
- 但 `InferenceEngine` 运行时把 `speed_limit` 塞进 vehicle_state[4]（见需求文档 §1 的口径冲突记录）

→ **训练侧 st[4]=speed_limit，但 train_v2 把 st[1]=curvature 塞进 M2[4]**。这是一个**训练-推理口径不一致**（训练喂 curvature、推理喂 speed_limit 到同一维），独立于录制格式，但会误导模型。**标注为推测**（未读 InferenceEngine 全文确认运行时塞法，仅依据文档转述）。
