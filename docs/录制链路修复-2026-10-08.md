## 一、改了什么（按需求逐条）

### 1. 双模式捕获（`Sources/AuroraDrive/Capture/CaptureEngine.swift`）

**原 bug**：`SCContentFilter(display: display, excludingWindows: [])` —— 排除列表**空数组**，
等于不排除任何窗口，整块显示器（含桌面 + 自家 UI）全录进训练数据。

**现在**：新增 `enum CaptureMode`：
- `.fullScreen`（录全屏/模式 A）：整显示器，但**排除所有自家窗口**（bundleIdentifier / pid / 应用名三重判定）
- `.window(id:)`（只录窗口/模式 B）：`SCContentFilter(desktopIndependentWindow:)`，天然不含自家 UI 与桌面

**运行时切换**：`applyMode(_:)` 走 `SCStream.updateContentFilter(_:)`（官方 API），
**不重启流、不断帧、不重申请权限**。

### 2. 窗口选择拉条（`Sources/AuroraDrive/App/MissionConsole.swift`）

预览框右缘新增 `WindowPickerRail`：
- 收起态：16pt 窄竖条（贴右缘，不挤动预览画面）
- 展开态：236pt 面板，列出 `SCShareableContent.windows`
- 过滤：仅 `isOnScreen`、windowLayer==0、≥160×120、排除自家窗口
- 排序：游戏窗口置顶 + 高亮，其余按面积降序
- 「录全屏」选项置顶；底部显示当前捕获源 + 自家 UI 告警
- 手点刷新（不随 30Hz tick 重枚举：`SCShareableContent.current` 10-60ms）

### 3. perspective 参数化（第三视角）

**原 bug**：`AuroraDriveApp.swift:4921` 与 `AIAgentPanel.swift:894` 硬编码 `"first"`，
而 `RecordEngine` 早已支持按参数写 `view.txt`（first→FPV / third→TPV）——参数在，没人传。

**现在**：
- `DriveState.recordThirdPerson` 开关 + `recordPerspective` 计算属性
- UI 本地路径与引擎命令都带 perspective（引擎进程**默认路径**，不传就静默录 FPV）
- `AIAgentPanel` 用 `recordPerspectiveProvider` 闭包读同一视角（AI `drive_dataset` 技能与 UI 开关一致）

**关键缺口修复（EngineMain.swift，Lead 授权）**：引擎进程的 `record` 分支原先只读
`on/glyph/expert`，不读 perspective → 用户选 TPV、引擎照旧录 FPV。现已透传 + 归一化。

### 4. `maxClipsPerKind` 可配（`Sources/AuroraDrive/Capture/RecordEngine.swift`）

**原 bug**：硬编码 10，录制启动时**静默删**最旧 clip → 用户采集 10000+ 帧数据凭空消失。

**现在**：优先级 `AURORA_MAX_CLIPS` 环境变量 > `maxClipsOverride` > 默认 10；
删旧 clip 时**必打日志**（删几个、剩几个、来源、调大方法）。

### 5. 修 meta.json.perspective 坏字段

旧代码 `url.lastPathComponent.components(separatedBy:"_").first` 恒返回 `"clip"`（目录名首段），
即 meta.json 永远写 `"perspective": "clip"`。训练端只读 view.txt（无人读此字段，故一直没暴露），
但它是错误信息，现已改为写真实视角（与 view.txt 同源）。

### 6. 自动断言（防回归）+ 可执行自检

- 新增 `--capture-selftest` 入口（登记进 oneShotFlags + 分发），返回失败项数
- `CaptureEngine.auditOwnWindowExclusion()`：验证全屏模式排除列表**非空**且覆盖所有在屏自家窗口
- 这是**充要条件**级断言，卡住「谁把 excludingWindows 改回空数组」这个回归

## 三、怎么用 TPV 录（用户操作指引）

1. 游戏里切到**第三视角**（游戏内快捷键 `Z`；`ControlEngine` 的 `GameKey.z` 已支持，AI 可 `press_key("Z")` 帮切）
2. AuroraDrive 控制台 → 打开**行驶录制**开关
3. 若只想录游戏画面（排除桌面 + 自家 UI）→ 预览框右缘点「窗口」拉条 → 选游戏窗口（自动高亮推荐）
4. 采集大数据集时设 `AURORA_MAX_CLIPS=1000`（否则默认只保留 10 个 clip，旧的最先被删）

## 四、边界情况与已知限制

| 边界 | 处理 |
|---|---|
| 目标窗口关闭 | 切换失败**保持原模式**（不静默切回全屏），原因写给 UI |
| 老版 UI 不发 perspective 字段 | 引擎回落 `"first"`（与旧行为一致） |
| 无屏幕录制权限 | 自检跳过真实枚举部分（提示授权），纯逻辑断言照跑 |
| 视角中途切换 | 不生效（与 glyphMode 同约定：录制中改视角 = 同一 clip 混两种视角，训练端会误判） |
| 引擎进程用 NSApp.windows 识别自家窗口 | 会**空**（引擎无 SwiftUI）→ 已改用 bundleIdentifier/pid 三重判定，两进程都正确 |
| `tools/aurora_recorder.c` 也抓整屏 | **未改**（不在本次写作用域，且是 C 代码），需要单独跟进 |
