### 4.3 最关键的未验证项（task-98 明确要求）

> **「验证 `.ayolom` 档 45Hz 是否真的装得下」**

**Lead 已纠正判据**（重要，我采纳）：

| 错误判据 | 正确判据 |
|---|---|
| ❌ "tick 单帧耗时 vs tick 预算" | ✅ "**异步推理队列的总吞吐 vs 投递率**" + "**实际 CPU 占用**" |

**Lead 给出的背景数据**：
```
tick 同步工作（实测 PERF 日志）: total p50 = 0.34ms   ← tick 本身完全不卡
异步推理（每次 tick 投递）:
  yolopx(ayolom) 20.9ms + V2 8.5ms + world_model 3ms = 32.4ms/帧
  30Hz → 0.97 核/秒 ； 45Hz → 1.46 核/秒
  但 P5 实测 45Hz 下 engine CPU = 85.2%（0.85 核）→ 估算偏保守
```

**我开工后的判据（Lead 指定）**：
1. 抓 `PERF.*tick分段` 的 `total` → 确认 tick 本身不阻塞
2. 抓 `tickGap=` → 确认 tick 实际间隔（ayolom 档应 ~22ms）
3. 看 `yolopxEngine.metrics` → 实测推理耗时
4. **最关键**：`ps -o %cpu` → 45Hz 下 engine CPU 是否逼近 100%（单核饱和）
5. **判据**：CPU 逼近 100% 或 tickGap 抖动大 → **装不下**；CPU 有余量且 tickGap 稳定 ~22ms → **装得下**
