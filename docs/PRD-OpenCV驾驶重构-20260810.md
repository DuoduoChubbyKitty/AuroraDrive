## 2. 产品定义

### 2.1 产品目标

1. 让 App 在「异环/NTE」第三人称开车场景中，以 OpenCV 车道线 + 鸟瞰图（BEV）为核心跟线感知，**保留 YOLO 作车/人避障感知**，实现「能沿路开的自动驾驶」。
2. 通过小地图蓝色导航线 + 速度表 OCR + HOG 路牌，实现方向/航点预判、180km/h 高速进弯提前减速与路牌语义读取。
3. 重构四档降级梯子（档2 融合驾驶、档3 纯规则兜底），统一键盘注入控制，整体提升可用性与恢复能力。

### 2.2 用户故事

1. 作为用户，我希望纯规则档（档3）能在空路上沿车道线直行/贴边回正，而不是误识别自车后疯狂刹停/倒车。
2. 作为用户，我希望在 180km/h 高速行驶时，App 能根据弯道曲率/小地图航点提前减速，避免冲出路外或失控。
3. 作为用户，我希望通过读取小地图蓝色导航线判断行驶方向/航点，让 App 在路口/弯道做出正确转向。
4. 作为用户，我希望速度表 OCR 提供真实车速反馈，让控速模块能维持目标巡航速度。
5. 作为用户，我希望 YOLO 保留作避障感知并与车道线跟线并存——检测到真实障碍时能避让，同时不再因误框自车而触发异常刹车。
6. 作为用户，我希望 HOG 路牌检测与 BEV 鸟瞰图增强感知，识别路牌/限速语义并提升弯道路缘识别鲁棒性。
7. 作为用户，我希望所有档位的控制统一走键盘注入（W/A/S/D/空格），不更换手柄方案。

## 3. 技术规范

### 3.1 需求池

优先级说明：**P0 = 必须实现（本次重构核心）**；**P1 = 应该实现**；**P2 = 可选/增强**。

#### A. 感知模块（全要素融合）

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| A1 | P0 | OpenCV 车道线检测（Canny+Hough 或颜色阈值，跟线驾驶主源） | 测试路段稳定输出车道线/道路边界；实时性满足驾驶（建议 ≥15fps，以测试为准） |
| A2 | P0 | 小地图蓝色导航线读取（参考 MananJK：小地图+路线 → 行驶方向/航点） | 定位小地图 ROI、解析导航线方向，输出转向/航点语义；分辨率/UI 缩放适配方案明确 |
| A3 | P0 | 速度表 OCR 读取（参考 CNNT：底部数字速度表 → 速度反馈） | 输出数值车速，供控速模块使用；识别失败时有降级/重试策略 |
| A4 | P1 | 自车车道偏离度估计 | 由车道线计算自车相对车道中心偏移，供档3 贴边回正与档2 跟线使用 |
| A5 | P0 | **多感知融合与置信度输出（五信号：车道线+YOLO+HOG+小地图+速度 OCR）** | 融合输出统一驾驶状态与各模块置信度，供梯子降级判定；融合架构设计明确（见 3.2） |
| A6 | P1 | HOG 路牌检测（参考 jimhoggey） | 检测路牌/限速类目标并输出语义；与融合层对接 |
| A7 | P0 | 鸟瞰图（BEV）变换（参考 CNNT，用于车道线/路缘识别） | 透视变换生成 BEV 视图，提升车道线/路缘/弯道识别鲁棒性 |
| A8 | P0 | YOLO 车/人检测（保留现有能力，作避障感知并入融合） | 保留 YOLO 物体检测作为避障输入；**过滤自车框**，避免 TPV 下误框自车导致异常刹车 |

#### B. 控制模块

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| B1 | P0 | 车道线跟线驾驶控制（档2） | 基于车道线+BEV 输出 steer/throttle/brake，含贴边回正、弯道跟随；空路不倒车、不误刹 |
| B2 | P0 | 高速进弯预判减速（180 控速） | 进弯前按弯道曲率/小地图航点提前减速，180km/h 场景可验证明显减速再入弯 |
| B3 | P1 | 目标巡航速度控制 | 基于速度表 OCR 维持可配置的目标巡航速度，加减速平滑 |
| B4 | P2 | 控速参数按车型可调 | 支持不同车辆手感差异的调参配置（按推荐默认：本期先单一配置，见 Q7） |
| B5 | P0 | 键盘注入统一控制（复用 ControlEngine，不换手柄） | 所有档位输出统一走键盘映射 W=13/A=0/S=1/D=2/空格=49；映射不变 |

#### C. 梯子重构

| 编号 | 优先级 | 需求 | 验收要点 |

### 3.2 多感知融合架构（设计要点）

五信号融合建议分层：

- **信号层**：车道线（A1/BEV A7）、YOLO 车/人（A8）、HOG 路牌（A6）、小地图导航线（A2）、速度 OCR（A3）各自独立输出 + 置信度。
- **融合层（A5）**：统一驾驶状态（车道偏离、前方障碍、方向航点、目标车速、路牌语义），输出各模块置信度。
- **决策层**：融合状态驱动控制（B 模块）与梯子降级（C3）。

### 3.3 技术选型点（按推荐默认推进，可后补）

OpenCV 在 Swift/macOS 的集成方式，见 Q5：

- **方案 A：引入第三方 OpenCV 库**（如 opencv2.framework / CocoaPods/SPM 集成）——功能全、与社区方案对齐，但引入较大的二进制依赖。
- **方案 B：原生自写**（CoreImage / Vision / Accelerate 实现 Canny+Hough 或颜色阈值）——零第三方依赖、可控，但实现量与调参成本高。
- **推荐默认**：先以原生自写（方案 B）验证车道线/BEV 可行性，保留升级到第三方库（方案 A）的通道。

## 4. 非目标（本期不做）

- 不做语义分割 / 深度估计等重型感知。
- 不做端到端模型重训（M9 保持现状，见 Q8）。
- 不做红绿灯识别 / 行人让行等复杂交规逻辑（YOLO 仅做基础车/人避障）。
- 不接入游戏内部 API / 内存读取，保持「屏幕视觉 + 键盘注入」纯外挂方案。
- 不做多平台支持（仅 macOS）。
- 不做赛道记忆 / 地图建图等长期记忆能力。

## 5. 需求决议与待确认问题

### 5.1 已决议（用户拍板，不再变更）

1. **YOLO 保留**：作为物体检测（车/人）避障感知，与车道线等融合；早前「YOLO 全删」方案作废。
2. **感知全要素融合**：三个社区项目方案全都要——jimhoggey（OpenCV 车道线 + YOLO 车/人 + HOG 路牌）、MananJK（小地图蓝色导航线读取）、CNNT（鸟瞰图变换 + 速度表 OCR）。
3. **控制统一键盘注入**：复用现有 ControlEngine（W/A/S/D/空格映射），不换手柄。

## 6. 验收标准

**一句话**：五信号感知融合（车道线 + YOLO 车/人 + HOG 路牌 + 小地图导航线 + 速度表 OCR）可用，YOLO 避障与车道线跟线并存，控制统一键盘注入；在确认的空路测试路段，档2/档3 能沿车道行驶且不误刹、不倒车，180km/h 高速进弯前提前减速，感知退化时四档梯子平滑降级（M9 → 车道线融合驾驶 → 纯规则 → 脱困）。

---

*附：核心背景（已确诊问题）——① YOLO 为 COCO 物体检测不检车道线，纯规则档只会避障不会开车；② TPV 下 YOLO 将自车框为「车」且落在危险区，导致疯狂刹停/只倒车（融合时须过滤自车框）；③ 大世界测试路段无障碍物，避障价值有限，但 YOLO 保留作车/人检测并与车道线融合（Q10）。*
