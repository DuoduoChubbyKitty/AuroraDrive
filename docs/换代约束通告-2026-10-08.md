## 🔴 追加铁律（2026-10-08，w1-backend 找到出处，Lead 已核实 4 处原文）

### INT8 全量化会毁掉车道线 —— 项目既有实测，不是推测

**四处逐字出处**：
1. `tools/yolopx/export_yolopx_coreml.py:58-64`（最原始实测记录）：
```
**⚠️ INT8 全量化已证伪（实测，勿用）**：
  同一批真实行车图下三档量化的车道线正像素占比：
      fp16   1.30–1.80%   ✅
      w8a16  1.30–1.80%   ✅（与 fp16 逐位一致）
      int8   0.13–0.21%   ❌ 掉约 10×
  车道线是极细目标，激活全 int8 量化会直接把它抹掉。故**只产 fp16 与 w8a16**。
```
2. `tools/yolopx/export_yolopx_coreml.py:422`（命令行帮助）：
   `help="额外产出 int8 全量化（⚠️ 已实测证伪：车道线头会掉约 10× 像素，仅供对比）"`
3. `tools/yolopx/export_yolopx_int8.py:42-46`（**根因**）：
```
目录**全是游戏 UI 截图**（钓鱼小游戏、菜单、设置页、桌面），几乎没有
可行驶区域与车道线。用它们统计激活范围 → 分布严重偏斜 → 量化后
车道线头直接塌陷（实测正像素 1.3~1.8% → 0.13~0.21%，掉约 10×）。
正确做法：用 repo 自带的真实行车画面（BDD100K 风格 FPV，1280×720，...）
```

### ⟹ 对本次换代的直接影响

| 结论 | 说明 |
|---|---|
| ⚠️ **不能简单"全 INT8 量化"** | 车道线是极细目标，激活全 int8 会抹掉它 |
| ✅ **正确配方：palette(kmeans 8bit) + 关键头保 fp16** | 项目已量产 `ayolom` 配方（7.2M→3.8M），是唯一验证过的路子 |
| ✅ **校准集必须是真实行车画面** | `export_yolopx_int8.py:44` 明确：用游戏 UI 截图校准 → 分布偏斜 → 塌陷 |
| ⚠️ **但 M9-v2 的 lane 分支是编码器不是 mask 头** | 输出是特征向量不是掩码，**不能直接外推**结论 → 必须专项测（w1 正在做） |

### 另一条 w1 发现的技术细节

`exp_quant_palette.py:18-24` 实测：**`group_size=32` 会静默跳过约 70% 张量**
（coremltools 对不整除的张量只打 warning 不报错）→ 默认应用 `--group-size 1`
（per-channel 等价物，100% 覆盖），保留 gs=32 作对照。**这直接决定 INT8 体积能否压到位。**

## 🔴 追加：车头朝向 / 视角朝向 的抓包事实（Lead 亲查，2026-10-08）

### 1. 抓包解出的 rotation 是【角色/玩家】的（不是相机的）
证据：`CoordinateCapture.swift:445` 注释——「角色移动时 X1/X2 每包同步变化，静止时字段完全不变」→ 解出来的位置/旋转是**玩家实体**的。

### 2. rotation 是 UE5 Rotator（pitch/yaw/roll，单位度）
`ue5Rotator()`（:166）解码：3 个角度，各带 1 位 present 标志 + 16 位压缩值，
`angle = compressed × 360/65536`，>180 则 −360。注释（:193 附近）：**Pitch 和 Yaw 存在，Roll 通常不存在**。

### 3. `toPose()` 的 heading = rotation.yaw 算的 compass_heading（0-360 度）
`CoordinateCapture.swift:215-229`：yaw → viewDir → atan2(east, north) → 0-360°。
**这是车头/角色朝向的真值来源。**

### 4. ⚠️ 但 NetworkLocator 把它覆盖了！
`NetworkLocator.swift:550-558`：
```swift
var heading = pose.4                    // ← 真车头朝向（rotation.yaw）
if 位移² > 16 {
    heading = atan2(dx, dy)...          // ← 一移动就被"运动方向"覆盖
}
```
**用户实测**：视角/运动往哪走，heading 就往哪走，角色没变 → 印证了"被覆盖"。
**修正方案**：把 rotation 真值单独存成 `carHeading`（不被 atan2 覆盖），原 `cameraHeading` 保留（=运动方向估计）。

### 5. 单位陷阱（必读）
- 抓包 heading：**0-360 度**（compass）
- 模型契约：**弧度 [-π,π]**
- 还有 pitch 也在包里（rotation.0），可一并透传
- **喂模型前必须 度→弧度 + compass 系→相对车头/视角 系，别直接喂**

### 6. 加速度也在包里（scale ÷10，:392）
`CoordinateCapture.swift:392`：`ue5Vector(payload, offset: bitOffset+32, scale: 10)` 解出 **accel**，
**坐标系（世界系 vs 车体系）尚未实测确认**，代码里"只存不用，等标定"。
→ 喂模型前同样要标定。
