## 10. 依赖方向（按 `import` 实测 + 类型引用实测）

### 10.1 编译级模块依赖（`import` 实测）

```
AuroraDrive (主可执行 target, path=".")
 ├── import AuroraDriveShared ........ 0 处（主 target 未直接 import）
 ├── import OpenCVFlow ............... 1 处 —— 仅 Inference/OpticalFlowBridge.swift:42
 └── System frameworks：SwiftUI / AppKit / CoreML / ScreenCaptureKit / Vision /
     Accelerate / MetalKit / Network / ApplicationServices / AudioToolbox / IOKit …

AuroraDriveUserAgent (可执行 target)
 └── import AuroraDriveShared ........ 1 处 —— main.swift:4

AuroraDriveShared (基础 target)
 └── import Foundation ............... 无内部依赖（最底层）
```

**结论**：显式 `import` 的模块依赖只有**一条**真实边：`AuroraDriveUserAgent → AuroraDriveShared`；以及 `AuroraDrive → OpenCVFlow`。
7 个业务子目录**同属一个 Swift module**（`Sources/AuroraDrive` 是同一个 target），彼此之间**没有 import**——全靠类型直接引用，编译器不做可见性拦截。**所以「目录依赖」是约定，不是强制**。

### 10.3 值得点名的三条结论

1. **`Core/` 到 `Inference/` 存在反向引用**：`AuroraFlags.swift` / `AuroraPaths.swift` / `EngineClient.swift` / `EngineMain.swift` 4 个文件引用了 Inference 层类型。所以「Core 是纯底层」的说法**不成立**——它不是干净的叶子。
2. **`App/ → Agent/` 是单向的**：实测无任何 Agent 文件引用 App 的类型；但 **Agent 引用 `DriveState`（5 文件）**，而 `DriveState` 声明在 `App/AuroraDriveApp.swift`——**App ↔ Agent 构成双向依赖圈**（`AIAgentPanel` / `DegradeStateMachine` / `RuleController` / `ToolRegistry` / `LLMSelfTest` ←→ `DriveState`）。
3. **`Agent/` 内部自成一簇**：`AgentLoop`(8) / `ToolRegistry`(6) / `LLMTransport`(6) 的引用全部落在 `Agent/` 内，AI 助手子系统相对独立。

### 10.4 依赖方向的「应然」vs「实然」

| 层 | 期望方向 | 实测 |

| `Core/`（基础设施） | 被所有层引用，自己不引用业务层 | ⚠️ 被引用 ✓，但**反向引用 Inference** ✗ |
| `Capture/`（输入） | 被 Inference / App 引用 | ✓ `CaptureEngine` 被 6 个 Inference 文件引用 |

| `Locate/`（定位） | 只被 App 引用 | ✓ 实测 Agent/Capture/Control/Core/Inference 均 0 引用 |
| `Agent/`（AI 助手） | 依赖 Core/Inference，被 App 引用 | ⚠️ 反向依赖 `DriveState`(App) ✗ |
