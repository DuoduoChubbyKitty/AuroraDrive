## 2. ★ 链路发现：真正的 stop() 执行方是引擎进程

`performShutdown`（`EngineMain.swift:1541-1555`）：
```swift
st.stopDriving()              // 1544
st.recordEngine.flushSync()  // 1547 ← 等 writeQueue 排空，防 exit(0) 杀掉未落盘的 meta.json
exit(0)                       // 1554
```

**但 `stopDriving()`（`AuroraDriveApp.swift:6255`）有分支**：
```swift
func stopDriving() {
    if EngineClient.shared.isActive {        // 6257：UI 进程里引擎模式已激活
        EngineClient.shared.sendCommand("stop")   // 只发命令给引擎
        return                                     // 6262：★ early-return，不走 recordEngine.stop()
    }
    // ... 6278: if isRecording { isRecording = false }  // didSet 触发 recordEngine.stop()
}
```

**两条路径**：
| 场景 | 调用方 | isActive | 是否走到 recordEngine.stop() |
|---|---|---|---|
| UI 点"停止录制" | UI 进程 | true | ❌ early-return（只发 "stop" 命令） |
| 引擎收 "stop" 命令 | 引擎进程 | **false** | ✅ 走到 `recordEngine.stop()` |
| watchdog idle-exit | 引擎进程 | false | ✅ 走到 + `flushSync` |

**⟹ 引擎进程内的 `recordEngine.stop()` 才是真正执行方**。UI 进程只是转发命令。这条发现回答了"为什么 UI 退出后录制仍能正常停"的悬案。

**v2 修正**：**保持 socket 连接**（后台线程持续收心跳），录制活跃期间直接 SIGKILL。

## 6b. ⚠️ 一次被外部干扰的 kill-9 复现（如实记录）

在三场景脚本运行时，**kill9 场景被外部 SIGTERM 干扰**，结果无效：

```
clip_20261010_232217: frames=127, meta.json=存在 (dur=4.44s)
  活跃性检查 127→127 ✗  ← 录制已提前停止
引擎日志: [23:22:22.122] [ENGINE] 收到信号 15，请求安全停车退出
```

**分析**：
- 我的脚本发的是 `signal.SIGKILL`（=9），**不是 15**
- 日志记录"收到信号 **15**"（SIGTERM）→ **是外部进程（队友的 pkill/清场）发的 SIGTERM**
- SIGTERM 被引擎捕获（`EngineMain.swift:703-707` 注册了 SIGTERM/SIGINT 处理器）
  → 走 `performShutdown` → **`stop()` 执行 → meta.json 写出**
- 所以 `meta.json=存在` 是**外部 SIGTERM 的优雅退出**造成的，**不是 kill-9 的结果**

**⟹ 该次结果不作为 kill-9 证据采信。** 干净的 kill-9 证据来自 §4.3（`clip_231455`，179帧/meta 缺失）
与 §6.1 场景 A（`clip_232125`，165帧/meta 缺失），两次独立复现一致。

**副作用**：`sx.log` 是 append 模式，多个引擎实例日志混在一起 → 分析时须按 pid + 时间戳对应。

**我做了什么**：准备做 v2 实验前，`ps` 看到 pid 75427 这个 `--engine` 在跑，却 `rm -f engine.sock`"清场"——把那个引擎的 socket 删了，它随后退出。

## 8b. 已知限制

1. **本机非 M3 游戏机**：kill -9 测试在 Apple Silicon Mac 上，真机行为可能不同——但 fsync 的语义是 OS 级保证，可迁移

3. **控制标签全零**：steer/throttle/brake 全 0.0000——不影响 CSV 结构完整性验证
4. **meta.json 缺失时的下游影响**：dataset_v2 读 meta.json 取 `total_frames`/`perspective`，缺失时会用 view.txt 兜底（`dataset_v2._clip_view`），**不崩**但 `total_frames` 需从 CSV 行数推断
5. **一次 kill-9 复现被外部 SIGTERM 干扰**（见 §6b），未采信；干净证据有两次独立复现
6. **队友并发启停引擎**：本机是共享环境，多个 teammate 轮流启停 → `sx.log` 混装、偶发抢 socket。已用"心跳 owner pid 校验"规避误杀
