# 真车头抓包实验设计 · 静止转视角 vs 原地转向对照

> 日期：2026-10-08 · 设计人：w2-transport（抓包线监督）
> 前置结论：`docs/车头朝向鉴定-2026-10-08.md` —— **现有抓包字段里的 rotation 是相机朝向（ControlRotation）**，包内无车体 rotator。
>
> 本实验的目标：**用对照法证明/证伪「ControlRotation 能分离出车头」**，并实测标定若存在的相机-车头偏移。

---

## 一、实验原理

UE5 第三视角下，玩家 `ControlRotation`（相机）与车体 yaw 的关系只有三种可能：

| 假设 | 含义 | 判据 |
|---|---|---|
| H1：相机=车头 + 固定偏移 | 游戏相机是"硬锁定车后"模式 | 静止转视角时 rotation **不变**（转不动相机）；原地转向时 rotation 与车头同步变 |
| H2：相机独立，车头不可得 | 相机可自由旋转，包里无车体信息 | 静止转视角时 rotation **变**；原地转向时 rotation 也变且无法区分哪个是车头 |
| H3：相机=弹性跟随 | 相机以弹性延迟追车头（SpringArm 回正） | 静止转视角时 rotation 短暂变化后**回弹**；原地转向时 rotation 滞后跟随 |

**判定的关键**：静止转视角（H1 预期不变 / H2、H3 预期变）——这是单一变量对照，一个实验就能切掉 H1。

---

## 二、实验准备

### 2.1 抓包通道（2026-09-30 实测事实）

| 通道 | 内容 | 端口 |
|---|---|---|
| **C2S UDP**（主目标） | 客户端移动 RPC，**~8Hz 持续**，站立也发 | **随服务器变化，永不写死**（历史：30212 → 30160） |
| TCP 30031 | 心跳（15s 一个，微秒时钟）+ 元数据推送 | 固定 |

过滤器照抄现网（`CoordinateCapture.swift:1105`）：

```
(tcp port 30031) or udp
```

⚠️ **UDP 必须在过滤器里**：真实移动数据（含 ControlRotation）在 C2S UDP 移动包里
（2026-09-30 实测：UDP 30160 C2S 6288 包 → 解出 2444 个有效姿态）。只抓 TCP 30031
会重演"移动包被挡、探测 23 轮全空"的旧事故。

### 2.2 工具

- 抓包：`tcpdump -i en8 -n -s 0 -U -w <out> "(tcp port 30031) or udp"`（root；iface 用默认路由网卡，先 `route get default` 确认）
- 解码：`/tmp/r1/drv/diagdir/diag`（真实 `UE5Decoder` 抽取版，含 `debugCandidates` 直出 rotation）；**需扩展**以支持 UDP 链路层（现版只解析 IPv4+TCP，UDP 要加 proto==17 分支与 8 字节 UDP 头）
- 对照记录：手机秒表录屏（记录"开始转视角/停止"的墙钟时刻，与 pcap 时间戳对齐）

## 三、实验步骤（4 组，每组 ≥60s，中间静止 10s 分隔）

### 实验 A：纯静止基线（对照组，必做）

1. 进游戏，角色站定（不动摇杆、不转视角），**60 秒完全不动**
2. 全程录屏（画面 + 计时），抓包
3. **预期**：rotation（P/Y/R）与位置全部恒定；若 rotation 自己漂移 → 说明有噪声，后续实验要以它为基线扣除

### 实验 B：静止转视角（决定性实验，切掉 H1）

1. 角色站定**不动**（摇杆零输入）
2. 按以下节奏只转**视角/鼠标**（不动 WASD）：
   - 0-10s：不动（基线）
   - 10-20s：把视角向右转 ~90°
   - 20-30s：保持
   - 30-40s：转回原方向
   - 40-50s：向左转 ~180°
   - 50-60s：保持
3. 全程录屏 + 抓包
4. **判定**：
   - rotation.yaw 随转视角同步变化 → **H1 被证伪**，rotation 是相机（预期结果）
   - rotation.yaw 纹丝不动 → H1 成立（相机硬锁车后），rotation 可直接当车头
   - rotation.yaw 变了又**回弹**到原值 → H3（弹性跟随），变化量与回正时长可标定

### 实验 C：原地转向（车头变，相机跟随）

1. 角色站定，用键位让**车体原地转向**（若有原地转向键；驾驶态下用 A/D 原地打轮；若无原地转向则改用「低速绕桩」，见变体 C'）
   - **C'（无原地转向时的替代）**：极低速直线行驶（W 轻点），期间只微调视角 ±30°，与实验 B 的 90°/180° 区分度拉开
2. 节奏同 B（10s 基线 → 4 段动作各 10s）
3. **判定**：
   - rotation.yaw 跟随车头变化且**无回弹** → 与实验 B 的"回弹"行为区分 → 可分离车头（H3 成立的佐证）
   - rotation.yaw 变化规律与 B 完全一致 → 无法从包内分离车头（H2 确认），只能靠运动方向 + 视觉

### 实验 D：匀速直线 + 固定视角（运动方向 vs rotation 的互检）

1. 找一段长直路，**W 按住不转视角**，匀速直线行驶 30s
2. **判定**：
   - `atan2(ΔmapX, ΔmapY)` 运动方向应恒定（直线）
   - rotation.yaw 与运动方向的差值 = **相机-车头偏移的实测值**（若 H3 且相机回正完成）
   - 这个差值若恒定 → 可作为固定偏移补偿进 `motionHeading`；若漂移 → 不可补偿，只能靠运动方向

## 四、判据汇总

| 实验 | H1（相机锁车头） | H2（相机独立） | H3（弹性跟随） |
|---|---|---|---|
| A 静止 | rotation 恒定 | rotation 恒定 | rotation 恒定 |
| B 静止转视角 | **rotation 不变** | rotation 变，不回弹 | rotation 变后**回弹** |
| C 原地转向 | rotation 跟车头变 | rotation 变化与 B 不可分 | rotation 滞后跟随、无回弹 |
| D 直线行驶 | rotation≈运动方向+定值 | rotation 与运动方向无固定关系 | rotation≈运动方向+定值（回正后） |

**结论树**：
- B 不变 → rotation 可当车头用（H1），`carHeading = pose.4` 合法，本小姐收回前言
- B 变不回弹（H2）→ **包里没有车头**；真车头只能：①运动方向（修好 atan2 镜像 bug 后）②视觉模型推导
- B 变且回弹（H3）→ 车头 = rotation 回弹后的稳态值；或用「回正完成时刻」的 rotation

## 五、数据产出与解析

每组实验产出 `exp_<A|B|C|D>.pcap` + 对应录屏。解析输出（每帧）：

```
t=12.345 loc=(x,y,z) rot(P,Y,R) → yaw_degs, motion_dir(Δmap)
```

分析脚本要画三张图（判定用）：
1. **yaw(t) 曲线**：与录屏对齐，标注"开始转视角"时刻 → 看响应/回弹
2. **运动方向(t) vs rotation.yaw(t)**：实验 D 的差值曲线 → 定偏移是否恒定
3. **位置轨迹**：确认 A/B 组角色确实没动（对照组有效性）

## 六、风险与坑（都是实测踩过的）

| 坑 | 对策 |
|---|---|
| UDP 端口随服务器变 | 过滤器用裸 `or udp`，**永不写死端口** |
| `hasValidRotation` 是弱判据（单包 40-935 偶然命中） | 解析时按 `time+location+rotation` 连续性锁定（解码器已有），只取**锁定后**的连续帧，不取孤立命中 |
| turn.pcap 类 protobuf 双记录包位扫描不覆盖 | 解码器需扩展双记录路径（或确认 C2S UDP 包不走该布局——2026-09-30 实测 UDP 6288 包解出 2444 姿态，说明可解） |
| 只抓 TCP 30031 | **禁止**：移动数据在 UDP（旧事故：探测 23 轮全空） |
| 解析脚本只支持 TCP | 需加 UDP 分支（proto==17 + 8 字节 UDP 头）——本次 `/tmp/r1/drv` 的 `tcpPayloads` 已是现成底子 |
| 镜像 bug（w8 发现） | `NetworkLocator.swift:560` `atan2(dx, dy)` 的轴序若与地图坐标不一致，8 方向里 6 个反——**实验 D 的判据依赖它**，先修再跑 D |
| 录屏与 pcap 时钟不同步 | 用录屏里的系统时钟（含秒表）与 pcap ts_sec 对齐；或抓包同时 `date +%s` 打点 |

## 八、预期结论（写在本小姐下头之前）

按上游协议语义（ControlRotation = 玩家控制器旋转）与本仓库已有证据链，
**最可能的结果是 H2 或 H3**：
- H2：包里无车头，真车头 = 运动方向（修好 atan2）+ 视觉模型推导 —— 与用户"heading 跟视角走"的实测一致
- H3：车头 = rotation 的回正稳态，可标定

**H1（相机硬锁车头）概率最低**——若真如此，用户就不会观察到"转视角 heading 跟着变"。

跑完实验把三张图回传，本小姐按判据树出最终结论。
