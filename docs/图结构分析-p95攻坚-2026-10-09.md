## 2. ★ 关键发现：batch 分布极不均衡

```
含 batch=8 的张量:  31 个   ← 只有 ImageEncoder 这一段
含 batch=1 的张量: 465 个   ← 其余全是单帧
```

**⟹ 8 帧只占 31 个张量（ImageEncoder），465 个张量是单帧的（时序/refiner/MoE/头）**

## 3. 由此推导的攻坚方向

### 3.1 双模型拆分的拆点（给 S1）
```
模型 A = ImageEncoder（8帧）  → 31 个 batch=8 张量，纯卷积
模型 B = 时序+refiner+MoE+头  → 465 个 batch=1 张量，单帧图
```
**关键推理**：
- **1帧 + palette 实测 ANE 2.23ms ✅** → 模型 B（单帧图）ANE 成功率高
- 模型 A 是纯卷积（无 GRU/无 MoE）→ 值得试 ANE
- 若 A 也失败 → 试 batch=4 跑两次（S4 在测这个边界）

### 3.2 编码成本归因（给 S4）
- 8 帧 batch 贯穿 ImageEncoder 的 18 个 conv
- **估算**：ImageEncoder 占 8× 成本，其余单帧
- **验证方法**：单独导出 ImageEncoder（8帧）测耗时，与整模型对比

### 3.3 图瘦身机会（给 S3）
- **cast 19 个**：fp16/fp32 转换 —— 若能统一精度可省
- **slice_by_index 30 个**：GRU while_loop 拆解 —— 若能静态展开可能更快
- **linear 132 个**：refiner 107 个 —— shared=True 下 12 步共用一个 cell，但展开成静态图后有 12 份（正常）
- **softmax 4 个**：MoE 路由（只在 4 步，符合设计）

## 5. 最可能成功的路线（Lead 判断）

| 路线 | 预期 | 依据 |
|---|---|---|
| **① 双模型拆分** | A(8帧卷积) + B(单帧465张量) → 若 B 能 ANE，总延迟可能 3~8ms | batch 分布分析 |
| **② 特征缓存**（Swift 侧） | 每帧只编码 1 帧 → 8× 提速 | 8帧里7帧是历史 |
| **③ 执行路径调优** | computeUnits/macOS15/去重 → 10~30% | 项目旧经验 |
| **④ 量化调优** | 4bit → 图更小 → 可能 ANE 能编译 | 图大小与 ANE 编译相关 |
