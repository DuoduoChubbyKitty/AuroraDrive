## 二、阶段 1：零风险改动（立即做）

### 改动 1：`captureCursor = false`（修复假光标 BUG）

**位置**：`Vendor/MetalGoose/Engine/GooseUpscaler.swift:54-61`

**改动**：
```swift
public func configureInterpolation() {
    let settings = CaptureSettings.shared
    settings.scalingType = .off
    settings.aaMode = .off
    settings.frameGenMode = .interpolation
    settings.frameGenMultiplier = 2
    settings.captureCursor = false          // ← 新增
    engine.updateSettings(settings)
}
```

**为什么**：`Stubs.swift:15` 的 `MouseConstraintManager.currentCursorFraction()` **硬编码返回 `(0.5, 0.5)`**，而 `CaptureSettings.captureCursor` 默认 `true` → **画面正中永远有一个不跟随鼠标的假箭头**。

**影响链**：
```
settings.captureCursor = false
  → GooseEngine.swift:1821  next.captureCursorEnabled = false
  → GooseEngine.swift:1203  if config.captureCursorEnabled { ... }   // 不进入
  → 不再调用 drawSyntheticCursor
```

**⚠️ 会破什么**：
- **真光标是否还在？** → ✅ **在**。`CaptureEngine.swift:218` 已设 `config.showsCursor = true`（SCStream 捕获真光标）
- **`CaptureSettings` 持久化** → 改动会写入 UserDefaults（`didSet { store(...) }`），下次启动保持 `false` ✓

**验证**：
1. 开插帧 → 看画面正中是否还有假箭头
2. 移动鼠标 → 真光标仍可见
3. `--upscale-selftest` 通过

**回滚**：删掉那一行。

**收益**：修复用户可见的视觉 BUG（插帧开启时必现）。

### 改动 2：`upscalePool = nil`（修复 22MB 内存泄漏）

**位置**：`Sources/AuroraDrive/Capture/CaptureEngine.swift:264-274`（`stop()` 的 `captureQueue.sync` 块）

**改动**：
```swift
self.captureQueue.sync {
    self.nativePool = nil
    self.nativePoolWidth = 0
    self.nativePoolHeight = 0
    self.yoloBufferPool = nil
    self.yoloBufferPoolSize = 0
    self.uiBufferPool = nil
    self.uiPoolWidth = 0

    self.upscalePoolWidth = 0
    self.upscalePoolHeight = 0

```

**为什么**：`stop()` 的注释写"停捕获时把**三个** CVPixelBufferPool 置 nil，释放 ~8MB"，但 `CaptureEngine` 实际有 **4 个池**（`upscalePool` 在 `:131`）→ **第 4 个从未清理**。

**⚠️ 会破什么**：
- **必须在 `captureQueue.sync` 内**（否则与 `stream()` 内的建池竞争）→ ✅ 已在块内
- **`upscalePool` 只在 `stream()`（captureQueue）上创建** → ✅ 已验证
- **`stop()` 后重启** → `makeUpscaleBufferPool` 检查 `pool == nil` → **自动重建** ✓

**验证**：
1. 反复"停止→启动" 5 次 → 无崩溃
2. `footprint <pid>` 前后对比 → `IOSurface` 数量下降
3. 内存不增长

**回滚**：删掉 3 行。

**收益**：每次停止驾驶释放全分辨率池（每块 22MB × 池深度）。

### 改动 4：`fastPathActive` 前置检查（修复 YOLO 停摆）

**位置**：`Sources/AuroraDrive/Inference/YoloEngine.swift:264-270`

**改动**：
```swift
func inferFast(pixelBuffer: CVPixelBuffer) {
    guard enabled else { return }
    guard isLoaded, let modelRef = model else {      // ← 先检查
        loadIfNeeded()
        return
    }
    fastPathActive = true                             // ← 后置位（原在 guard 之前）
    ...

```

**为什么**：原代码 `fastPathActive = true` 在 `guard isLoaded` **之前** → **模型未加载时也置 true** → `tick` 的 `if !yoloEngine.fastPathActive` 判 false → **永不回退慢路径** → **YOLO 完全停摆**。

**⚠️ 会破什么**：
- **无**。改动后 `fastPathActive` 只在真正开始直通推理时置位 ✓

**建议同时加超时回退**：
```swift
// YoloEngine 内新增
private(set) var lastFastPathTime: Date = .distantPast

func inferFast(pixelBuffer: CVPixelBuffer) {
    ...
    fastPathActive = true
    lastFastPathTime = Date()          // ← 记录
    ...

// AuroraDriveApp.swift:2658 改为
let fastPathStale = Date().timeIntervalSince(yoloEngine.lastFastPathTime) > 1.0
if !yoloEngine.fastPathActive || fastPathStale {
    yoloEngine.infer(image: cg)
}
```

**验证**：
1. 临时改名模型文件 → 启动 → 看 `detections` 是否仍更新（应走慢路径）
2. 正常启动 → 看引擎日志 `det=` 数（快路径）
3. 停止抓屏 → YOLO 不应停摆

**回滚**：把 `fastPathActive = true` 移回 `guard` 前。

### 改动 5：`blur(92) → 60`（GPU 最大单点）

**位置**：`Sources/AuroraDrive/App/AuroraTheme.swift:323`

**改动**：
```swift
.blur(radius: 60)      // 原 92
```

**为什么**：`AuroraLightField` 有 **3 个 blob**（最大 `max(w,h) × 0.78` = 936px @1200×760）+ **26 秒 `repeatForever` 动画** + **blur radius 92（模糊核 185×185）**。
- **3 blob 总面积 = 窗口的 1.89 倍**
- **每帧运算 ~6.4 亿次** → **60fps 下 ~383 亿次/秒**
- **`.offset` 每帧变 → 模糊结果无法缓存 → 每帧重算**

**⚠️ 会破什么**：
- **视觉**：光斑边缘从"极柔和"变"略锐"（核 185 → 121）
- **3 个使用点同时受影响**：`MissionConsole.swift:578`（主画面）/ `:2843`（大地图）/ `:3131`（技能层）
- **动画、颜色联动、位置** 均不变 ✓

**⚠️ 若视觉不接受**，替代方案（**视觉零影响**）：
```swift
// 方案 A：加 drawingGroup（-10%，视觉不变）
ZStack { blob ×3 }
.drawingGroup()
.blur(radius: 92)

// 方案 B：预渲染成图片（-95%，视觉不变，但需处理路况变色）
//   预渲染 6 个版本（每种 RoadCondition 一个）
private static let lightFieldImages: [RoadCondition: Image] = [...]
Image(...).resizable().offset(...).animation(...)
```

**验证**：
1. **截图对比**（改动前 vs 后）
2. 切换路况 → 光斑变色仍工作
3. 观察 30 秒 → 26 秒动画仍工作
4. 活动监视器看 GPU 下降

**回滚**：改回 92。

**收益**：GPU 最大单点，-60%（或方案 B 的 -95%）。

## 三、阶段 2：低风险改动（阶段 1 验证后做）

### 改动 7：`publish` 的 CGContext → memcpy（引擎最大热点）

**位置**：`Sources/AuroraDrive/Core/EngineMain.swift:220-247`

**实测证据**：`sample <engine_pid> 8` 显示 **`tickOnce` 的 14 个样本 100% 在 `publish`**：
| 位置 | 样本 | 占比 |
|---|---|---|
| `:241` `ctx.draw(img)` | 8 | **57.1%** |
| `:238` `CGContext(data:)` | 3 | **21.4%** |
| 编译器生成 | 3 | 21.4% |
| **`DriveState.tick()`** | **0** | **0%** |

**改动**：
```swift
} else if let img = image {
    let w = img.width
    let h = img.height
    if w > 0, h > 0, w <= EngineFrameShm.maxWidth, h <= EngineFrameShm.maxHeight {
        let pageSize = w * h * 4
        if pageSize != currentPageSize {
            currentPageSize = pageSize
            generation += 1
            storeU32(32, generation)
            storeU64(72, UInt64(pageSize))
        }
        let active = base.load(fromByteOffset: 36, as: UInt32.self)
        let writePage = active == 0 ? 1 : 0
        let dest = base.advanced(by: EngineFrameShm.pixelsOffset + writePage * currentPageSize)

        // ★ 优化：CGImage 底层已是 32BGRA premultipliedFirst（CaptureEngine 用
        //   CGDataProvider 零拷贝包装，CaptureEngine.swift:407-409），格式与目标完全一致
        //   → 直接 memcpy。原 CGContext.draw 会走完整 CG 绘制管线 + 像素格式转换 +
        //   Alpha 混合（实测占引擎主线程 78.6%）。
        if let data = img.dataProvider?.data, let src = CFDataGetBytePtr(data) {
            let srcBPR = img.bytesPerRow
            let copyBytes = w * 4
            if srcBPR == copyBytes {
                memcpy(dest, src, copyBytes * h)                  // 紧凑布局：一次 memcpy
            } else {
                for r in 0..<h {                                   // 有行填充：逐行
                    memcpy(dest.advanced(by: r * copyBytes),
                           src.advanced(by: r * srcBPR), copyBytes)
                }
            }
            storeU32(24, UInt32(w))
            storeU32(28, UInt32(h))
            storeU32(36, UInt32(writePage))
        } else {
            // ★ 兜底：dataProvider 不可读时回退原 CGContext 路径（功能零损失）
            let cs = CGColorSpaceCreateDeviceRGB()
            let bitmapInfo = CGImageAlphaInfo.premultipliedFirst.rawValue
                | CGBitmapInfo.byteOrder32Little.rawValue
            if let ctx = CGContext(data: dest, width: w, height: h,
                                   bitsPerComponent: 8, bytesPerRow: w * 4,
                                   space: cs, bitmapInfo: bitmapInfo) {
                ctx.draw(img, in: CGRect(x: 0, y: 0, width: w, height: h))
                storeU32(24, UInt32(w))
                storeU32(28, UInt32(h))
                storeU32(36, UInt32(writePage))
            }
        }
    }
}
```

**⚠️ 必须保持的 4 条不变量**：
| # | 不变量 | 破坏后果 |
|---|---|---|
| ① | 像素格式 = `premultipliedFirst + byteOrder32Little` | UI 侧颜色错乱（红蓝互换） |
| ② | `bytesPerRow = w*4`（紧凑） | 图像斜切/错行 |
| ③ | 写入"非活动页" | 画面撕裂 |
| ④ | 写完像素后才翻页（`offset 36`） | 同上 |

**⚠️ 为什么安全**：
- **UI 侧读者**：`EngineClient.swift:508-517`，按 `w*4` + `premultipliedFirst + byteOrder32Little` 读 → **与源格式一致** ✓
- **`ctx.draw(img, in: CGRect(0,0,w,h))`** 的**目标尺寸 = 源尺寸** → **无缩放** → **纯格式转换**
- **源已是目标格式** → **转换是恒等** ✓

**⚠️ 验证清单**：
1. 画面正常（无花屏/斜切）
2. 颜色正确（红色元素仍是红色）
3. **`sample <engine_pid> 8` → `publish` 占比应从 ~100% 降到 <20%**
4. 帧率仍 30fps（引擎日志 `seq` 差）
5. `--speed-selftest` / `--yolo-selftest` 通过
6. 插帧路径正常（若开启）

**回滚**：把 `if let data = img.dataProvider...` 改成 `if false`（走兜底分支）。

**收益**：**引擎 CPU -78.6%**（实测驱动）。

## 四、阶段 3：需实测改动（最后做）

### 改动 10：`onUpscaleFrame` 加门禁（省 22MB/帧）

**位置**：两处
1. `Sources/AuroraDrive/Capture/CaptureEngine.swift:317`（**源头门禁，最有效**）
2. `Sources/AuroraDrive/Core/EngineMain.swift:550` + `Sources/AuroraDrive/App/AuroraDriveApp.swift:2132`

**问题全貌**：
| # | 接线点 | 进程 | 行为 |
|---|---|---|---|
| 1 | `EngineMain.swift:550` | **引擎** | 存 `latestFullFrame` |
| 2 | `AuroraDriveApp.swift:2132` | **UI** | `upscaleHost.push` |

**两处都无条件**，但 `CaptureEngine.swift:317` 的 `copyUpscaleFrame(from:)` 会**先做 22MB 拷贝**（`if let onUpscaleFrame, let upscaleCopy = copyUpscaleFrame(...)`）→ **插帧关闭时白白拷贝 22MB/帧**。

**最优改动（源头门禁）**：
```swift
// CaptureEngine 新增属性
var upscaleWanted = false          // 由 DriveState 同步

// CaptureEngine.swift:317 改为
if let onUpscaleFrame, upscaleWanted,
   let upscaleCopy = copyUpscaleFrame(from: pixelBuffer) {
    onUpscaleFrame(upscaleCopy)
}
```

**⚠️ 会破什么**：
- **`upscaleWanted` 需同步**：UI 开插帧 → 通过 socket 命令通知引擎 → **有延迟**（首帧可能丢，可接受）
- **若判断错误** → 插帧收不到帧 ❌ → 必须实测

**⚠️ 简化方案（只改 UI 侧，收益小但零风险）**：

### 改动 12：预编译 metallib（启动 -100ms~1s）

**位置**：`Vendor/MetalGoose/Engine/GooseEngine.swift:440-470`（`setupPipelines`）+ `run.sh`

#### ⚠️ 先搞清楚现状（已实测）

**`setupPipelines` 的 library 加载顺序**（`:444-467`）：
```swift
let library: MTLLibrary? = {
    // ① Bundle.main 的 Shaders.metal（源码）→ device.makeLibrary(source:)
    if let url = Bundle.main.url(forResource: "Shaders", withExtension: "metal"),
       let src = try? String(contentsOf: url, encoding: .utf8),
       let compiled = try? device.makeLibrary(source: src, options: nil) {
        return compiled
    }
    // ② exeDir/Shaders.metal（源码）
    // ③ exeDir/Vendor/MetalGoose/Engine/Shaders.metal（源码）
    // ④ 硬编码路径 /Users/dupi/Desktop/自动驾驶系统/Vendor/.../Shaders.metal（源码）
    let candidates: [URL] = [ exeDir/Shaders.metal, exeDir/Vendor/..., 硬编码路径 ]
    for url in candidates {
        if let src = try? String(contentsOf: url, encoding: .utf8),
           let compiled = try? device.makeLibrary(source: src, options: nil) { return compiled }
    }
    // ⑤ device.makeDefaultLibrary()   ← 最后！
    return device.makeDefaultLibrary()
}()
```

**实测当前状态**：
| 项 | 实际值 |
|---|---|
| `AuroraDriveUI.app/Contents/Resources/` | **不存在** → ① 失败 |
| `exeDir/Shaders.metal` | **不存在** → ② 失败 |
| `exeDir/Vendor/.../Shaders.metal` | **不存在** → ③ 失败 |
| **`/Users/dupi/Desktop/自动驾驶系统/Vendor/MetalGoose/Engine/Shaders.metal`** | **存在** → **④ 命中** ✓ |

**★ 结论**：
1. **当前实际走 ③**（`exeDir/Vendor/.../Shaders.metal`，相对路径）→ **④ 不执行** ✓
2. **`Contents/Resources/` 不存在** → **① 永远失败**（无法预编译 metallib 生效）
3. **④ 是"最后兜底"**：**若 App 被移出项目目录**（如放到 `/Applications/`）→ **③ 失败 → ④ 命中**（依赖原目录还在）
4. **若原项目目录也不在** → **⑤ `makeDefaultLibrary()` 失败 → `library = nil` → 插帧静默失效** ⚠️

#### 改动方案（两步）

**步骤 1：预编译 metallib 并打包**（`run.sh`）
```bash
# 在 rm -rf .build 之后、swift build 之前插入
echo "[2.5/4] 预编译 Metal shader"
mkdir -p "$BUNDLE_DIR/Contents/Resources"
xcrun -sdk macosx metal -c Vendor/MetalGoose/Engine/Shaders.metal -o /tmp/Shaders.air 2>&1 | tail -3
xcrun -sdk macosx metallib /tmp/Shaders.air -o "$BUNDLE_DIR/Contents/Resources/default.metallib" 2>&1 | tail -3
```

**步骤 2：让 `setupPipelines` 优先用 metallib**（**必须改 Swift 代码**）
```swift
let library: MTLLibrary? = {
    // ★ 优先用预编译 metallib（快 100ms-1s）
    if let lib = device.makeDefaultLibrary() {
        return lib
    }
    // 回退：运行时编译（保留原逻辑，作为兜底）
    if let url = Bundle.main.url(forResource: "Shaders", withExtension: "metal"), ... { ... }
    let candidates: [URL] = [ ... ]
    ...
    return nil
}()
```

**★ 为什么必须改代码**：当前顺序是"源码编译优先"，metallib 是**最后**的 fallback → 只打包 metallib **不会生效**。

#### ⚠️ 会破什么

| 项 | 影响 |
|---|---|
| **`default.metallib` 生成失败** | 回退运行时编译 ✓（代码保留 fallback） |
| **`Shaders.metal` 改动后** | 需重新跑 `run.sh`（已自动） |
| **`makeDefaultLibrary()` 的语义** | 从 `Bundle.main` 找 `default.metallib` → **需确保在 `Contents/Resources/`** |
| **改动 vendored 代码** | ⚠️ `setupPipelines` 是 vendored 的 → **但只是调整加载顺序，不改语义** |

#### ⚠️ 顺带修复的（P356）

**把 ④ 的硬编码路径去掉**（改为相对路径）：
```swift
let candidates: [URL] = [
    exeDir.appendingPathComponent("Shaders.metal"),
    exeDir.appendingPathComponent("Vendor/MetalGoose/Engine/Shaders.metal"),
    // ★ 删除硬编码：URL(fileURLWithPath: "/Users/dupi/Desktop/自动驾驶系统/...")
]
```
**→ 项目可移动** ✓

#### ⚠️ 验证

1. **启动计时**（两个进程各快 ~100ms-1s）
2. **插帧正常** + `--upscale-selftest` 通过
3. **`ls AuroraDriveUI.app/Contents/Resources/default.metallib`** 应存在
4. **临时改名项目目录** → 插帧仍工作（验证硬编码已去除）

#### 回滚

- **步骤 1**：删 `run.sh` 两行
- **步骤 2**：恢复原来的加载顺序
