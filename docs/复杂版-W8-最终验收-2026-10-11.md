### R1 专项（★ 判据已由 Lead 修正）

**❌ 旧判据（已作废）**：~~单帧 ≈34.4ms vs 45Hz 预算 22.2ms~~
**作废原因**（Lead 说明）：旧分解**把异步推理算进了 tick 同步线程** —— 实测 tick 同步工作 total p50 仅 **0.27~0.42ms**（不是 34.4ms）。

**✅ 新判据（队列利用率）**：
```
45Hz 到达间隔   = 22.2 ms
yolopx 服务时间 = 26.1 ms（实测 p50，35 样本；★ 设计值仅 10.42ms）
→ 利用率 = 26.1 / 22.2 = 118% > 1  → 队列饱和
→ 实际产出率被限在 1/26.1ms = 38.3 Hz，且持续跳帧（isInferencing 防重叠）
```

**⟹ 问题不是"超预算"，而是「产出率被限 + 跳帧」。**

**⚠️ 本骨架阶段的核实状态**：
| 项 | 我的核实结果 |
|---|---|
| tick 同步 p50 = 0.27~0.42ms | ⚠️ **未能独立复现**（需引擎运行 + PERF 日志；骨架阶段引擎未跑） |
| yolopx `lastLatencyMs` 字段存在 | ✅ **已核实**（`EngineMain.swift:1009`、`AuroraDriveApp.swift:2578-2585` 均有引用） |
| yolopx 设计值 10.42ms 出处 | ✅ **已核实**（`YolopxEngine.swift:196/239/620` 注释"ANE 上 p50 10.4ms → 95.9Hz"） |
| `isInferencing` 防重叠存在 | ✅ **已核实**（`YolopxEngine.swift:427/451/467/845`，注释明确"一半提交被 isInferencing 门白扔"） |
