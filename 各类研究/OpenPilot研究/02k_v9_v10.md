## 0. 重要前提澄清（必读）

在进入正文前，必须先对几个被广泛误传/混淆的概念做事实核对，否则会把研究引向错误方向。本节是全文的"防雷区"。

| 任务中出现的术语 | 实际事实核对 | 结论 |
|---|---|---|
| supercombo v9 / v10 | openpilot 的驱动模型文件确实叫 `supercombo.onnx`（位于 `selfdrive/modeld/models/`）。但 comma **不以 v9/v10 命名模型**，而是随 openpilot 软件版本号走（0.9.x / 0.10.x / 0.11.x）。所谓 "v9/v10" 应理解为 "0.9 系列模型 / 0.10 系列模型" | 真实存在，但需对齐到 0.9.x/0.10.x 语义 |
| CommaVLM（视觉-语言模型，用于驾驶） | comma.ai **没有**把 VLM 放进驾驶策略。0.11.1（2026-06）首次"用本地托管的 VLM 生成驾驶员监控（DM）模型的训练标签"（手机使用检测）。即 VLM 只做**离线标注**，不在车端推理、不参与驾驶决策。comma 的驾驶哲学是纯端到端神经网络 + World Model，明确反对把 LLM/VLM 用于驾驶（信奉 Sutton 的 "Bitter Lesson"） | 部分真实，但定位与传闻相反 |
| DriveSeg（分割任务联合训练） | **未发现** comma 官方有 "DriveSeg" 产品/分支。comma 驾驶模型走端到端，**不做显式语义分割用于驾驶决策**。0.11 中 off-policy 的 FastViT 会输出车道线/路沿/前车等，但仅供 UI 可视化与 lead-car fallback，并非占用网格/通用障碍物分割 | 不存在（传闻），但有相关"可视化输出"可借鉴 |
| openpilot 2.0 | **不存在**。当前主线为 0.11.x。0.10 博客明确："we'll work towards openpilot 1.0, where end-to-end longitudinal control graduates from Experimental to Chill mode"。即下一个里程碑是 1.0（端到端纵向控制进入 Chill 模式），尚无 2.0 | 不存在 |
| comma Mini | **不存在**。comma.ai/shop 当前在售设备只有 comma four（\$999）。历史设备：comma one → comma two → comma three → comma 3X → comma four。无 Mini 型号 | 不存在 |
| proprioceptive features（本体感受） | **真实概念**。supercombo 输入含 desire、traffic convention、循环/横向规划状态、车辆状态（速度、转向等）；torqued/lagd 在线学习车辆动力学 | 真实 |

> 因此，本报告在忠实记录 comma.ai 真实演进的同时，对"传闻/不存在"的术语给出对应的真实替代物与可借鉴思路，以便 AuroraDrive 团队能落到可执行的路线。

## 1. supercombo 模型与 0.9 系列演进（"v9"）

### 1.1 supercombo 是什么

openpilot 的核心驱动模型以 ONNX 形式部署在 `selfdrive/modeld/models/supercombo.onnx`，由 `modeld` 守护进程在 GPU（tinygrad）上推理。它是一个**多任务、端到端**的神经网络：输入图像与若干状态向量，直接输出可执行的横向轨迹（plan）、纵向意图、以及可视化用的车道线/路沿/前车等。历史上 backbone 经历了 EfficientNet-B2 → FastViT 的迁移。

supercombo 的经典输入（社区逆向 + 各 release 博客交叉验证）包括：
- 两路相机图像（窄 FOV + 宽 FOV），历史帧上下文；
- **desire**：换道/转向意图（one-hot）；
- **traffic convention**：左行/右行（one-hot）；
- **recurrent / lateral planning state**：上一时刻的规划状态（横向 Q 等），用于时间上下文——这正是"本体感受"的体现；
- 车辆状态（速度、转向角等，经 localizer 估计）；
- 0.9.4 起：**navigation features**（压缩后的地图向量）；
- 0.9.5 起：**navigation instructions**（三值向量）。

输出：plan（多条候选轨迹 + 概率）、lead（前车）、lane lines / road edges、pose、vision features 等。

### 1.2 0.9 系列关键里程碑（2022-11 ~ 2025-06，"v9" 主线，历时近三年）

- **0.9.0（2022-11）"Experimental Mode"**：首次端到端纵向规划（alpha，独立开关）。引入新的**信息瓶颈**：从 KL 散度改为加性高斯白噪声构成的"高斯信道"，每帧约 700 bits 容量，按样本约束信息流，防 cheating。时间汇总器从 GRU 改为**定长历史编码**（更接近 attention），反应更敏捷、更不易 cheating。仿真器引入**深度重投影（depth reprojection）**。同时推出 **torqued**：在线学习每辆车的横向动力学（LatAccelFactor / FrictionCoefficient，全最小二乘），消除手调 PID。
- **0.9.4（2023-07）"Navigate on openpilot"**：三大组件（横向 e2e + 纵向 e2e + 导航）首次齐聚。新增 `mapsd`（绘制 256×256 极简地图：白路 + 灰路线）与 `navmodeld`（地图压缩模型，把地图压成几百维向量喂入驾驶模型）。
- **0.9.5（2023-11）"Farmville / Non-Inflatable / Lemon Pie"**：架构大改——backbone 从 EfficientNet 换为 **FastViT**（混合 Vision Transformer，arXiv:2303.14189），自此所有测试都更好。新增 **navigation instructions**：长度 50 的三值向量（左/直/右，-500~+500m，20m 分辨率）。横向 MPC 与 planner **整体移入模型内部**，模型直接输出可执行横向轨迹。
- **0.9.6（2024-02）**：vision model 用更多数据训练；直接输出 curvature 用于横向控制；AGNOS 9；comma body 通过 WebRTC 流式控制。
- **0.9.7（2024-06）**：输入过去 curvature 以获得更平滑准确的横向控制；简化末层网络结构。
- **0.9.8（2025-03）"Gas Gating"**：Chill 模式下用模型的"人类何时踩油门/刹车"预测来门控加速（接近红灯/出口时智能不加速）。**DM 模型全面迁移到 GPU（tinygrad）**，弃用 SNPE/UINT8 DSP。**图像处理管线移到 ISP**（IFE+ICP/BPS，首个非 Android 的骁龙 ISP 驱动），两路相机 0.1ms 处理，省 0.5W、端到端延迟降 10ms。**GPS-free Localizer**（Kalman 滤波移除 GPS 输入）。**Firehose Mode**：数据摄入扩 100×，为训练 SOTA 级 diffusion/驾驶模型备料。AGNOS 11（Ubuntu 24.04，QDL 取代 Fastboot，不可砖）。
- **0.9.9（2025-06）"Filet-o-Fish"**：为对接新 ML Simulator 做准备——在重投影仿真器里以 **5FPS 训练**（运行时仍 20FPS，输入降采样到 5FPS 对齐）。新增 **lagd**：在线学习每辆车的横向时间延迟（处理延迟+转向器延迟+响应滞后），shadow 模式上线。**外接 USB GPU**（tinygrad USB GPU 驱动，可把桌面 GPU 插到 comma 3X 的 USB-C 口，"算力超 HW4 Tesla"）。AGNOS 12（修显示撕裂回到 60FPS）。新增 Tesla Model 3/Y 支持。

> 小结：0.9 系列三年的主线是"把规则一点点搬进模型"——横向 MPC 进模型（0.9.5）、纵向 e2e 进 experimental（0.9.0）、导航进模型（0.9.4/0.9.5）、车辆动力学在线学习（torqued/lagd）、并把推理/图像管线压榨到极致（ISP、tinygrad、USB GPU），为 0.10 的 World Model 革命铺路。

## 2. supercombo v10（0.10 系列）：World Model 登场

### 2.1 0.10.0（2025-08）"Tomb Raider / Space Lab / Vegan Filet-o-Fish"

博客原话："**After three years on the 0.9 series, we welcome you to the 0.10 series.**" 0.10 由全新的训练架构定义，核心是**用 World Model 做规划监督**，彻底移除横向与纵向的 MPC（训练与推理都不再用），对应 CVPR 2025 论文《Learning to Drive from a World Model》（arXiv:2504.19077）。

三大变化：
1. **World Model Planner（Tomb Raider, #35620）**：旧模型预测"人类会开到的状态"（与当前状态不同的目标），再由 MPC 生成可行轨迹；0.10 起模型直接从当前状态出发预测轨迹，监督来自"知道未来"的 World Model。横向（Chill+Experimental）与纵向（Experimental）的 MPC **全部移除**。
2. **Lead Car 检测改进（Space Lab, #35816）**：停车启停场景下前车检测显著提升，低速被忽略帧从 78% 降到 52%；用 25 个 CARLA 场景验证。
3. **VAE 压缩（Vegan Filet-o-Fish, #35240）**：ML Simulator 是在 latent space 运行的 diffusion 模型，宽/窄图像被编码为 32×16×32 张量（自定义 VAE）。先用重投影仿真器产出 VAE 压缩帧训练，验证压缩损失可忽略。

同时：comma three 转 LTS；commaCarSegments v2（3000 小时 CAN 数据，HuggingFace）；CAN parser 用 Python 重写，省 700 行车型代码。

### 2.2 0.10.1（2025-10）World Model 大幅扩容

- World Model：**移除全局定位输入**、**参数量 ×2**、**训练片段 ×4**；
- VAE 压缩模型：新架构 + 新训练目标；
- Driving Vision Model：训练片段 ×4；
- 新 DM 模型。

### 2.3 0.10.2（2025-11）comma four 支持

仅 comma four 适配变更，comma 3X 无 0.10.2。

### 2.4 0.10.3（2025-12）"Cool People's Model"

- **时序策略架构更灵活**：Vision Features / Desire / Traffic Convention 的编码从"定长非因果 attention"改为"变长因果 attention"，为可变时序长度训练与 World Model 仿真训练铺路。
- **新 on-policy 物理噪声模型**：噪声从"无偏置初值"起步（旧模型从偏离态起步），这是用 World Model 仿真训练的必要改动。
- 新 DM 模型：首次纳入 comma four 片段（comma four 驾驶员摄像头位置与 comma 3/3X 不同）。
- **IPC 内存效率 ×10**：MSGQ 自定义 pub-sub 此前每个服务固定 10MB 环形缓冲，膨胀到 711MB；按服务可配置后降到 90MB。
- 刷新 flash.comma.ai（新引导向导、自定义 USB Vendor ID）。

## 3. supercombo v10 的"完成体"：0.11.0（2026-03）"WMI 模型 🍉"

> 标题：**"The first robotics agent fully trained in a learned simulation"**（首个完全在学习的仿真中训练并交付真实用户的机器人 agent）。

这是 comma 十年项目的里程碑：2016 年论文《Learning a Driving Simulator》提出构想 → 2021 年起上线端到端模型（经典仿真 on-policy 训练）→ 2023 年 commaVQ（首个 transformer 世界模型）→ 2025 年 0.10 首个用 World Model 做规划的模型（仍用重投影仿真器出视频）→ **2026 年 0.11 首个视频与规划都由 World Model 生成的模型**。

### 3.1 两步训练法

1. 在大规模无标注车队数据上训练一个大型神经网络仿真器（**World Model**）；
2. 在 World Model 交互产生的数据上训练一个小型神经网络（**driving policy**）。

意义：经典仿真器只能仿真纵向策略的小偏差，导致高速选速不可靠；神经网络仿真器的保真度可随算力与数据提升，且只要 policy 比 simulator 小（"Big World Hypothesis"）就不会 cheating。0.11 合入 nightly 后，用户在 experimental mode（端到端纵向）的使用占比创历史新高，对停车车辆的响应也更灵敏。

### 3.2 World Model 技术细节（0.11）

**Frame Compressor（帧压缩器，ViT）**：
- 编码器 50M 参数，解码器 100M（深 2×）；
- 两路相机视图（窄+宽，各 3×128×256）编码进 32×16×32 的统一 latent；
- 损失：LPIPS + 对抗损失 + 最小二乘误差；
- 采用 **MAE（Masked Auto Encoder）**：编码器输入随机 mask 补丁，学习 unmask，促进可建模性（比基线好 2.7×，媲美 REPA 且无需额外 loss）。该改进随 0.10.1 上线。

**Diffusion Transformer（扩散 Transformer）**：
- **2B 参数**（n_layer=48, n_head=25, n_embd=1600），适配 3D 数据；
- 每样本：2 秒过去上下文 + 1 秒未来条件 + 0~7 秒仿真窗口，5FPS 采样；
- 动作（6DOF 相对位姿）、扩散噪声级别、帧索引用 **AdaLN-single**（PixArt-α）注入；
- **block-causal attention**：token 只能关注本帧与过去帧，不支持未来帧 → 可用 KV-cache；
- 训练数据：**2.5M 分钟驾驶视频**，Rectified Flow + logit-normal 噪声采样，并对噪声级别输入做增广以抗自回归 rollout 累积误差；
- 采样：逐帧 15 步 Euler，**CFG（Classifier-Free Guidance）强度 2.0**，吞吐 **12.2 frames/sec/gpu**（依赖 KV-cache）。

**Driving Policy（驾驶策略）**：
- **off-policy 模型**：FastViT，预测车道线/路沿/前车等（**仅用于可视化与 lead-car fallback，不参与端到端策略**）；
- **on-policy 模型**：小型 transformer，2 秒上下文 @ 5FPS，学习预测 World Model 在 rollout 中给出的动作；rollout 由 World Model + 最新 policy 检查点生成（"near on-policy"，类 IMPALA/GORILA 的分布式异步）；
- rollout 中注入观测/动作噪声：横向（lag、lag 补偿失配、横向加速度、转向）、纵向（lag、lag 补偿失配、俯仰、油门/刹车）。

### 3.3 comma four 功耗大降

parked 时 panda MCU 留守检测点火，旧功耗 225mW，0.11 降至 **52mW（-77%）**：禁用未用外设（225→158mW）→ VOS1 降到 VOS3（-41mW）→ 进入 stop mode（关 PLL/HSE/SRAM retention，仅留 CAN RX 与 SBU 中断）。对比：典型车 key-off 250–600mW，BMW 诊断阈值 600mW。

### 3.4 0.11.1（2026-06）"LM GT3"——CommaVLM 的真实登场

> 这是全报告对"CommaVLM"的关键订正点。

0.11.1 的 DM（驾驶员监控）模型 **LM GT3**（#37425）改进手机使用检测，是**首个用本地托管的 VLM（Vision-Language Model）生成训练标签的 openpilot DM 模型**：

- 手机使用 ground truth 由 VLM 回答 YES/NO 问题、取 YES token 的输出概率生成（语言模型只预测一个 token）；
- 旧方案是手工标注图像 + 自定义分类器网络；
- 评测集：1k 手工标注 *phone_using* + 80 张 *phone_mounted*（难负样本）；
- VLM 显著降低误报、提升主动手持手机检出，且 **所有** 仪表盘支架手机均判为真负；
- 上线后同组 71 台设备对比：openpilot 开启时手机使用时长显著下降，关闭时也有小幅下降。

> **结论：comma 确实用了 VLM，但仅用于离线 DM 标签生成（车端不跑 VLM、不参与驾驶）。** 驾驶策略仍是 FastViT + 小 transformer + World Model 的纯端到端神经网络。把 VLM 塞进驾驶回路违背 comma 的"苦涩教训"信仰（他们认为驾驶应靠 search+learning 在算力/数据上 scale，而非语言先验）。

## 4. CommaVLM 架构（文字图）

由于 comma 未公开 VLM 的具体模型名/参数，以下是基于 0.11.1 博客与 comma 工程惯例的**合理重建**：

```
                       【CommaVLM：离线 DM 标签生成管线（0.11.1+）】

   ┌───────────────────────── 离线训练侧（数据中心 / 本地托管）─────────────────────────┐
   │                                                                                      │
   │  车队 DM 图像  ──▶  [VLM（视觉-语言模型，本地托管）]                                 │
   │   (驾驶员帧)        │  输入：图像 + 文本 prompt（YES/NO 问题，如                     │
   │                     │       "Is the driver using a handheld phone?"）                │
   │                     │  输出：YES token 的概率（只预测 1 个 token）                   │
   │                     └──▶  软标签 P(phone_use)  ──▶  DM 监督信号                     │
   │                                                              │                       │
   │  [DM 模型 LM GT3（小型 CNN/Transformer）]  ◀── 监督训练 ──┘                          │
   │   输入：驾驶员摄像头帧                                  （端到端，无需手标）           │
   │   输出：phone_use 概率 / distraction 概率                                            │
   └──────────────────────────────────────────────────────────────────────────────────────┘
                                                │ 部署
                                                ▼
   ┌───────────────────────────── 车端推理（comma 3X / four, GPU tinygrad）────────────────────────────┐
   │  驾驶员摄像头 ──▶ [DM 模型 LM GT3] ──▶ 手机使用/分心概率 ──▶ DM 策略（告警/静音）                  │
   │  注：车端【不跑 VLM】，VLM 只在训练侧用。驾驶策略 supercombo 也【不接 VLM】。                       │
   └──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

要点：
- **输入**：图像 + 文本 prompt（YES/NO）；
- **输出**：单 token 概率（软标签）；
- **训练数据**：车队海量 DM 帧（无需手标，VLM 自动标）；
- **推理时间**：VLM 离线、批量、不实时；车端 DM 模型才实时；
- **与 supercombo 的集成**：**无集成**。VLM 与驾驶策略完全解耦，只服务 DM。

## 5. DriveSeg 真相与"分割"在 comma 体系里的真实形态

如第 0 节所述，comma **没有**名为 DriveSeg 的分割任务/产品。但"分割/占用"思想在 comma 体系里有以下真实形态，可供借鉴：

1. **off-policy FastViT 的可视化输出**（0.11）：车道线、路沿、前车概率等——本质是"轻量感知头"，但**只用于 UI 与 lead-car fallback**，不进端到端策略。comma 明确把感知从决策回路里剥离，避免手工感知瓶颈。
2. **World Model 的 latent 表征**：32×16×32 的 latent 已隐式编码可行驶空间/障碍物，但 comma 不显式解出 occupancy grid——他们认为显式表征会限制 scale。
3. **VAE/MAE 压缩器**：把像素压成结构化 latent，可视为"软分割/软占用"的载体。

> 借鉴建议（见第 11 节）：AuroraDrive 若要做通用障碍物/占用网格，**不要**学 comma 把分割完全砍掉（comma 是 L2 辅助驾驶、有人监督，可承受偶发漏检；L4 不可），而应把分割作为**辅助安全头**与端到端策略并联，而非串联进决策。

## 6. proprioceptive features（本体感受特征）

comma 的本体感受特征贯穿 0.9 全程，是其"每辆车自适应"的关键：

- **车辆状态输入 supercombo**：速度、转向角（经 localizer 的 Kalman 滤波估计，0.9.8 起 localizer 移除 GPS 依赖）、横向规划状态（recurrent / lateral Q，上一时刻的 desired curvature）等。0.9.5 起"输入过去 curvature"使横向更平滑；0.9.6 起"直接输出 curvature"。
- **torqued（0.9.0 起）**：在线学习每辆车的 LatAccelFactor 与 FrictionCoefficient（全最小二乘，对 lag 校正后的转向力矩-横向加速度点集），每段行程结束保存，下次复用。覆盖约 60% 车队（Toyota/Lexus/Hyundai/Kia/Genesis）。
- **lagd（0.9.9 起）**：在线学习每辆车的横向时间延迟（处理延迟+转向器延迟+响应滞后），shadow 模式上线，0.10 起启用真实值。
- **与视觉特征的融合**：这些本体感受量作为低维向量与 vision features 拼接/条件化注入 policy，使同一模型适配不同车型、胎压、磨损、转向柱特性的个体差异。

> 这是 comma 区别于"一套标定走天下"厂商的核心：把车辆动力学参数当作**可在线学习的隐变量**，而非手工标定常量。

## 7. navigation features（导航特征）

- **0.9.4 Navigate on openpilot**：`mapsd` 绘制 256×256 极简地图（白路+灰路线）→ `navmodeld`（地图压缩模型）压成几百维向量 → 喂入 supercombo。模型据此预测"人类会怎么开以跟随地图"。
- **0.9.5 navigation instructions**：长度 50 的三值向量（左/直/右，-500~+500m，20m 分辨率），弥补"地图图像不足以判断动作类型与距离"的场景。
- **与地图的集成**：mapsd 是自研地图渲染器（`selfdrive/navd/map_renderer.cc`），不依赖在线地图 SDK，离线渲染保证一致性。
- **路径规划辅助**：导航特征并非"给模型一条参考线让它跟踪"，而是作为**场景上下文**让端到端策略自己学会在哪转弯/出匝道。comma 把"导航"也端到端化，而非规则化路径跟踪。

## 8. openpilot 2.0？——真实版本脉络与"1.0"目标

不存在 openpilot 2.0。真实主线（截至 2026-07）：

```
0.8.x(2021 e2e横向) → 0.9.0(2022 e2e纵向 experimental) → 0.9.4(2023 导航)
→ 0.9.5(2023 FastViT) → … → 0.9.9(2025-06 USB GPU) 
→ 0.10.0(2025-08 World Model Planner) → 0.10.1(2025-10 WM×2) 
→ comma four(2025-11) → 0.10.2(2025-11) → 0.10.3(2025-12 因果attention)
→ 0.11.0(2026-03 首个全学习仿真训练的 agent) → 0.11.1(2026-06 VLM 标 DM) → 0.11.2(nightly)
```

下一个里程碑是 **openpilot 1.0**：端到端纵向控制从 Experimental 毕业到 Chill 模式（即默认可靠的端到端纵向）。2.0 尚未提上日程。

**数据集规模**：
- comma2k19（2019）：加州 280 公路 33 小时、2019 段每段 1 分钟；
- commaCarSegments v2（2025）：3000 小时 CAN 数据，2 万用户车队；
- commaVQ 数据集：10 万分钟压缩驾驶视频；World Model 训练用 **300 万分钟**；0.11 Diffusion Transformer 训练用 **250 万分钟**。

**与 comma 3X 的差异要点**：comma 4 不是换 SoC（仍是 845 系），而是**形态/功耗/制造**的全面重构——把 3X 的算力塞进 1/5 体积，靠 MAX 散热解锁持续 turbo，并大幅降功耗与售价。算力本身与 3X 同级（845 MAX 略高频），真正的"算力跃迁"靠 **0.9.9 引入的外接 USB GPU**（tinygrad 驱动，可插桌面级 GPU，"算力超 HW4 Tesla"）为未来大模型铺路。

**推理性能对比**：845 上 supercombo 经 tinygrad + ISP 优化后端到端延迟持续下降（0.9.8 借 ISP 降 10ms）；DM 模型迁 GPU 后告别 SNPE 量化精度损失。0.11 的 2B Diffusion Transformer **只在训练侧/数据中心跑**，车端仍跑小型 on-policy transformer + FastViT，故 comma 4 无需更强 SoC 即可享受 World Model 训练红利。

## 13. AuroraDrive 迁移建议与模型演进路线

### 13.1 借鉴判断（逐项）

| comma 概念 | AuroraDrive 是否值得借鉴 | 理由与做法 |
|---|---|---|
| World Model 训练驾驶策略（0.10/0.11） | ✅ 强烈推荐 | 核心范式。先建重投影仿真器做 on-policy 训练（防 covariate shift），再逐步迁到学习型 World Model。论文 arXiv:2504.19077 可直接复现。AuroraDrive 若有车队数据，优先建 VAE/DiT 压缩器 + future anchoring + Plan Head |
| VLM 进驾驶回路（传闻） | ❌ 不建议 | comma 自己都不做。驾驶应靠 search+learning 在算力/数据上 scale，语言先验对实时控制收益小、延迟大。VLM 仅适合**离线**做场景理解/标注/罕见 case 检索 |
| CommaVLM（VLM 离线标 DM） | ✅ 推荐借鉴 | 用本地 VLM 自动生成软标签，替代手标，可扩到 AuroraDrive 的 DMS/注意力/手势等。取 YES token 概率做软标签是低成本高效做法 |
| DriveSeg（分割联合训练） | ⚠️ 谨慎借鉴 | comma 把感知从决策剥离（只留可视化头）。AuroraDrive 若做 L4/通用障碍物，**应保留分割/占用头作为并联安全头**（不串联进 e2e 决策），用于兜底刹车与可解释性。可借 comma 的 latent 压缩思想做"软占用" |
| proprioceptive features | ✅ 强烈推荐 | 把车辆动力学参数（扭矩系数、摩擦、横向延迟、转向延迟）当**在线学习隐变量**，per-car 自适应。直接照搬 torqued（全最小二乘）+ lagd（在线延迟估计）思路 |
| navigation features | ✅ 推荐 | 自研极简地图渲染 + 地图压缩模型 + 三值指令向量，离线一致、低带宽。比直接喂高精地图更适配 e2e |
| 信息瓶颈（高斯信道 ~700 bits/帧） | ✅ 推荐 | 防 cheating 的关键。端到端训练必加，按样本约束信息流 |
| 变长因果 attention（0.10.3） | ✅ 推荐 | 替代 GRU/定长非因果，支持可变时序与 World Model rollout 训练 |
| tinygrad + ISP + USB GPU | ✅ 推荐 | 推理极致优化路径。ISP 处理图像省 GPU 给模型；外接 GPU 为大模型预留算力 |
| 把 MPC 全移除 | ⚠️ 分阶段 | comma 是 L2 有人监督。AuroraDrive 若做高阶自动驾驶，建议**先保留 MPC 作为安全兜底**，e2e 策略做主，MPC 做监督/兜底，成熟后再逐步退场 |

### 13.2 AuroraDrive 模型演进路线（建议四阶段）

**阶段 A（0~6 月）：打地基——重投影仿真 + 信息瓶颈 + 本体感受**
- 复现 comma 0.9 路线：FastViT backbone + 高斯信道信息瓶颈 + 定长/因果时间汇总；
- 上线 torqued + lagd 在线车辆动力学学习；
- 建重投影仿真器做 on-policy 训练（深度重投影 + 噪声注入），解决纯模仿学习的 covariate shift；
- 保留分割/占用头作并联安全头（不进决策回路），用于兜底与可解释性。
- 里程碑：横向 e2e 上线（toggle），纵向仍 MPC。

**阶段 B（6~12 月）：World Model Planner——取代 MPC 监督**
- 训练 VAE 压缩器（32×16×32 latent）+ DiT World Model（future anchoring + Plan Head）；
- 用 World Model 做 planning 监督，横向/纵向 MPC 退为兜底；
- 上线导航特征（地图压缩模型 + 指令向量）；
- 自建数据中心（参考 comma \$5M 数据中心博客），避免云锁定。
- 里程碑：experimental mode 端到端纵向（alpha）。

**阶段 C（12~18 月）：全学习仿真训练——WMI 路线**
- 扩 World Model 到 2B 级 DiT + MAE 压缩器，Rectified Flow + CFG，KV-cache 采样；
- policy 用 World Model rollout 做 near on-policy 训练（IMPALA 式分布式）；
- 引入 VLM **离线**标注 DMS/罕见场景（CommaVLM 范式），不进车端；
- tinygrad + ISP 推理优化，预留 USB/外接 GPU 算力。
- 里程碑：纵向 e2e 毕业到默认（Chill），即 AuroraDrive 的 "1.0"。

**阶段 D（18 月+）：scale 与外接算力**
- 随数据/算力 scale World Model（comma 实测 LPIPS 随数据/参数持续提升）；
- 探索外接 GPU 跑更大 on-device 模型；
- 评估是否把占用/分割头逐步退场（视安全裕度）。
- 里程碑：接近 openpilot 0.11 水平——"全学习仿真训练的驾驶 agent"。

### 13.3 三条红线（不要踩）
1. **不要把 VLM/LLM 放进实时驾驶回路**——延迟、不可控、违背 scale 法则；只做离线标注/检索。
2. **不要在 L4 早期就完全移除感知/规则兜底**——comma 是 L2，可承受偶发漏检；AuroraDrive 须保留分割/占用/规则安全头并联。
3. **不要手工标定车辆动力学常量**——一律在线学习（torqued/lagd 范式），否则无法跨车型 scale。

## 14. 结论

comma.ai 在 2025-2026 完成了从"规则+端到端混合"到"**全学习仿真训练的端到端 agent**"的范式跃迁：0.9 三年把规则一点点搬进模型并榨干硬件；0.10 用 World Model 取代 MPC 监督；0.11 让视频与规划都由 World Model 生成，成为首个交付真实用户的全学习仿真训练机器人 agent。其间 VLM 仅以"离线 DM 标注器"身份登场（0.11.1），驾驶策略始终是纯端到端神经网络。comma 4 把 3X 算力塞进 1/5 体积并大幅降功耗降售价，真正的算力跃迁靠外接 USB GPU 预留。

对 AuroraDrive 而言，最值得借鉴的是 **World Model on-policy 训练范式 + 本体感受在线学习 + 信息瓶颈防 cheating + VLM 离线标注**；最需警惕的是**盲目照搬"L2 无兜底"到 L4** 与**把 VLM 塞进实时驾驶**。按 13.2 的四阶段路线推进，可在 18 个月内逼近 openpilot 0.11 的水平。
