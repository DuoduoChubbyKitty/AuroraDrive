## 流式 SSE 错误根因（23:4x 查清，两套代理都根治）
- **之前的 529 记录是浅层误判**。真正的根因是**双层**的：
  1. **launchd 进程不继承用户 shell 的 HTTPS_PROXY**：`launchctl getenv HTTPS_PROXY` 返回空，所以代理进程（经 launchd 拉起）里 httpx `trust_env=True` 读不到代理 → **裸直连上游** `integrate.api.nvidia.com` → 被墙掐断（只收首 chunk 或 529）。
  2. **即使走通代理，chunked 帧格式写错**：代理声明 `Transfer-Encoding: chunked` 却写出**裸 SSE 字节**（未按 `len\r\n data \r\n` 封装），客户端(httpx/TRAE)按 chunked 解析卡住→读到 0 字节→ReadTimeout/SSE 错误。
- **决定性验证**：同样 httpx 代码+同样 venv+同样环境变量，独立脚本打上游流式**完整收全**（21282 字节/63 行/DONE=1），但代理线程里写出裸字节时客户端 bytes=0 → 锁定是代理写出格式问题，非网络。
- **最终修复**（deepseek_proxy.py + nvidia_proxy.py 都已改）：
  - plist 加 `<EnvironmentVariables>` 注入 `HTTPS_PROXY/HTTP_PROXY=http://127.0.0.1:12451` + `NO_PROXY`（com.deepseek.thinkproxy.plist / com.nvidia.thinkproxy.plist 都加了）。改 plist 后必须 `launchctl unload` + `load` 才生效（kickstart 只读内存旧配置）。
  - 代理 `_forward_raw` 流式分支：httpx `Client(http2=True, trust_env=False, proxy=HTTPS_PROXY)` 显式走代理（避免 NO_PROXY=127.0.0.1 让 httpx 把代理服务器自身也 no_proxy→直连卡死）；写出时每帧 `f"{len(chunk):x}\r\n"+chunk+b"\r\n"`，结尾 `b"0\r\n\r\n"` 终止帧。
- **验证通过**：8793 流式 bytes=17248/data=51/DONE=1（43s）；8792 流式 bytes=6035/data=19/DONE=1（3s）。两个代理流式全部正常。
- **关键教训**：① launchd 进程的环境变量必须显式在 plist 里写，不能依赖用户 shell 继承；② HTTP/1.1 + `Transfer-Encoding: chunked` 必须严格按 chunked 帧格式写，否则客户端解析失败（这是「SSE 错误」的真凶，不是代理本身没数据）；③ 排查时独立脚本复现 + 代理内 SSE-DBG 日志对比是定位「网络 vs 写出格式」分歧的最快手段。

## TRAE SSE 报错 4028（decoding response body / downstream）+ 上游断流 + 限流 + 重试 + 容灾合并
### 4028 根因与修复
- 用户 TRAE 报 `Stream error: SSE stream error: Transport error: error decoding response body (origin: downstream) (4028)`。
- 根因：上游 NVIDIA 把 `reasoning_content` 与 `content` **混在同一 delta** 里发（尤其 deepseek 模型），TRAE 的 SSE 解析器对这种混合/带私有字段的 chunk 不稳 → 解码失败报 4028。
- 修复：代理 `_stream_one` 规范化 SSE——逐事件剥掉 `delta.reasoning_content` 字段，只保留干净 `content`，按标准 OpenAI chunk 重发。验证：流式收全无 reasoning_content、TRAE 侧 4028 消失。

### 上游断流 / 限流
- 用户问"突然断了"：日志 `upstream error: Server disconnected` → 代理回 502。是 NVIDIA 免费层主动掐 TCP，**非限流**（日志无 429）。
- NVIDIA 公开限流：免费层 **40 RPM**（每分钟40次），无每小时限制、无 SLA、不稳定易断连。

### 加自动重试（429 + 5xx + 连接异常）
- 非流式：`_forward_raw` 加重试循环（首发+2次），429 读 retry-after 指数退避（封顶10s基数），5xx/连接异常 1s/2s 退避。只在「未向客户端写任何字节」前重试。
- 流式：抽 `_stream_one` 方法，规范化 SSE；只在「写字节前」失败才重试（写过 token 绝不再重发，避免 TRAE 重复内容）；中途断流正常收尾（补 0 帧）而非 502 硬断。

## 12451 桥接器重写 + 代理改直连（00:21-00:35，跨24日）
