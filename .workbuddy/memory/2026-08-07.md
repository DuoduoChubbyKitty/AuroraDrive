## 23:40 【决定性根因】"游戏收不到 M9 的键"= hold() 事件流干涸（非权限/非前台/非模型）

### 现象与用户质问
用户："纯规则它都能输入，为什么就那个破模型输入不了？走的是同一条输入路径。你但凡去查一眼代码。"
—— 用户判断完全正确。我此前一直在猜权限/前台/Chromium，没读代码，方向全错。

### 真正的 bug（读代码找到）
`ControlEngine.hold()` 第 121 行：
```swift
if heldKeys.contains(keyCode) { return }   // 已按住 → 直接返回，不再发任何事件
postKeyEvent(keyCode: keyCode, keyDown: true)
```
CGEvent 注入是**一次性事件**，不像真实键盘硬件会持续上报。于是：
- **M9 档**：直道输出恒定（s=-0.03 t=0.98）→ 首帧发 1 个 keyDown，之后 30Hz 全被 return 掉
  → **整段驾驶只产生过 1 个键盘事件**。日志 `held=1` 恒定不变即铁证。
  → 用户点"开始驾驶"时前台是 App 自己，唯一那个 keyDown 被 App 吃掉；切到游戏后再无任何事件。
  → 完美对应用户描述："一开始好像真注入了一小火，后面没有任何一点点反应"。
- **纯规则档**：YOLO 框每帧闪烁 → dangerLevel 在 safe/caution/danger 间跳 → steer 在 0/±0.5/±1.0、
  brake 在 0/0.1/0.6/1.0 间反复切 → hold/release 不停交替 → **持续产生新事件流** → 游戏收得到。

**核心结论：同一条注入路径，差别在"输出稳不稳定"。输出越稳定，事件流越干涸。**
这也解释了此前独立工具测出 `CGEventSourceKeyState=true` 但游戏不动：
系统键盘状态是全局的，但**事件分发只到事件产生瞬间的前台应用**；游戏从未收到属于它的事件，
它自己的输入状态机就是"没按"。

### 修复（正规设计，非补丁）
模拟真实键盘 auto-repeat —— 真实键盘按住时硬件持续上报，系统持续产生带 autorepeat 标记的 keyDown。
1. `postKeyEvent(keyCode:keyDown:autorepeat:)` 新增参数，autorepeat 时
   `event.setIntegerValueField(.keyboardEventAutorepeat, value: 1)`
2. 新增 `ControlEngine.refreshHeldKeys()`：对 heldKeys 每键重发 keyDown(autorepeat: true)
3. `applyCommand()` 末尾调用 `controlEngine.refreshHeldKeys()`，随 30Hz 主循环刷新
   （与 macOS 默认按键重复率同量级）
4. 新增诊断字段 `postedEventCount`（@ObservationIgnored，避免每帧触发 SwiftUI 重绘），
   日志加 `ev=` → 事件流是否持续一眼可见（ev 每秒应涨约 30，不涨=干涸）
5. 顺手清理死变量 `healthEngine`（未使用警告）
